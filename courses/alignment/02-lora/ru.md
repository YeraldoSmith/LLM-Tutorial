## 2.1 Параметрически эффективное дообучение

Идея **параметрически эффективного дообучения** (Parameter-Efficient Fine-Tuning, PEFT): **заморозить** исходную модель и обучать лишь небольшое число новых параметров. Тогда:

- градиенты и состояние оптимизатора хранятся только для этих немногих параметров, и памяти нужно гораздо меньше;
- для каждой задачи хранится лишь её небольшой набор параметров (от нескольких МБ до нескольких сотен МБ), а не вся модель;
- исходная модель остаётся нетронутой, и между задачами можно переключаться в любой момент.

Из множества методов PEFT самый популярный — **LoRA** (Low-Rank Adaptation, низкоранговая адаптация), предложенная Microsoft в 2021 году.

## 2.2 Как работает LoRA

Дообучить линейный слой — значит заменить его вес W на W + ΔW. Ключевое предположение LoRA: **ΔW не обязана быть произвольной матрицей — достаточно матрицы «низкого ранга»**. Поэтому ΔW записывают как произведение двух узких матриц:

```formula
W' = W + (α / r) · B · A　　　(W: d_out × d_in, заморожена; B: d_out × r; A: r × d_in; r намного меньше d)
```

- **r** — **ранг**, обычно 8–64;
- **α** — масштабный множитель (часто в 1–2 раза больше r), чтобы при смене r не приходилось заново подбирать скорость обучения;
- при прямом проходе `W'x = Wx + (α/r)·B(Ax)`: x сжимается до r измерений и разворачивается обратно — вычислений совсем немного.

Обучаемых параметров вместо d_out × d_in становится r × (d_in + d_out):

```python
def lora_params(d_in, d_out, r):
    return r * (d_in + d_out)

for d_in, d_out, r in [(4096, 4096, 8), (4096, 4096, 16), (4096, 14336, 16), (8192, 8192, 64)]:
    full = d_in * d_out
    lora = lora_params(d_in, d_out, r)
    print(f"матрица {d_out:>5}×{d_in:<5}, r={r:>2}: целиком {full:>11,} параметров, LoRA {lora:>9,} ({lora / full:.2%})")
```

Прямой проход на чистом Python:

```python
def matvec(M, x):
    return [sum(m * v for m, v in zip(row, x)) for row in M]

W = [[1.0, 0.0, 2.0], [0.0, 1.0, -1.0]]      # замороженный исходный вес, 2×3
A = [[0.5, -0.5, 1.0]]                       # r = 1, значит A — 1×3
B = [[2.0], [-1.0]]                          # а B — 2×1
alpha, r = 2, 1
x = [1.0, 2.0, 3.0]

base = matvec(W, x)
delta = [(alpha / r) * v for v in matvec(B, matvec(A, x))]
print("выход исходной модели:", base)
print("поправка LoRA:", delta)
print("выход после дообучения:", [b + d for b, d in zip(base, delta)])

merged = [[W[i][j] + (alpha / r) * B[i][0] * A[0][j] for j in range(3)] for i in range(2)]
print("со слитыми весами:", matvec(merged, x))
```

Обратите внимание на две вещи:

- **B начинается с нуля** (A — с маленьких случайных чисел). Поэтому в начале обучения B·A = 0, и модель **в точности** совпадает с исходной: дообучение плавно стартует от неё.
- **После обучения веса можно слить**: прибавить `(α/r)·B·A` прямо к W и получить обычную модель без всяких дополнительных затрат при инференсе. Или не сливать и во время работы переключать разные LoRA под разные запросы.

## 2.3 Почему хватает низкого ранга?

В матрице 4096 × 4096 больше 16 миллионов чисел, а у LoRA с r = 8 всего 65 тысяч обучаемых параметров — как этого может хватить? Исследования показали, что изменение весов ΔW при дообучении обычно сосредоточено в **немногих направлениях** (его «внутренняя размерность» низкая) — в конце концов, дообучение лишь подстраивает уже имеющиеся способности.

Сингулярное разложение (SVD) показывает, сколько у матрицы «главных направлений». Построим матрицу, у которой «настоящее изменение лишь в 4 направлениях плюс немного шума»:

```python requires=numpy
import numpy as np

rng = np.random.default_rng(0)
d = 256
delta = rng.normal(size=(d, 4)) @ rng.normal(size=(4, d)) + 0.05 * rng.normal(size=(d, d))

U, S, Vt = np.linalg.svd(delta)
print("8 наибольших сингулярных чисел:", np.round(S[:8], 1))
for r in (1, 2, 4, 8, 32):
    approx = (U[:, :r] * S[:r]) @ Vt[:r]                  # оставляем только первые r направлений
    err = np.linalg.norm(delta - approx) / np.linalg.norm(delta)
    print(f"r = {r:>2}: относительная ошибка {err:.3f}")
```

Первые 4 сингулярных числа велики, а дальше резко падают; при r = 4 ошибка уже на уровне шума, и больший r почти не помогает. LoRA делает ставку на то, что настоящее дообучение выглядит так же.

## 2.4 Реализуем LoRA сами

Напишем слой LoRA на PyTorch: он оборачивает замороженный `nn.Linear` и обучает только A и B. Нарочно сделаем так, чтобы целевой вес отличался от исходного изменением **ранга 1**, и посмотрим, выучит ли его LoRA с r = 4:

```python requires=torch timeout=120
import torch
from torch import nn

torch.manual_seed(0)
d = 64

class LoRALinear(nn.Module):
    def __init__(self, base: nn.Linear, r=4, alpha=8):
        super().__init__()
        self.base = base
        for p in self.base.parameters():
            p.requires_grad = False                                   # замораживаем исходный вес
        self.A = nn.Parameter(torch.randn(r, base.in_features) * 0.01)
        self.B = nn.Parameter(torch.zeros(base.out_features, r))      # B начинается с нуля
        self.scale = alpha / r

    def forward(self, x):
        return self.base(x) + self.scale * (x @ self.A.T) @ self.B.T

base = nn.Linear(d, d, bias=False)
u, v = torch.randn(d, 1), torch.randn(1, d)
target_W = base.weight.detach() + 0.5 * (u @ v) / d ** 0.5           # цель = исходный вес + изменение ранга 1
x = torch.randn(2048, d)
y = x @ target_W.T

layer = LoRALinear(base, r=4, alpha=8)
trainable = sum(p.numel() for p in layer.parameters() if p.requires_grad)
total = sum(p.numel() for p in layer.parameters())
print(f"обучаемых параметров {trainable} / всего {total}")

opt = torch.optim.Adam([p for p in layer.parameters() if p.requires_grad], lr=1e-2)
for step in range(301):
    loss = nn.functional.mse_loss(layer(x), y)
    opt.zero_grad()
    loss.backward()
    opt.step()
    if step % 100 == 0:
        print(f"шаг {step:3d}: потери {loss.item():.6f}")

with torch.no_grad():
    merged = layer.base.weight + layer.scale * layer.B @ layer.A      # сливаем в обычный вес
    print(f"наибольшая ошибка слитого веса относительно цели: {(merged - target_W).abs().max().item():.5f}")
```

Обучение всего 512 параметров (в матрице их 4096) снижает потери практически до нуля.

## 2.5 LoRA для большой модели с помощью PEFT

На практике библиотека **PEFT** от Hugging Face добавляет LoRA к выбранным слоям модели в несколько строк (модель скачивается):

```python norun
from transformers import AutoModelForCausalLM
from peft import LoraConfig, get_peft_model

model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen3-0.6B")
config = LoraConfig(
    r=16,                                    # ранг
    lora_alpha=32,                           # α
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                    "gate_proj", "up_proj", "down_proj"],   # линейные слои внимания и MLP
    lora_dropout=0.05,
    task_type="CAUSAL_LM",
)
model = get_peft_model(model, config)
model.print_trainable_parameters()           # обычно обучаемы лишь около процента
```

Обычные настройки из практики:

- **Какие слои**: в исходной статье адаптировали только q и v внимания; позже оказалось, что **все линейные слои** (включая MLP) работают лучше.
- **r и α**: r = 8–64, α = r или 2r. Чем труднее задача и чем дальше она от исходной модели, тем больше r.
- **Скорость обучения**: на порядок выше, чем при полном дообучении, обычно 1e-4 – 2e-4.
- **Результат крошечный**: адаптер LoRA обычно весит несколько десятков МБ, его легко распространять и комбинировать, а системы обслуживания (например, vLLM) умеют загружать сразу много LoRA и переключать их под запрос.

## 2.6 QLoRA: большая модель на одном GPU

LoRA сокращает градиенты и состояние оптимизатора, но замороженная базовая модель всё равно должна поместиться в память: по 2 байта на параметр в BF16 — это 140 ГБ для 70 млрд параметров. **QLoRA** (Dettmers и др., 2023) идёт дальше и **квантует замороженную базовую модель до 4 битов**:

- **NF4** (4-bit NormalFloat): 4-битный формат, созданный для «примерно нормально распределённых весов», точнее обычных 4-битных целых;
- **двойное квантование**: даже масштабные множители, используемые при квантовании, квантуются ещё раз, экономя память;
- **страничные оптимизаторы**: когда памяти не хватает, состояние оптимизатора временно переносится в оперативную память, чтобы пики не приводили к падению;
- A и B у LoRA по-прежнему обучаются в BF16, а 4-битные веса для каждого вычисления временно восстанавливаются в BF16.

```python
def finetune_memory_gb(N, method, lora_fraction=0.01):
    if method == "полное":
        return 16 * N                         # параметры и градиенты BF16 + главные веса FP32 и Adam (урок 2 части 4)
    base_bytes = {"LoRA": 2, "QLoRA": 0.5}[method]   # замороженная базовая модель: BF16 или 4 бита
    return base_bytes * N + 16 * N * lora_fraction   # плюс состояние обучения самих параметров LoRA

for N in (7, 70):                              # в миллиардах параметров; результат в ГБ (без активаций)
    row = [f"{m} {finetune_memory_gb(N, m):6.1f} ГБ" for m in ("полное", "LoRA", "QLoRA")]
    print(f"модель {N:>2}B: " + ", ".join(row))
```

В статье о QLoRA модель на 65 млрд параметров дообучили на **одном GPU с 48 ГБ**, не уступив полному 16-битному дообучению. Так настройка больших моделей стала доступна одиночкам и маленьким командам. Плата — скорость: восстановление 4-битных весов при каждом вычислении делает обучение несколько медленнее, чем у LoRA.

## 2.7 Ограничения и разновидности LoRA

- **Учит меньше, но и забывает меньше**: Biderman и др. (2024) обнаружили, что в задачах, требующих много новых знаний (например, продолжение обучения на больших объёмах кода или математики), LoRA заметно уступает полному дообучению; зато она меньше «забывает» исходные умения. Поэтому LoRA хорошо подходит для настройки формата, стиля и конкретных задач и хуже — для вливания больших объёмов новых знаний.
- **Разновидности**: DoRA (2024) раскладывает веса на «величину» и «направление» и настраивает их отдельно; другие методы улучшают инициализацию и скорости обучения. Принцип всегда тот же, что у LoRA: заморозить большое, обучать маленькое.

## 2.8 Итоги

- Полное дообучение требует много памяти и полной модели на каждую задачу; PEFT замораживает исходную модель и обучает немного новых параметров.
- LoRA: W' = W + (α/r)·B·A, обучаемых параметров вместо d_out·d_in становится r·(d_in + d_out); B начинается с нуля, так что вначале модель не меняется.
- Изменения весов при дообучении обычно низкоранговые, поэтому хватает маленького r; после обучения BA можно слить в W без затрат при инференсе.
- Обычные настройки: все линейные слои, r = 8–64, α = r–2r, скорость обучения около 1e-4; адаптеры маленькие и легко переключаются.
- QLoRA: базовая модель квантуется до 4-битного NF4, плюс двойное квантование и страничные оптимизаторы — и один GPU дообучает модели на десятки миллиардов параметров.
- LoRA подходит для настройки формата, стиля и задач, но уступает полному дообучению при вливании большого объёма новых знаний.

### Задание 5: Почему B начинается с нуля?

В LoRA матрица B инициализируется нулями, а A — маленькими случайными числами. Какова главная цель?

- удвоить скорость обучения
- чтобы в начале обучения B·A = 0 и выход модели в точности совпадал с исходным, плавно стартуя от него
- вдвое уменьшить число параметров LoRA
- потому что B не нужно обучать

<details>
<summary>Ответ и разбор</summary>

B·A = 0 означает, что начальный вес — это сам W, так что дообучение не портит исходную модель с первых шагов. A не может тоже быть нулевой: тогда градиенты и B, и A были бы нулевыми, и обучение не смогло бы начаться.
</details>
