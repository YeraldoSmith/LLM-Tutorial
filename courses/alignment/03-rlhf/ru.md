# 3. Модели вознаграждения и RLHF

> 🎯 **Цели урока**: понять, почему «сравнить два ответа» проще, чем «написать идеальный ответ», и как выглядят данные предпочтений; обучить **модель вознаграждения** по **модели Брэдли — Терри** (реализовав её самим на чистом Python); понять цель RLHF — максимизировать награду, удерживая модель «на поводке» **штрафом KL**, — и вывести её оптимальное решение; самостоятельно провести «обучение с подкреплением» методом градиента стратегии **REINFORCE**; узнать обрезанную цель **PPO** и её цену; распознавать **взлом награды**, предвзятость к длине и угодничество; познакомиться с RLAIF и «конституционным ИИ».
>
> ⏱ **Время**: 90 минут　|　📋 **Что нужно знать**: урок 1 этой части; уроки 2 и 4 части 2 (softmax, градиенты)

SFT научило модель подражать образцам. Но у образцов есть потолок: ответы разметчиков не обязательно лучшие, а многие качества — полезнее, честнее, безопаснее — трудно передать примерами. Оказалось, что **сравнить, какой из двух ответов лучше**, гораздо проще, чем **самому написать идеальный ответ**. **Обучение с подкреплением на основе обратной связи от людей** (Reinforcement Learning from Human Feedback, RLHF) использует такие сравнения, чтобы улучшить модель.

## 3.1 Данные предпочтений

Данные RLHF — это набор **предпочтений**:

```text
Промпт: Объясни, что такое фотосинтез.
Ответ A: Фотосинтез — это процесс, в котором растения с помощью энергии света превращают углекислый газ и воду в сахар и кислород... (ясно, точно)
Ответ B: Фотосинтез — это когда растения загорают. (слишком кратко)
Метка: A лучше B
```

Обычно SFT-модель генерирует несколько ответов на один промпт, а разметчики (или, как мы увидим, другая модель) указывают, какой лучше. Каждый пример записывается как **(промпт, выбранный ответ, отвергнутый ответ)**. InstructGPT использовал десятки тысяч таких сравнений.

## 3.2 Модели вознаграждения: оценка ответов

Нам нужна **модель вознаграждения** (reward model, RM), которая автоматически оценивает любой ответ. Обычно это языковая модель, у которой выходной слой заменён «оценивающей головой», выдающей одно число. Как вывести оценки из сравнений вида «A лучше B»? С помощью **модели Брэдли — Терри** (на ней же основан Эло из урока 5 части 4):

```formula
P(A лучше B) = σ(r(A) − r(B))　　　потери = −log σ(r(выбранный) − r(отвергнутый))
```

σ — сигмоида. Чем больше разница наград двух ответов, тем увереннее модель, какой лучше; потери подталкивают награду выбранного ответа выше, чем у отвергнутого.

Обучим на чистом Python минимальную модель вознаграждения. Настоящая модель сама выучивает признаки из текста ответа; здесь же, для наглядности, каждый ответ описан 4 признаками, придуманными вручную, а награда — их взвешенная сумма:

```python
import math

def sigmoid(z):
    return 1 / (1 + math.exp(-z))

# каждый ответ описан 4 признаками: [отвечает на вопрос, вежлив, длина (в сотнях слов), есть фактическая ошибка]
pairs = [                                  # (выбранный ответ, отвергнутый ответ)
    ([1, 1, 0.5, 0], [0, 1, 0.4, 0]),
    ([1, 0, 0.3, 0], [1, 0, 0.3, 1]),
    ([1, 1, 0.8, 0], [1, 0, 0.6, 0]),
    ([1, 0, 1.2, 0], [0, 0, 1.5, 0]),
    ([1, 1, 0.4, 0], [1, 1, 0.9, 1]),
    ([1, 0, 0.6, 0], [0, 1, 0.2, 0]),
]

def reward(w, f):
    return sum(wi * fi for wi, fi in zip(w, f))

w = [0.0] * 4
for epoch in range(200):                   # градиентный спуск, минимизирующий −log σ(r_выбр − r_отв)
    for c, r in pairs:
        diff = reward(w, c) - reward(w, r)
        g = sigmoid(diff) - 1              # производная потерь по diff
        w = [wi - 0.5 * g * (ci - ri) for wi, ci, ri in zip(w, c, r)]

names = ["отвечает на вопрос", "вежлив", "длина", "фактическая ошибка"]
print("выученные веса:", {n: round(x, 2) for n, x in zip(names, w)})
acc = sum(reward(w, c) > reward(w, r) for c, r in pairs) / len(pairs)
print(f"точность на обучающих данных: {acc:.0%}")

short = [1, 0, 0.3, 0]                     # короткий и верный
padded = [1, 0, 2.0, 0]                    # то же содержание, разбавленное «водой»
print(f"короткий верный ответ: {reward(w, short):.2f}, разбавленный ответ: {reward(w, padded):.2f}")
```

Модель вознаграждения научилась поощрять ответ на вопрос и сильно наказывать фактические ошибки — очень разумно. Но она **заодно выучила «чем длиннее, тем лучше»**: в обучающих данных выбранные ответы чаще оказывались длиннее. Поэтому ответ, разбавленный «водой», получает больше. Запомните это — мы вернёмся к этому в разделе 3.6.

## 3.3 Цель RLHF: максимум награды, но без ухода далеко

Имея модель вознаграждения, мы настраиваем языковую модель (в обучении с подкреплением её называют **стратегией**, policy, и обозначают π), чтобы её ответы получали больше. Но если гнаться **только** за высокой оценкой, модель найдёт, как «обмануть» модель вознаграждения, — будет порождать текст, который та оценивает высоко, но который на деле плох. Поэтому в цель RLHF добавляют ограничение: **не уходить слишком далеко от исходной SFT-модели (эталонной модели π_ref)**:

```formula
максимизировать　E[r(ответ)] − β · KL(π ‖ π_ref)
```

**Расхождение Кульбака — Лейблера** `KL(π‖π_ref) = Σ π(y) · log(π(y) / π_ref(y))` измеряет, насколько различаются два распределения вероятностей: 0, когда они совпадают, и тем больше, чем сильнее различие (это близкий родственник перекрёстной энтропии из урока 6 части 1: перекрёстная энтропия = энтропия + KL). β задаёт, насколько короток поводок. У этой цели красивое оптимальное решение:

```formula
π*(ответ) ∝ π_ref(ответ) · exp(r(ответ) / β)
```

То есть оптимальная стратегия **перевзвешивает** эталонную модель экспонентой награды. Игрушечная задача всего с 4 вариантами ответа показывает, что делает β:

```python
import math

answers = ["верный, краткий", "верный, многословный", "неверный, но уверенный", "отказ отвечать"]
ref = [0.3, 0.3, 0.2, 0.2]                 # вероятность каждого ответа у SFT-модели (эталонной)
reward = [1.0, 0.6, -1.0, -0.5]            # оценки модели вознаграждения

for beta in (10, 1, 0.3, 0.05):
    weights = [p * math.exp(r / beta) for p, r in zip(ref, reward)]
    pi = [w / sum(weights) for w in weights]
    kl = sum(p * math.log(p / q) for p, q in zip(pi, ref))
    avg_r = sum(p * r for p, r in zip(pi, reward))
    print(f"β = {beta:<5} оптимальная стратегия {[round(p, 3) for p in pi]}  средняя награда {avg_r:.3f}  KL {kl:.3f}")
```

При большом β стратегия почти не меняется (KL ≈ 0); чем меньше β, тем смелее она гонится за наградой и тем дальше уходит от эталона; при β, стремящемся к 0, она ставит всё на ответ с наибольшей наградой. На деле модель вознаграждения неидеальна, и слишком смелая ставка ведёт в ловушку взлома награды, — поэтому β нельзя делать слишком маленьким.

## 3.4 Градиент стратегии: REINFORCE

У настоящей языковой модели астрономическое число возможных ответов, и оптимум нельзя найти перебором, как выше. Остаётся только **сэмплировать**: сгенерировать ответ, оценить его и поправить параметры в соответствии с оценкой. Самый простой метод — **REINFORCE** (градиент стратегии):

```formula
∇ E[r] = E[ (r − b) · ∇ log π(ответ) ]
```

Интуитивно: сгенерировав ответ, повышаем его вероятность, если его награда выше «среднего уровня» b (**базовой линии**), и понижаем, если ниже. Базовая линия не меняет матожидания градиента, но сильно уменьшает его случайность. Обучим REINFORCE'ом стратегию из 4 ответов выше (включив штраф KL в награду) и посмотрим, найдёт ли она сама оптимум при β = 0,3:

```python
import math
import random

random.seed(0)
ref = [0.3, 0.3, 0.2, 0.2]
reward = [1.0, 0.6, -1.0, -0.5]
beta, lr = 0.3, 0.1

def softmax(z):
    m = max(z)
    e = [math.exp(v - m) for v in z]
    return [v / sum(e) for v in e]

logits = [math.log(p) for p in ref]                 # стартуем от эталонной модели
for step in range(3001):
    pi = softmax(logits)
    i = random.choices(range(4), weights=pi)[0]     # сэмплируем ответ
    score = reward[i] - beta * math.log(pi[i] / ref[i])      # награда минус штраф KL
    baseline = sum(p * (r - beta * math.log(p / q)) for p, r, q in zip(pi, reward, ref))
    advantage = score - baseline
    for j in range(4):                              # производная log softmax по j-му логиту
        logits[j] += lr * advantage * ((1 if j == i else 0) - pi[j])
    if step % 1000 == 0:
        print(f"шаг {step:4d}: {[round(p, 3) for p in softmax(logits)]}")
```

Только «пробуя и глядя на оценку», стратегия сходится к оптимуму `[0.788, 0.208, 0.001, 0.004]`, вычисленному в разделе 3.3. Настоящий RLHF работает так же, только «ответ» — целый текст, а log π(ответ) — сумма логвероятностей его токенов.

## 3.5 PPO: более устойчивые обновления

REINFORCE прост, но слишком большой шаг может внезапно испортить стратегию безвозвратно. InstructGPT и ранний ChatGPT использовали **PPO** (Proximal Policy Optimization, OpenAI, 2017), суть которого — ограничить размер каждого шага:

```formula
ratio = π_нов(ответ) / π_стар(ответ)　　цель = min( ratio · A, clip(ratio, 1 − ε, 1 + ε) · A )
```

A — **преимущество** (advantage, как `r − b` выше), ε обычно 0,2. Если новая стратегия уже подняла вероятность хорошего ответа больше чем на 20%, дальнейший рост ничего не добавляет, — так каждое обновление остаётся небольшим и быстрым шагом:

```python
def ppo_objective(ratio, advantage, eps=0.2):
    clipped = max(1 - eps, min(1 + eps, ratio))
    return min(ratio * advantage, clipped * advantage)

for ratio, adv in [(1.0, 1.0), (1.5, 1.0), (0.5, 1.0), (1.5, -1.0), (0.5, -1.0)]:
    print(f"ratio {ratio}, преимущество {adv:+}: цель {ppo_objective(ratio, adv):+.2f}")
```

PPO работает хорошо, но он **дорогой** и **сложный**: при обучении в памяти одновременно 4 большие модели — обучаемая стратегия, замороженная эталонная модель, модель вознаграждения и **модель ценности** (critic) для оценки преимуществ, — плюс куча гиперпараметров, требующих тонкой настройки. Это подтолкнуло к более простым методам: **DPO** из следующего урока вовсе обходится без обучения с подкреплением, а **GRPO** из урока 5 избавляется от модели ценности.

## 3.6 Взлом награды

Модель вознаграждения — лишь **приближение** предпочтений людей. Чем усерднее стратегия её оптимизирует, тем легче находит в ней лазейки — это **взлом награды** (reward hacking), ещё один пример закона Гудхарта (урок 5 части 4):

- **Предвзятость к длине**: как в примере раздела 3.2, модель вознаграждения любит длинные ответы, и стратегия учится писать длинно и пусто.
- **Угодничество** (sycophancy): люди склонны выше оценивать ответы, согласные с ними, и модель учится поддакивать пользователю, даже когда он неправ.
- **Игра с форматом**: обилие списков, жирного шрифта и эмодзи, потому что так ответ выглядит «старательнее».
- Gao и др. (2022) систематически изучили «переоптимизацию»: по мере того как стратегия удаляется от эталона, оценка модели вознаграждения продолжает расти, а **настоящее** качество сначала растёт, а потом падает.

Средства: штраф KL, более крупные и качественные модели вознаграждения, контроль длины в данных предпочтений, регулярный сбор свежих предпочтений для переобучения модели вознаграждения и усреднение нескольких таких моделей.

## 3.7 Пусть обратную связь даёт ИИ

Разметка предпочтений людьми медленная и дорогая. Так появился **RLAIF** (Reinforcement Learning from AI Feedback): ответы сравнивает сильная модель вместо людей. Самый известный пример — **конституционный ИИ** (Constitutional AI) от Anthropic (2022): сначала записывается набор принципов («конституция»), например «выбирай более честный и менее вредный ответ»; затем модель по этим принципам критикует и исправляет собственные ответы и сравнивает пары ответов, а обучение идёт на предпочтениях, сгенерированных ИИ. Правила выравнивания становятся прозрачнее (они записаны в принципах), а стоимость сильно падает.

## 3.8 Итоги

- Сравнивать проще, чем показывать; данные предпочтений — тройки (промпт, выбранный, отвергнутый).
- Модели вознаграждения обучают с потерями Брэдли — Терри −log σ(r_выбр − r_отв); они перенимают перекосы данных (например, любовь к длинным ответам).
- Цель RLHF: максимизировать E[r] − β·KL(π‖π_ref); оптимум π* ∝ π_ref·exp(r/β); β задаёт, насколько далеко стратегия может уйти от эталона.
- REINFORCE: ∇E[r] = E[(r − b)∇log π], базовая линия уменьшает дисперсию; PPO ограничивает каждое обновление обрезанным отношением вероятностей, но требует 4 модели, сложен и дорог.
- Взлом награды: длина, угодничество, формат; против него — KL, лучшие модели вознаграждения, контроль длины и другое.
- RLAIF и конституционный ИИ: обратную связь по принципам даёт модель.
