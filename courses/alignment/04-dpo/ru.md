>
> ⏱ **Время**: 70 минут　|　📋 **Что нужно знать**: уроки 1 и 3 этой части

RLHF из прошлого урока сначала обучает модель вознаграждения, а затем проводит обучение с подкреплением с PPO: сразу 4 модели, постоянная генерация во время обучения и множество гиперпараметров — настраивать очень трудно. В 2023 году Rafailov и др. из Стэнфорда предложили **DPO** (Direct Preference Optimization, прямая оптимизация предпочтений): **обучать языковую модель прямо на данных предпочтений**, без отдельной модели вознаграждения и без обучения с подкреплением. Простой и устойчивый, он быстро стал самым распространённым методом оптимизации предпочтений для открытых моделей.

## 4.1 Исходим из оптимума RLHF

В прошлом уроке мы получили оптимальную стратегию при ограничении KL:

```formula
π*(y) = π_ref(y) · exp(r(y) / β) / Z
```

Z — нормирующая константа, благодаря которой вероятности в сумме дают 1 (для данного промпта это фиксированное число, но для него нужно суммировать по всем возможным ответам, так что вычислить его невозможно). **Перевернём** это равенство и выразим награду через стратегию:

```formula
r(y) = β · log( π*(y) / π_ref(y) ) + β · log Z
```

Это значит: **зная оптимальную стратегию и эталонную модель, мы знаем и награду** (с точностью до константы). Подставим её в формулу Брэдли — Терри для модели вознаграждения. Для одного промпта, с выбранным ответом y_w и отвергнутым y_l:

```formula
P(y_w лучше y_l) = σ( r(y_w) − r(y_l) ) = σ( β · log(π(y_w)/π_ref(y_w)) − β · log(π(y_l)/π_ref(y_l)) )
```

Невычислимое β·log Z **в точности сокращается**! Значит, правдоподобие предпочтений можно записать прямо через вероятности языковой модели π, а его максимизация (минимизация минус логарифма) даёт **функцию потерь DPO**:

```formula
L_DPO = −log σ( β · [ log(π(y_w)/π_ref(y_w)) − log(π(y_l)/π_ref(y_l)) ] )
```

Подзаголовок статьи о DPO — «Ваша языковая модель — тайком модель вознаграждения»: `β · log(π(y)/π_ref(y))` — это **неявная награда** модели. Обучая DPO, мы подгоняем эту неявную модель вознаграждения под предпочтения — а сама стратегия при этом и есть та оптимальная стратегия, к которой стремился RLHF.

## 4.2 Вычисляем потери DPO

DPO нужны всего четыре числа: логвероятности, которые стратегия и эталонная модель дают выбранному и отвергнутому ответам (логвероятность ответа — сумма по его токенам):

```python
import math

def sigmoid(z):
    return 1 / (1 + math.exp(-z))

def dpo(pi_w, pi_l, ref_w, ref_l, beta=0.1):
    reward_w = beta * (pi_w - ref_w)           # неявная награда выбранного ответа
    reward_l = beta * (pi_l - ref_l)           # неявная награда отвергнутого ответа
    margin = reward_w - reward_l
    return -math.log(sigmoid(margin)), reward_w, reward_l

# логвероятности двух ответов у эталонной модели (не меняются при обучении)
ref_w, ref_l = -42.0, -40.0
for label, pi_w, pi_l in [("начало обучения (π = π_ref)", -42.0, -40.0),
                          ("выбранный ответ вероятнее", -38.0, -40.0),
                          ("отвергнутый ответ менее вероятен", -42.0, -50.0),
                          ("оба падают, отвергнутый сильнее", -45.0, -60.0)]:
    loss, rw, rl = dpo(pi_w, pi_l, ref_w, ref_l)
    print(f"потери {loss:.4f}, неявные награды: выбранный {rw:+.2f}, отвергнутый {rl:+.2f}  ← {label}")
```

Несколько наблюдений:

- В начале π = π_ref, обе неявные награды равны 0, а потери — log 2 ≈ 0,693.
- Потерям важна только **разность**: повысить вероятность выбранного ответа или понизить вероятность отвергнутого — оба пути уменьшают потери.
- Последняя строка — частый случай: **оба** ответа стали менее вероятны, отвергнутый — сильнее. Потери уменьшились, но и хороший выбранный ответ стал менее вероятен — известная проблема DPO (раздел 4.5).
- Если взять градиент по одной паре, окажется, что её вес — `σ(−margin)`: пары, которые модель уже хорошо различает (большой margin), почти ничего не вносят, и обучение сосредотачивается на парах, которые она **ещё не выучила**.

## 4.3 Проверка на игрушечной задаче

Вернёмся к задаче с 4 ответами из прошлого урока. На этот раз мы **не сообщаем** модели награды; даём лишь 4000 предпочтений, случайно сгенерированных по «истинным наградам» с вероятностями Брэдли — Терри (имитация разметки людьми). Куда придёт стратегия при градиентном спуске по потерям DPO?

```python
import math
import random

random.seed(1)

def sigmoid(z):
    return 1 / (1 + math.exp(-z))

def softmax(z):
    m = max(z)
    e = [math.exp(v - m) for v in z]
    return [v / sum(e) for v in e]

ref = [0.3, 0.3, 0.2, 0.2]
true_reward = [1.0, 0.6, -1.0, -0.5]           # модель её не видит — только сгенерированные по ней предпочтения
beta = 0.3

data = []                                      # (выбранный, отвергнутый)
for _ in range(4000):
    i, j = random.sample(range(4), 2)
    if random.random() < sigmoid(true_reward[i] - true_reward[j]):
        data.append((i, j))
    else:
        data.append((j, i))

theta = [math.log(p) for p in ref]             # логиты стратегии, стартуем от эталонной модели
for step in range(601):
    pi = softmax(theta)
    grad, loss = [0.0] * 4, 0.0
    for w, l in data:
        z = beta * (math.log(pi[w] / ref[w]) - math.log(pi[l] / ref[l]))
        loss += -math.log(sigmoid(z))
        g = (1 - sigmoid(z)) * beta            # вес градиента этой пары σ(−z)·β
        grad[w] += g
        grad[l] -= g
    theta = [t + 5.0 * g / len(data) for t, g in zip(theta, grad)]
    if step % 200 == 0:
        print(f"шаг {step:3d}: потери {loss / len(data):.4f}, стратегия {[round(p, 3) for p in softmax(theta)]}")

best = [p * math.exp(r / beta) for p, r in zip(ref, true_reward)]
print("теоретический оптимум RLHF:", [round(b / sum(best), 3) for b in best])
```

Ни модели вознаграждения, ни сэмплирования — только данные предпочтений, и DPO приходит к окрестности теоретического оптимума RLHF (предпочтения — конечная случайная выборка, поэтому результат слегка отличается от теории). Именно это и обещал вывод в разделе 4.1.

(В этой постановке градиент по логитам в точности равен `g·(e_w − e_l)`: члены log softmax, зависящие от π, сокращаются между выбранным и отвергнутым ответами.)

## 4.4 DPO на практике

- **Данные**: как и для моделей вознаграждения, тройки (промпт, выбранный, отвергнутый). Распространённые открытые наборы — например, UltraFeedback (ответы нескольких моделей, оценённые GPT-4).
- **Эталонная модель**: обычно SFT-модель. Её логвероятности при обучении не меняются, поэтому их можно вычислить заранее и сохранить — тогда во время обучения в памяти GPU только одна модель.
- **β**: часто около 0,1. Чем больше β, тем меньше модель решается отходить от эталона.
- **Скорость обучения**: очень маленькая, при полном обучении около 5e-7; 1–3 эпохи.
- С библиотекой TRL (нужен GPU; актуальный API смотрите в официальной документации):

```python norun
from datasets import load_dataset
from trl import DPOConfig, DPOTrainer

dataset = load_dataset("trl-lib/ultrafeedback_binarized", split="train")   # prompt / chosen / rejected
trainer = DPOTrainer(
    model="Qwen/Qwen3-0.6B",                          # обычно сначала проходит SFT
    train_dataset=dataset,
    args=DPOConfig(output_dir="qwen3-dpo", beta=0.1),
)
trainer.train()
```

## 4.5 Проблемы DPO

- **Вероятность выбранного ответа тоже может падать**: как в последней строке раздела 4.2, DPO требует лишь роста «выбранный − отвергнутый», и оба могут падать вместе, отчего ответы модели становятся странными. Частое средство — добавить к потерям немного SFT-потерь на выбранных ответах.
- **Офлайн-данные**: данные предпочтений обычно собраны заранее и порождены другими (или ранними) моделями. Когда обучение меняет ответы модели, старые данные подходят хуже. **Онлайн / итеративный DPO** — генерировать текущей моделью новые ответы, заново размечать предпочтения и снова обучать — работает лучше и ближе к RLHF.
- **Длина**: если в данных выбранные ответы обычно длиннее, DPO тоже выучит «чем длиннее, тем лучше» (как и модели вознаграждения, раздел 3.6).
- **Переобучение**: данные предпочтений шумные (люди не всегда согласны), и DPO может раздуть разрыв для некоторых пар до бесконечности.

Что лучше, DPO или PPO, — спор продолжается. Общее мнение: DPO прост, устойчив и дёшев и подходит для большинства ситуаций; тщательно настроенное онлайн-RL имеет более высокий потолок. Передовые модели обычно используют и то, и другое, а в задачах с надёжной автоматической проверкой, вроде математики и кода, всё чаще применяют методы обучения с подкреплением из следующего урока.

## 4.6 Семейство DPO

После DPO появилось множество вариантов, и каждый меняет функцию потерь:

| Метод | Год | Главная идея |
|-------|-----|--------------|
| **IPO** | 2023 | заменить −log σ квадратичными потерями, чтобы разрыв неявных наград останавливался около целевого значения, — против переобучения |
| **KTO** | 2024 | пары не нужны: каждый ответ просто помечен «хороший» или «плохой»; вдохновлён теорией перспектив из поведенческой экономики |
| **ORPO** | 2024 | без эталонной модели: к SFT-потерям добавляется штраф «отношения шансов», и SFT с оптимизацией предпочтений делаются за один шаг |
| **SimPO** | 2024 | без эталонной модели: неявная награда — **средняя** логвероятность на токен (устраняет предвзятость к длине), а разрыв должен быть не меньше γ |

Например, потери SimPO:

```formula
L_SimPO = −log σ( β · [ log π(y_w) / |y_w| − log π(y_l) / |y_l| ] − γ )
```

```python
import math

def sigmoid(z):
    return 1 / (1 + math.exp(-z))

def simpo(logp_w, len_w, logp_l, len_l, beta=2.0, gamma=1.0):
    margin = beta * (logp_w / len_w - logp_l / len_l) - gamma
    return -math.log(sigmoid(margin))

# выбранный ответ длинный (поэтому его общая логвероятность ниже), отвергнутый — короткий
print("сравнение сумм (как в DPO, без деления на длину): выбранный", -120.0, "отвергнутый", -30.0)
print("сравнение средних на токен: выбранный", -120.0 / 100, "отвергнутый", -30.0 / 20)
print(f"потери SimPO: {simpo(-120.0, 100, -30.0, 20):.4f}")
```

У длинного ответа общая логвероятность естественным образом ниже; после деления на длину сравнивается «насколько естественен в среднем каждый токен», и длина больше не помогает и не мешает.

## 4.7 Итоги

- Если из оптимума RLHF π* ∝ π_ref·exp(r/β) выразить награду, получится r = β·log(π/π_ref) + константа; при подстановке в Брэдли — Терри константа сокращается, и возникают потери DPO.
- L_DPO = −log σ(β·[log(π(y_w)/π_ref(y_w)) − log(π(y_l)/π_ref(y_l))]); β·log(π/π_ref) — неявная награда.
- DPO не нужны ни модель вознаграждения, ни сэмплирование RL — только пары предпочтений и эталонная модель (её логвероятности можно посчитать заранее); на игрушечной задаче он идёт к оптимуму RLHF.
- На практике: β ≈ 0,1 и очень маленькая скорость обучения; проблемы: вероятность выбранного ответа может падать, офлайн-данные плохо подходят, предвзятость к длине, переобучение; онлайн / итеративный DPO работает лучше.
- Варианты: IPO (квадратичные потери), KTO (отдельные метки «хорошо/плохо»), ORPO и SimPO (без эталонной модели; SimPO нормирует по длине).

### Задание 5: Что не нужно DPO?

Что из этого не нужно DPO по сравнению с RLHF на основе PPO?

- данные предпочтений (пары выбранных / отвергнутых ответов)
- эталонная модель (или заранее посчитанные её логвероятности)
- отдельно обученная модель вознаграждения и сэмплирование обучения с подкреплением во время обучения
- обучаемая языковая модель

<details>
<summary>Ответ и разбор</summary>

DPO «прячет» модель вознаграждения в саму стратегию (неявная награда) и обучается прямо на парах предпочтений как обучение с учителем, без отдельной модели вознаграждения и без генерации во время обучения. Данные предпочтений и эталонная модель по-прежнему нужны.
</details>

<!-- exercise: dpo-beta -->
### Задание 6: Роль β

Что означает больший β в DPO?

- модель смелее отходит от эталона
- неявные награды в большем масштабе, поэтому уже небольшое изменение вероятностей создаёт разрыв, и модели не нужно далеко уходить от эталона, — как более сильное ограничение KL
- большую скорость обучения
- больше обучающих данных

<details>
<summary>Ответ и разбор</summary>

β происходит из коэффициента штрафа KL в цели RLHF: чем больше β, тем сильнее ограничение и тем ближе оптимальная стратегия к эталону. В потерях DPO β масштабирует отношения логвероятностей, и очень малых изменений достаточно, чтобы потери снизились.
</details>
