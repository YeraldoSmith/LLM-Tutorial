訓練完一個模型，怎麼知道它好不好？比上一個版本強多少？比別家的模型呢？這比想象的難得多：語言模型能做的事情太多了，任何一個分數都只反映了一個側面。這一課介紹常用的評測方法，以及解讀分數時要注意的陷阱。

## 5.1 語言建模本身：困惑度和每位元組位元數

最直接的指標是模型在沒見過的文字上的**損失**（平均每個 token 的負對數機率），或者它的指數——**困惑度**（perplexity，第三部分第 1 課）：

```python
import math

probs = [0.25, 0.6, 0.05, 0.9, 0.4]               # 模型給真實的下一個 token 的機率
nll = [-math.log(p) for p in probs]               # 每個 token 的負對數機率（單位：nat）
loss = sum(nll) / len(nll)
print(f"平均損失 {loss:.3f} nat/token，困惑度 {math.exp(loss):.2f}")

text = "今天天氣很好"                                # 假設這 5 個 token 拼起來是這段文字
n_bytes = len(text.encode("utf-8"))
bpb = sum(nll) / math.log(2) / n_bytes            # 總資訊量換算成位元，再除以位元組數
print(f"{n_bytes} 個位元組，每位元組 {bpb:.3f} 位元")
```

困惑度有一個問題：它依賴於**分詞器**。分詞器切得粗（一個 token 包含的文字多），每個 token 就更難預測，困惑度更高，但這並不說明模型更差。所以比較不同分詞器的模型時，常用**每位元組位元數**（bits per byte, BPB）：把總的資訊量換算成位元，除以原文的位元組數，就和分詞方式無關了。

損失是訓練時最重要的指標——它平滑、穩定，和規模定律直接相關（第 2 課）。但使用者關心的是「能不能答對題、寫對程式碼、聽懂指令」，這需要專門的評測集。

## 5.2 選擇題：怎麼打分也有講究

**MMLU**（2020）是最有名的選擇題評測：57 個學科（數學、歷史、法律、醫學……）的約 1.4 萬道四選一題目。它的升級版 **MMLU-Pro**（2024）有十個選項、更多推理題；**GPQA**（2023）是研究生水平的物理、化學、生物題，題目設計得連上網搜尋也很難找到答案（「GPQA Diamond」是其中最難的 198 道）。

讓模型做選擇題，有兩種打分方式：

1. **生成答案**：在提示裡列出選項，讓模型輸出「A」「B」……，再檢查輸出。適合對話模型。
2. **比較機率**：把每個選項的文字接在題目後面，計算模型給這段文字的**對數機率**，選機率最高的。不需要模型會按格式回答，適合還沒經過指令微調的基礎模型。

第二種方式有個陷阱：選項越長，包含的 token 越多，對數機率加起來就越低。所以常常要按長度**取平均**——但這樣做有時又會反過來偏愛長選項：

```python
# 每個選項各個 token 的對數機率（選項長短不一）
options = {
    "A": [-1.2, -0.8, -0.9],
    "B": [-2.5],
    "C": [-1.0, -1.1],
    "D": [-3.0, -0.2, -0.3, -0.4],
}
by_sum = max(options, key=lambda k: sum(options[k]))
by_mean = max(options, key=lambda k: sum(options[k]) / len(options[k]))
for k, lp in options.items():
    print(f"{k}：{len(lp)} 個 token，總和 {sum(lp):5.2f}，平均 {sum(lp) / len(lp):6.3f}")
print("按總和選：", by_sum, "；按平均選：", by_mean)
```

同一個模型、同一道題，換一種打分方式，選出的答案就不一樣了。所以**比較分數時，評測的細節必須完全相同**：同樣的提示格式、同樣的範例數量（0-shot 還是 5-shot）、同樣的打分方式。不同論文裡同一個模型的「MMLU 分數」常常相差好幾分，原因就在這裡。

## 5.3 生成題：數學和程式碼

### 數學：精確匹配

**GSM8K**（小學數學應用題）、**MATH**（競賽數學）、**AIME**（美國數學邀請賽，每年 30 道題，2024 年起被廣泛用來評測推理模型）這類評測，讓模型寫出解題過程，最後提取答案和標準答案比較。「提取」看似簡單，其實很容易出錯：模型可能寫 `1,000`、`1000.0`、`$1000`、`答案是 1000 元`……通常要先**規範化**再比較，或者要求模型把最終答案寫在固定的格式裡（比如 `\boxed{1000}`）。

### 程式碼：pass@k

**HumanEval**（OpenAI，2021，164 道 Python 函式題）、MBPP 這類評測，把模型寫的程式碼放進沙箱執行，用單元測試判斷對錯。常用的指標是 **pass@k**：讓模型對每道題生成 k 個答案，**只要有一個**透過測試就算解出。

怎樣估計 pass@k？最直接的方法是真的生成 k 個答案看有沒有對的，但這樣隨機性很大。更好的做法是對每道題生成 n 個（n ≥ k）答案，數出其中 c 個是對的，再用組合數算出「從 n 個裡隨機選 k 個，至少有一個對」的機率：

```formula
pass@k = 1 − C(n − c, k) / C(n, k)
```

```python
from math import comb

def pass_at_k(n, c, k):
    if n - c < k:                      # 錯的不夠 k 個：隨便選 k 個都至少有一個對的
        return 1.0
    return 1 - comb(n - c, k) / comb(n, k)

def naive(n, c, k):                    # 一個常見的錯誤做法：把 c/n 當作每次的成功率
    return 1 - (1 - c / n) ** k

for n, c, k in [(10, 3, 1), (10, 3, 5), (200, 10, 10), (200, 10, 100)]:
    print(f"n={n:3d} c={c:2d} k={k:3d}：無偏估計 {pass_at_k(n, c, k):.4f}，錯誤做法 {naive(n, c, k):.4f}")
```

`1 − (1 − c/n)^k` 看起來合理，但它假設可以「有放回地」抽取，會系統性地**低估** pass@k。HumanEval 的論文給出了上面的無偏估計。

現在的程式碼評測越來越接近真實工作：**LiveCodeBench** 不斷收集新發布的競賽題，避免題目被訓練資料「汙染」；**SWE-bench Verified**（2024）是 500 個來自真實 GitHub 專案的問題，模型要閱讀整個程式碼庫、修改程式碼，讓專案原有的測試透過——這已經是在評測**智慧體**（第七部分）的能力了。

## 5.4 人類偏好：競技場和 Elo

很多能力——回答是否有幫助、寫作好不好、語氣是否合適——沒有標準答案。**Chatbot Arena**（LMArena，2023 年起）的做法是：使用者輸入一個問題，兩個匿名模型各給一個回答，使用者投票選擇更好的那個。用幾百萬次投票，就能給所有模型排出名次。

排名用的是國際象棋裡的 **Elo 評分**（以及更嚴格的 Bradley–Terry 模型）：兩個模型的分差決定了「預期勝率」，實際結果比預期好就加分，比預期差就減分：

```formula
預期得分 E_A = 1 / (1 + 10^((R_B − R_A) / 400))　　新分數 R_A' = R_A + K · (實際得分 − E_A)
```

```python
def elo(ra, rb, score_a, k=32):          # score_a：A 贏 1，平局 0.5，輸 0
    expected_a = 1 / (1 + 10 ** ((rb - ra) / 400))
    change = k * (score_a - expected_a)
    return ra + change, rb - change

print("兩個 1500 分的模型，A 贏：", elo(1500, 1500, 1))
print("1600 分的 A 輸給 1400 分的 B：", [round(v, 1) for v in elo(1600, 1400, 0)])
print("1600 分的 A 贏了 1400 分的 B：", [round(v, 1) for v in elo(1600, 1400, 1)])
print("400 分的差距意味著預期勝率：", round(1 / (1 + 10 ** (-400 / 400)), 3))
```

爆冷（強者輸給弱者）帶來大幅的分數變化，意料之中的結果只帶來小幅變化。

### 大模型當評委

人工投票又慢又貴，於是常常讓一個強大的模型來當評委（**LLM-as-a-judge**），比如 MT-Bench、AlpacaEval。它很方便，但有幾種已知的偏差：

- **位置偏差**：傾向於選擇先出現（或後出現）的回答。對策：交換順序再評一次，兩次結果一致才算數。
- **長度偏差**：傾向於更長、更詳細的回答，哪怕內容並不更好。AlpacaEval 2.0 因此推出了「長度控制」的勝率。
- **自我偏好**：傾向於自己（或同一家族的模型）寫的回答。
- 而且評委本身也會犯錯，在專業問題上未必比被評測的模型更懂。

## 5.5 2026 年常見的評測

| 方向 | 代表性評測 |
|------|------------|
| 知識與推理 | MMLU-Pro、GPQA Diamond、**HLE**（Humanity's Last Exam，2025，約 2500 道各領域專家出的難題） |
| 數學 | MATH-500、AIME 2024/2025 |
| 程式碼 | LiveCodeBench、SWE-bench Verified |
| 指令遵循 | **IFEval**（「用不超過 100 個詞」「不要用逗號」等可以自動檢查的指令） |
| 長上下文 | 大海撈針（needle in a haystack）、RULER |
| 智慧體 | SWE-bench、τ-bench（客服場景中呼叫工具）、瀏覽網頁、操作電腦的評測 |
| 抽象推理 | ARC-AGI（用圖形謎題考察「學習新規則」的能力） |
| 人類偏好 | LMArena |
| 安全 | 拒答有害請求、越獄攻擊、偏見等專門的評測 |

評測集的「壽命」越來越短：MMLU 釋出時最好的模型只有 40 多分，幾年後前沿模型都在 90 分上下，**飽和**了，區分不出高低；GSM8K 也是如此。於是不斷有更難的評測出現，HLE 的名字（「人類的最後一場考試」）就反映了這種追趕。

## 5.6 解讀分數的陷阱

- **資料汙染**：評測題如果出現在訓練資料裡，分數就虛高了（第 1 課講過去汙染）。新出的評測（比如 LiveCodeBench、每年的 AIME）可以一定程度上避免這個問題。
- **提示敏感**：換一種提示的措辭、換幾個範例、換一下選項順序，分數可能變化好幾分。
- **古德哈特定律**：「當一個指標變成目標，它就不再是一個好的指標。」專門為了刷某個排行榜而最佳化，可能讓模型在這個評測上很好，在別的地方卻沒有提升。
- **統計噪聲**：評測集是有限的，分數本身有隨機誤差。正確率 p、題目數 n 時，95% 置信區間大約是 `p ± 1.96 × √(p(1 − p) / n)`：

```python
import math

def accuracy_ci(correct, total):
    p = correct / total
    half = 1.96 * math.sqrt(p * (1 - p) / total)
    return p, p - half, p + half

for name, correct in [("模型 A", 360), ("模型 B", 375)]:
    p, low, high = accuracy_ci(correct, 500)
    print(f"{name}：500 題對了 {correct} 題，正確率 {p:.1%}，95% 置信區間 [{low:.1%}, {high:.1%}]")
```

72% 和 75% 看起來差了 3 分，但兩個區間大幅重疊——只有 500 道題時，這點差距**完全可能是運氣**。題目少的評測（AIME 每年只有 30 道題！）尤其要注意：常見的做法是對每道題取樣多次，報告平均的正確率。

### 最好的評測是你自己的評測

公開評測衡量的是通用能力。如果你要用模型做一件具體的事——給客服郵件分類、從合同裡提取條款、回答你公司產品的問題——最可靠的辦法是**收集幾十到幾百個真實的例子**，寫好標準答案或評分規則，建一個自己的評測集。每次換模型、改提示詞，都先在它上面跑一遍。第七部分會更詳細地講。

## 5.7 小結

- 困惑度（或損失）衡量語言建模能力，但依賴分詞器；每位元組位元數與分詞無關。
- 選擇題可以生成答案，也可以比較選項的對數機率；打分方式、提示格式、範例數量都會影響分數，比較時必須一致。
- 數學題用精確匹配，要先規範化答案；程式碼題用單元測試和 pass@k，pass@k 要用無偏估計 `1 − C(n−c, k)/C(n, k)`。
- 沒有標準答案時用人類偏好（Arena + Elo）或大模型評委；評委有位置、長度、自我偏好等偏差。
- 評測會飽和、會被汙染、對提示敏感；分數有統計誤差，要看置信區間。
- 為自己的任務建立專門的評測集。

### 練習 2：pass@k

輸入 n、c、k：每道題生成了 n 個答案，其中 c 個透過了測試。用無偏估計計算 pass@k，保留 4 位小數。

<details>
<summary>提示</summary>

### 練習 3：Elo 評分

輸入一行：A 的分數、B 的分數、A 的比賽結果（1 贏、0.5 平、0 輸）、K 值。輸出比賽後 A 和 B 的新分數，各保留 1 位小數，用空格隔開。

```text

```

<details>
<summary>提示</summary>

`expected_a = 1 / (1 + 10 ** ((rb - ra) / 400))`，`change = k * (score - expected_a)`，A 加上 change，B 減去 change。
</details>

<details>

<!-- exercise: small-diff -->
### 練習 5：差 3 分說明什麼？

在一個有 200 道題的評測上，模型 X 的正確率是 70%，模型 Y 是 73%。下面哪個結論最合理？

- Y 一定比 X 強
- X 一定比 Y 強
- 這點差距在統計誤差範圍內，還不能確定誰更強，需要更多的題目或更多次的取樣
- 評測集太小，分數毫無意義

<details>
<summary>答案與解析</summary>

200 道題、70% 左右的正確率，95% 置信區間的半寬約為 6.4 個百分點，兩個模型的區間大幅重疊，3 分的差距很可能只是隨機波動。分數並非毫無意義，只是不足以區分這兩個模型。
</details>

<!-- exercise: judge-bias -->
### 練習 6：大模型評委

讓一個大模型比較兩個回答哪個更好時，下面哪種做法能減輕它的**位置偏差**？

- 只給它看更長的那個回答
- 交換兩個回答的順序再評一次，兩次結論一致才採用
- 讓被評測的模型自己當評委
- 把溫度設為 2

<details>
<summary>答案與解析</summary>

位置偏差是指評委偏愛某個位置上的回答。交換順序各評一次，就能發現並抵消這種偏差。讓模型給自己打分會引入自我偏好；溫度和回答長度與位置偏差無關。
</details>
