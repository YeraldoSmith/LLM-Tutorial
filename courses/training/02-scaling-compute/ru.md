## 2.1 Считаем параметры

В трансформере из урока 5 части 3 параметры сосредоточены в двух местах: во внимании и в сети прямого распространения (MLP). При размерности модели d и L слоях:

- внимание: четыре матрицы d × d для Q, K, V и выхода — всего **4d²**;
- MLP: две матрицы d → 4d → d — всего **8d²**;
- итого примерно **12d²** на слой, плюс матрица эмбеддингов V × d для словаря размера V.

Современные модели в стиле Llama немного отличаются: K и V используют **групповое внимание по запросам** (GQA, урок 4) с меньшим числом голов; MLP — это SwiGLU с тремя матрицами; входные эмбеддинги и выходной слой обычно не общие. Посчитаем оба варианта:

```python
def gpt2_params(L, d, V, ctx):
    per_layer = 12 * d * d + 13 * d          # матрицы 12d² плюс смещения и LayerNorm
    return L * per_layer + V * d + ctx * d + 2 * d

def llama_params(L, d, n_heads, n_kv, ffn, V):
    head_dim = d // n_heads
    attn = 2 * d * d + 2 * d * n_kv * head_dim    # Q и выход — d×d; у K и V только n_kv голов
    mlp = 3 * d * ffn                             # SwiGLU: гейт, проекции вверх и вниз
    per_layer = attn + mlp + 2 * d                # плюс два RMSNorm
    return L * per_layer + 2 * V * d + d          # входные эмбеддинги + выходной слой (не общие) + финальный RMSNorm

print(f"GPT-2 small : {gpt2_params(12, 768, 50257, 1024) / 1e6:.0f}M")
print(f"GPT-2 XL    : {gpt2_params(48, 1600, 50257, 1024) / 1e9:.2f}B")
print(f"Llama 3 8B  : {llama_params(32, 4096, 32, 8, 14336, 128256) / 1e9:.2f}B")
print(f"Llama 3 70B : {llama_params(80, 8192, 64, 8, 28672, 128256) / 1e9:.2f}B")
```

Результаты в точности совпадают с официальными числами параметров (124 млн, 1,5 млрд, 8,0 млрд, 70,6 млрд). Заметьте: чем больше модель, тем сильнее параметры сосредоточены в матрицах слоёв (растущих как d²) и тем меньше доля эмбеддингов.

## 2.2 Вычисления: C ≈ 6ND

Обучение модели с N параметрами на D токенах требует примерно такого объёма вычислений (операций с плавающей точкой, FLOPs):

```formula
C ≈ 6 · N · D
```

Почему 6? На каждый параметр и каждый токен:

- **прямой проход** делает одно умножение и одно сложение → 2 операции;
- **обратный проход** считает градиенты и по входам, и по параметрам — примерно вдвое больше работы → 4 операции.

(Собственные вычисления внимания зависят от длины последовательности и при не очень длинных последовательностях составляют малую долю; здесь мы их опускаем.) Аналогично **инференс** стоит примерно **2N** операций на каждый сгенерированный токен.

С этой формулой можно оценить время обучения:

```python
def train_days(N, D, gpus, peak_tflops, mfu):
    flops = 6 * N * D
    per_second = gpus * peak_tflops * 1e12 * mfu      # операций, реально выполняемых кластером за секунду
    return flops / per_second / 86400

H100 = 989            # пиковая производительность H100 на плотных матрицах BF16, около 989 TFLOPS
print(f"8 млрд параметров × 15 трлн токенов: {6 * 8e9 * 15e12:.1e} FLOPs")
for N, D, gpus in [(8e9, 15e12, 1024), (70e9, 15e12, 4096), (405e9, 15e12, 16384)]:
    days = train_days(N, D, gpus, H100, 0.40)
    print(f"{N / 1e9:>4.0f}B параметров, {D / 1e12:.0f}T токенов, {gpus:>5} H100: около {days:5.1f} дней")
```

- **MFU** (Model FLOPs Utilization, доля использования вычислений): пик GPU — лишь теоретическая величина. При настоящем обучении приходится ждать данные и обмен между устройствами, выполнять всякую служебную работу; **30–50%** считается хорошим результатом.
- Meta обучала Llama 3 405B на **16 000 H100**; DeepSeek сообщает, что полное обучение DeepSeek-V3 заняло около **2,79 млн GPU-часов на H800**. Это тот же порядок величин, что и наши оценки.

## 2.3 Законы масштабирования

В 2020 году Kaplan и др. из OpenAI обнаружили поразительную закономерность: в огромном диапазоне (на несколько порядков) тестовые потери языковой модели плавно падают по **степенному закону** от числа параметров N, объёма данных D и вычислений C. В логарифмических координатах это почти прямая — увеличивайте масштаб, и результаты **предсказуемо** улучшаются. Это и есть **законы масштабирования** (scaling laws), и именно они дают компаниям смелость вкладывать огромные деньги во всё более крупные модели.

В 2022 году Hoffmann и др. из DeepMind (статья **Chinchilla**) обучили больше 400 моделей и записали потери как функцию параметров и данных:

```formula
L(N, D) = E + A / N^α + B / D^β
```

- E — **неустранимые потери**: присущая языку случайность, которую не уберёт никакая модель;
- A / N^α — потери из-за **слишком маленькой** модели;
- B / D^β — потери из-за **нехватки данных**.

С коэффициентами из повторной подгонки данных Chinchilla (Besiroglu и др., 2024) посмотрим, как разделить **фиксированный объём вычислений** между параметрами и данными:

```python
E, A, B, alpha, beta = 1.82, 482.01, 2085.43, 0.3478, 0.3658

def loss(N, D):
    return E + A / N**alpha + B / D**beta

def best_split(C):                         # C фиксировано: перебираем N, а D задаётся из C = 6ND
    candidates = [10 ** (k / 100) for k in range(700, 1300)]
    return min(candidates, key=lambda N: loss(N, C / (6 * N)))

print("вычисления C   лучшее N      лучшее D     D/N   прогноз потерь")
for C in (1e21, 1e22, 1e23, 5.76e23, 1e24, 1e25):
    N = best_split(C)
    D = C / (6 * N)
    print(f"{C:9.1e}   {N / 1e9:10.1f}B   {D / 1e9:10.0f}B  {D / N:5.1f}   {loss(N, D):.3f}")

print()
print(f"Gopher     280B параметров × 0.3T токенов: потери {loss(280e9, 0.3e12):.3f}")
print(f"Chinchilla  70B параметров × 1.4T токенов: потери {loss(70e9, 1.4e12):.3f}")
```

Выводы:

- С ростом вычислений **параметры и данные должны расти примерно пропорционально**; в оптимуме приходится около **20 токенов на параметр**.
- До этого в основном наращивали число параметров. Собственная модель DeepMind Gopher (280 млрд параметров, 300 млрд токенов) на самом деле была **недообучена**. При тех же вычислениях (строка 5.8e+23 в таблице) вчетверо меньшая модель — Chinchilla, 70 млрд параметров на 1,4 трлн токенов — оказалась лучше.

## 2.4 Почему сегодняшние модели обучают сверх оптимума

Оптимум Chinchilla учитывает только стоимость **обучения**. Но обученная однажды модель используется миллионы раз, а стоимость **инференса** пропорциональна числу параметров. Поэтому сейчас обычно обучают модель меньше «оптимальной» на гораздо большем, чем в 20 раз, числе токенов — чуть дороже обучение, зато каждый будущий ответ дешевле.

```python
E, A, B, alpha, beta = 1.82, 482.01, 2085.43, 0.3478, 0.3658

def loss(N, D):
    return E + A / N**alpha + B / D**beta

N = 8e9
print("Модель на 8 млрд параметров читает всё больше данных:")
for D in (160e9, 1e12, 5e12, 15e12, 36e12):
    print(f"  {D / 1e12:5.2f}T токенов ({D / N:5.0f} на параметр): прогноз потерь {loss(N, D):.3f}")
```

Llama 3 8B прочитала 15 триллионов токенов — почти в 100 раз больше «оптимума», — и её потери всё ещё снижались. (Эти числа **экстраполированы** по формуле и показывают лишь тенденцию: модели, на которых формулу подгоняли, были гораздо меньше.)

## 2.5 Память: почему один GPU не обучит большую модель

Сколько памяти GPU нужно на каждый параметр при обучении? При распространённой схеме **смешанной точности BF16 + оптимизатор Adam**:

| Что хранится | Байт на параметр |
|--------------|------------------|
| параметры в BF16 (для прямого и обратного прохода) | 2 |
| градиенты в BF16 | 2 |
| «главные» параметры в FP32 (для обновления, ради точности) | 4 |
| первый момент Adam m (FP32) | 4 |
| второй момент Adam v (FP32) | 4 |
| **Итого** | **16** |

```python
import math

def train_memory_gb(N):
    return 16 * N / 1e9                      # без активаций

def infer_memory_gb(N, bytes_per_param=2):
    return bytes_per_param * N / 1e9         # только параметры (без KV-кэша — см. часть 6)

for N in (1e9, 8e9, 70e9, 405e9):
    need = train_memory_gb(N)
    print(f"{N / 1e9:>4.0f}B: обучение около {need:>6.0f} ГБ (не меньше {math.ceil(need / 80):>3} GPU по 80 ГБ), "
          f"инференс в BF16 около {infer_memory_gb(N):>4.0f} ГБ")
```

И это ещё без **активаций** — промежуточных результатов прямого прохода, нужных обратному. Они растут с размером батча и длиной последовательности и часто занимают больше места, чем параметры. Поэтому на одном GPU с 80 ГБ не поместится состояние обучения даже модели на 8 млрд параметров, а модели на 70 млрд нужен минимум десяток с лишним. Следующий урок покажет, как распределить модели и данные по сотням и тысячам GPU.

## 2.6 Эмерджентность, вычисления во время ответа и новые направления

- **Эмерджентные способности**: некоторые умения (например, арифметика с многозначными числами) будто бы «внезапно появляются», когда модель достигает определённого размера. Но Schaeffer и др. (2023) показали, что это во многом зависит от метрики: при оценке «всё или ничего» умение выглядит как скачок, а при непрерывной метрике (скажем, точности каждой цифры) улучшение на самом деле плавное.
- **Вычисления во время ответа** (test-time compute): с 2024 года **модели-рассуждатели** — OpenAI o1, DeepSeek-R1 и другие — показали ещё один путь масштабирования: не только увеличивать обучение, но и позволять модели «подумать подольше» перед ответом, порождая длинную цепочку рассуждений. Чем больше она думает, тем больше трудных задач решает, — новый вид закона масштабирования (подробно в части 5).
- **Стена данных**: качественного человеческого текста конечное количество, и при нынешних темпах он может закончиться через несколько лет. Это подталкивает исследования синтетических данных, мультимодальных данных и более эффективного обучения.

## 2.7 Итоги

- Около 12d² параметров на слой (в стиле GPT); для моделей в стиле Llama учитывайте GQA, SwiGLU и раздельные эмбеддинги.
- Вычисления на обучение C ≈ 6ND; инференс ≈ 2N на токен; дни обучения = 6ND ÷ (число GPU × пиковая производительность × MFU).
- Законы масштабирования: потери плавно падают по степенному закону от N, D и C; L(N, D) = E + A/N^α + B/D^β.
- Chinchilla: при фиксированных вычислениях N и D растут пропорционально, около 20 токенов на параметр; чтобы удешевить инференс, сегодняшние модели часто далеко превышают это соотношение.
- Память на обучение — около 16 байт на параметр (BF16 + Adam) плюс активации; инференс в BF16 — около 2 байт на параметр.
- Новые направления: вычисления во время ответа и синтетические данные.

### Задание 5: Шестёрка в 6ND

Откуда берётся «6» в формуле вычислений на обучение C ≈ 6ND?

- это число матриц в каждом слое трансформера
- на каждый параметр и токен: около 2 операций в прямом проходе и около 4 в обратном
- это эмпирическое число без объяснения
- Adam хранит 6 чисел на каждый параметр

<details>
<summary>Ответ и разбор</summary>

В прямом проходе каждый параметр участвует в одном умножении и одном сложении (2 операции); обратный проход считает градиенты и по входам, и по параметрам — примерно вдвое больше (4 операции). Всего 6. Инференс — это только прямой проход, отсюда около 2N на токен.
</details>
