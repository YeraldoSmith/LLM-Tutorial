## 1.2 Откуда берутся данные

- **Веб-страницы**: большая часть данных — из интернета, а важнейший открытый источник — **Common Crawl**, некоммерческая организация, которая с 2008 года раз в один-два месяца обходит интернет, по нескольку миллиардов страниц за раз, и бесплатно публикует результат.
- **Код**: открытые репозитории на GitHub и в других местах. Код не только учит модель программировать — считается, что он улучшает и рассуждения.
- **Книги, статьи, энциклопедии**: Википедия, статьи arXiv, книги в общественном достоянии — качественно, но мало.
- **Математика и наука**: математические сайты, учебники, разборы задач — им уделяют всё больше внимания.
- **Многоязычные данные**: русского, китайского и других языков в интернете гораздо меньше, чем английского, поэтому их обычно собирают отдельно и увеличивают их долю.
- **Синтетические данные**: текст, сгенерированный или переписанный существующими большими моделями (раздел 1.6).

Происхождение данных связано и с **авторским правом и лицензиями**: какие данные можно использовать для обучения и нужно ли разрешение — с 2023 года это предмет судебных исков и законодательства во многих странах. Поэтому открытое сообщество собрало немало наборов данных с ясным происхождением и лицензией, например **FineWeb** от Hugging Face (2024: около 15 триллионов токенов английского веб-текста, обработанных из 96 выпусков Common Crawl, причём весь код обработки опубликован).

## 1.3 Конвейер обработки данных

В сырых веб-страницах полно меню навигации, рекламы, «кракозябр», повторов и некачественного текста. Типичный конвейер выглядит так:

```text
сырые веб-страницы (HTML)
   │ ① извлечь основной текст: убрать HTML-теги, навигацию, подвалы
   ▼
чистый текст ── ② определение языка: что это за язык?
   │ ③ эвристическая фильтрация: выбросить слишком короткое, мусорное, с избытком символов, слишком повторяющееся
   │ ④ дедупликация: из одинаковых и почти одинаковых оставить одну копию
   │ ⑤ классификация качества: модель оценивает «образовательную ценность», «качество текста»
   │ ⑥ удаление личных данных: адреса почты, телефоны, номера документов…
   │ ⑦ деконтаминация: удалить текст, совпадающий с тестовыми заданиями
   ▼
текст, готовый к обучению (часто лишь несколько процентов исходных данных)
```

### Эвристическая фильтрация

Сначала простые правила быстро отсеивают очевидный мусор. DeepMind при обучении Gopher (2021) собрала набор таких правил (длина документа, средняя длина слова, доля символов, степень повторов и т. п.), и с тех пор они широко используются. Вот упрощённая версия:

```python
def check(doc):
    words = doc.split()
    if not 5 <= len(words) <= 100_000:          # Gopher требует не меньше 50 слов; для демонстрации ослаблено до 5
        return "длина"
    mean_len = sum(len(w) for w in words) / len(words)
    if not 3 <= mean_len <= 10:
        return "длина слов"
    if sum(any(c.isalpha() for c in w) for w in words) / len(words) < 0.8:
        return "мало слов с буквами"
    if len({w.lower() for w in words}) / len(words) < 0.3:
        return "слишком много повторов"
    return "оставить"

docs = [
    "Photosynthesis is the process by which green plants turn sunlight, water and carbon dioxide into sugar.",
    "Home | About | Login",
    "$$$ 100% !!! ### 2026 *** >>> <<< ### $$$ 100%",
    "click here click here click here click here click here click here",
    "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb c d e",
]
for d in docs:
    print(f"{d[:40]:<42}→ {check(d)}")
```

Правила грубые, зато очень быстрые. Учтите, что они придуманы **для конкретного языка**: в китайском нет пробелов между словами, так что `doc.split()` для него почти бесполезен — китайский текст считают по символам или сначала разбивают на слова.

### Точная дедупликация

Одна и та же статья перепечатывается на сотнях и тысячах сайтов. Повторы тратят вычисления впустую и заставляют модель **заучивать** этот текст. Простейшая дедупликация: нормализовать текст (единый регистр, схлопнутые пробелы), вычислить **хеш** и для каждого хеша оставить только первый документ:

```python
import hashlib
import re

def key(doc):
    normalized = re.sub(r"\s+", " ", doc.lower()).strip()
    return hashlib.sha256(normalized.encode()).hexdigest()

docs = [
    "Water boils at 100 degrees Celsius at sea level.",
    "Paris is the capital of France.",
    "water  boils at 100 degrees celsius at   sea level.",
    "Water boils at 100 degrees Celsius at sea level!",
]
seen, unique = set(), []
for d in docs:
    k = key(d)
    if k not in seen:
        seen.add(k)
        unique.append(d)
print(f"документов: {len(docs)} → {len(unique)}")
for d in unique:
    print(" ", d)
```

Третий документ отличается только регистром и пробелами — он удалён; но у четвёртого всего один лишний восклицательный знак, и хеш совсем другой. В интернете масса «почти дубликатов» — поменяли пару слов, добавили дату, другой подвал страницы, — и для них нужна **приближённая дедупликация**.

### Приближённая дедупликация: MinHash

Насколько похожи два документа, часто измеряют **мерой Жаккара**: режем каждый документ на маленькие кусочки (**шинглы**, например каждые 5 подряд идущих символов) и делим размер пересечения двух множеств шинглов A и B на размер их объединения:

```formula
J(A, B) = |A ∩ B| / |A ∪ B|
```

Но сравнить миллиарды документов попарно невозможно. Хитрость **MinHash**: оценить каждый шингл хеш-функцией и взять наименьший; вероятность того, что у двух документов «наименьший шингл» совпадёт, **в точности равна** их мере Жаккара. Со 128 разными хеш-функциями получается «подпись» из 128 чисел, и доля совпадающих позиций двух подписей оценивает меру Жаккара:

```python
import hashlib

def shingles(text, k=5):
    t = " ".join(text.lower().split())
    return {t[i:i + k] for i in range(len(t) - k + 1)}

def jaccard(a, b):
    return len(a & b) / len(a | b)

def h(s, seed):                       # хеш-функция номер seed
    digest = hashlib.md5(f"{seed}:{s}".encode()).digest()
    return int.from_bytes(digest[:8], "big")

def minhash(sh, num=128):             # подпись: минимум по каждой хеш-функции
    return [min(h(s, seed) for s in sh) for seed in range(num)]

def estimate(sig1, sig2):
    return sum(a == b for a, b in zip(sig1, sig2)) / len(sig1)

docs = {
    "A": "The quick brown fox jumps over the lazy dog near the old river bank.",
    "B": "The quick brown fox jumped over the lazy dog near the old river bank!",
    "C": "Large language models are trained on trillions of tokens of text.",
}
sh = {k: shingles(v) for k, v in docs.items()}
sig = {k: minhash(v) for k, v in sh.items()}
for x, y in [("A", "B"), ("A", "C")]:
    print(f"{x}-{y}: точная мера Жаккара {jaccard(sh[x], sh[y]):.2f}, оценка MinHash {estimate(sig[x], sig[y]):.2f}")
```

Подпись из 128 чисел гораздо короче текста. Добавим **хеширование с учётом близости** (LSH): разрежем подпись на b полос по r чисел, и если хоть одна полоса совпадает целиком, запишем пару документов в «кандидаты» для тщательного сравнения. Документы с похожестью s становятся кандидатами с вероятностью `1 - (1 - s^r)^b`. При b = 16 и r = 8:

| Похожесть s | 0,3 | 0,5 | 0,7 | 0,8 | 0,9 |
|-------------|-----|-----|-----|-----|-----|
| Вероятность стать кандидатами | 0,001 | 0,06 | 0,61 | 0,95 | 1,00 |

Почти все похожие пары находятся, а почти все непохожие даже не сравниваются, — так что дедупликация миллиардов документов занимает линейное время.

### Классификаторы качества

Правила убирают лишь очевидный мусор. Следующий шаг — **обучить классификатор оценивать документы**. Типичный пример — FineWeb-Edu (2024): большая модель (Llama 3 70B) сначала оценила сотни тысяч веб-страниц по «образовательной ценности» от 0 до 5; на этих оценках обучили маленький быстрый классификатор, он оценил все страницы, и остались только высоко оценённые. Модели, обученные лишь на этих 1,3 триллиона токенов «образовательных» страниц, заметно лучше справлялись с тестами на знания и рассуждения, чем модели, обученные на всех страницах.

### Удаление личных данных и деконтаминация

- **Личные данные**: правила и модели находят адреса почты, номера телефонов, IP-адреса, номера документов и т. п., их заменяют или удаляют.
- **Деконтаминация**: если тестовые задания (и ответы к ним) есть в обучающих данных, высокий балл модели может быть просто «заучен». Поэтому документы с длинными совпадениями с тестовыми наборами (скажем, 13 одинаковых слов подряд) удаляют. Мы вернёмся к этому в уроке 5.

## 1.4 Смеси, повторы и отжиг

Как смешиваются данные из разных источников, называется **смесью данных** (data mixture). Она сильно влияет на модель, и её обычно подбирают по множеству экспериментов с маленькими моделями. Важный вопрос: качественных данных часто мало, и смесь может требовать **прочитать их несколько раз**:

```python
budget = 15_000                # всего обучаемся на 15 триллионах токенов (в миллиардах)
sources = {                    # имя: (сколько есть, доля в смеси) — числа условные
    "веб":        (30_000, 0.70),
    "код":        (2_000, 0.15),
    "математика": (500, 0.07),
    "книги и статьи": (400, 0.05),
    "другие языки": (3_000, 0.03),
}
for name, (size, share) in sources.items():
    used = budget * share
    print(f"{used / size:4.2f} эпохи ({used:>6,.0f}B токенов)  {name}")
```

Исследования (Muennighoff и др., 2023) показывают, что повторение одних и тех же данных **примерно до 4 раз** работает почти так же, как новые данные; дальше польза быстро падает.

Многие модели завершают предобучение фазой, где скорость обучения опускается очень низко, а доля качественных данных (математика, код, учебники, отобранные страницы) растёт. Это **отжиг** (annealing): он заметно улучшает модель на сравнительно небольшом числе токенов.

## 1.5 Упаковка в обучающие последовательности

Модель обрабатывает последовательности фиксированной длины (скажем, 4096 или 8192 токена), а документы бывают разной длины. Обычно все документы склеивают друг за другом, после каждого ставят **токен конца** (EOS) и режут поток на равные блоки:

```python
docs = [[5, 8, 2], [7, 7], [1, 2, 3, 4, 5, 6], [9]]   # документы, уже разбитые на токены (id токенов)
EOS = 0
L = 4                                                 # длина одной обучающей последовательности

stream = []
for d in docs:
    stream += d + [EOS]                               # EOS между документами
print("склеено:", stream)

for i in range(0, len(stream) - L, L):
    x = stream[i:i + L]                               # вход
    y = stream[i + 1:i + L + 1]                       # цель: «следующий токен» в каждой позиции
    print("вход", x, "→ цель", y)
```

- Цель — это вход, сдвинутый на одну позицию: каждая позиция предсказывает следующий токен, в точности как в уроке 6 части 3.
- После упаковки в одной последовательности может оказаться несколько несвязанных документов. Простые реализации позволяют им «видеть» друг друга; более аккуратные меняют маску внимания, чтобы каждый токен видел только предыдущие токены **своего документа**.
- Длинные документы разрезаются между последовательностями. Отдельная фаза обучения на «длинный контекст» использует более длинные последовательности и больше длинных документов (урок 4).

## 1.6 Синтетические данные

Качественный человеческий текст заканчивается, и **синтетические данные** становятся всё важнее:

- **Переписывание**: модель переписывает посредственные веб-страницы в ясные вопросы-ответы или текст в стиле учебника;
- **Генерация**: модели Phi от Microsoft (с 2023 года) обучались на большом количестве сгенерированного «учебникового» текста, и даже небольшие модели получили неплохие способности к рассуждению;
- **Проверяемые данные**: математические задачи и код можно проверять автоматически, поэтому их генерируют массово и отбирают (в части 5 вы увидите, как этим пользуются модели-рассуждатели).

Но у синтетических данных есть риски: если поколение за поколением моделей обучать только на выходе предыдущего поколения, ответы становятся всё однообразнее, а редкие знания теряются — это **коллапс модели** (model collapse). Поэтому синтетику обычно смешивают с настоящими данными и тщательно фильтруют.

## 1.7 Итоги

- Данные для предобучения измеряются триллионами токенов: у Llama 3 больше 15T, у Qwen3 около 36T.
- Главный источник — веб (Common Crawl), плюс код, книги, статьи, математика и многоязычные данные.
- Конвейер: извлечение текста → определение языка → эвристические фильтры → дедупликация → классификатор качества → удаление личных данных → деконтаминация; часто остаются лишь проценты.
- Точная дедупликация: нормализация + хеш; приближённая: шинглы + MinHash (доля совпавших позиций ≈ мера Жаккара) + полосы LSH.
- Смесь задаёт долю каждого вида данных; качественные данные можно повторять несколько раз; в финальной фазе отжига больше качественных данных.
- Документы склеивают через EOS и режут на равные последовательности; цель — вход со сдвигом на один.
- Синтетические данные всё важнее, но нужно избегать коллапса модели.

### Задание 4: Сколько эпох у каждого источника?

В первой строке — общее число обучающих токенов `T` (в миллиардах). Каждая следующая строка до конца ввода описывает источник: `имя объём доля` (объём тоже в миллиардах токенов). Как в разделе 1.4, выведите, сколько раз читается каждый источник, в виде `имя эпохи` с 2 знаками после запятой.

```text
Пример ввода:
1000
web 2000 0.8
code 100 0.15
math 20 0.05
Пример вывода:
web 0.40
code 1.50
math 2.50
```

<details>
<summary>Подсказка</summary>

Эпохи = `T * доля / объём`. Чтение до конца ввода: `import sys`, `for line in sys.stdin:`.
</details>

### Задание 5: Зачем деконтаминация?

Для чего нужна «деконтаминация» при обработке данных для предобучения?

- чтобы удалить страницы с вирусами и вредоносным кодом
- чтобы тестовые задания не попали в обучающие данные и не завысили оценки
- чтобы удалить текст с личными данными
- чтобы убрать повторяющиеся веб-страницы

<details>
<summary>Ответ и разбор</summary>

Если модель видела тестовые вопросы и ответы во время обучения, её высокий балл может означать лишь то, что она их запомнила, а не настоящие способности. Поэтому обучающие документы с длинными совпадениями с тестовыми наборами удаляют. Личные данные и дедупликация — другие шаги конвейера.
</details>

### Задание 6: Для чего MinHash?

Для чего в основном используется MinHash при обработке данных?

- чтобы оценивать качество документов
- чтобы определять язык документа
- чтобы эффективно находить почти одинаковые документы
- чтобы разбивать документы на токены

<details>
<summary>Ответ и разбор</summary>

MinHash оценивает меру Жаккара двух документов по короткой подписи, а вместе с полосами LSH быстро находит почти дубликаты среди огромного числа документов. Качество оценивают классификаторами, язык — специальными моделями, а на токены текст разбивает токенизатор.
</details>
