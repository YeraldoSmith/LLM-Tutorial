## 6.1 Переобучение и недообучение

На самом деле нас интересует, как модель работает на **новых данных, которых она не видела**. Это называется **обобщением** (generalization).

- **Недообучение** (underfitting): модель слишком проста или мало обучена и не справляется даже с обучающей выборкой.
- **Переобучение** (overfitting): модель «зазубрила» обучающую выборку вместе с шумом и случайностями и ошибается на новых данных.

В примере ниже настоящее правило — «x > 5 означает класс 1», но 20% меток неверны (в реальных данных всегда есть шум). Классификатор «смотрит на k ближайших к x обучающих примеров и голосует большинством»:

```python
import random
random.seed(1)

def make(n):
    data = []
    for _ in range(n):
        x = random.uniform(0, 10)
        y = 1 if x > 5 else 0          # настоящее правило: x > 5 — класс 1
        if random.random() < 0.2:      # но 20% меток неверны (шум)
            y = 1 - y
        data.append((x, y))
    return data

train, test = make(100), make(1000)

def predict(x, k):                     # k ближайших обучающих примеров, голосование большинством
    near = sorted(train, key=lambda p: abs(p[0] - x))[:k]
    return 1 if sum(y for _, y in near) * 2 > k else 0

def accuracy(data, k):
    return sum(predict(x, k) == y for x, y in data) / len(data)

for k in (1, 5, 25):
    print(f"k={k:2d}  точность на обучении {accuracy(train, k):.0%}   на тесте {accuracy(test, k):.0%}")
```

При `k=1` на обучающей выборке 100% правильных ответов (ближайший сосед каждой точки — она сама), но точность на тесте самая низкая: модель запомнила и неверные метки. **Результат на обучающей выборке может обманывать**, поэтому данные делят на три части:

| Выборка | Назначение |
|---------|-----------|
| **обучающая** (train) | по ней считают градиенты и обновляют параметры |
| **валидационная** (validation) | проверяет обобщение во время обучения; по ней выбирают гиперпараметры (скорость обучения, размер модели…) и момент остановки |
| **тестовая** (test) | используется один раз в самом конце для итогового результата |

Если во время обучения рисовать обе кривые потерь, проблему видно сразу:

```text
потери                                    потери
 │╲                                         │╲
 │ ╲___ валидация                           │ ╲      ___── валидация (растёт = переобучение)
 │  ╲  ‾‾‾‾‾‾‾‾‾‾                           │  ╲___/
 │   ╲___ обучение                          │   ╲___
 │       ‾‾‾‾‾‾‾‾‾  обе высокие = недообучение │    ‾‾‾‾‾‾─── обучение (всё падает)
 └──────────────── шаги                     └──────────────── шаги
```

> [!NOTE]
> При предобучении LLM данных огромное количество (триллионы токенов), и каждый пример обычно встречается один или несколько раз, поэтому модель **редко переобучается**; главная проблема — недообучение. Поэтому увеличение модели и данных продолжает помогать (в части 4 поговорим о «законах масштабирования»). А вот при **дообучении** (fine-tuning) данных мало, и переобучение встречается очень часто.

## 6.2 Скорость обучения — главный гиперпараметр

Минимизируем `f(x) = x²` (минимум в 0) градиентным спуском, начиная с `x = 5`, и посмотрим, что дают разные скорости обучения:

```python
def descend(lr, steps=10):
    x = 5.0                       # минимизируем f(x) = x², минимум в x = 0
    path = []
    for _ in range(steps):
        x -= lr * 2 * x           # f'(x) = 2x
        path.append(x)
    return path

for lr in (0.01, 0.1, 0.9, 1.1):
    xs = descend(lr)
    print(f"lr={lr:<5} после 10 шагов x = {xs[-1]:10.4f}   первые 5 шагов:", " ".join(f"{v:.1f}" for v in xs[:5]))
```

| Скорость обучения | Что происходит |
|-------------------|----------------|
| слишком мала (0.01) | стабильно, но очень медленно; за 10 шагов почти не сдвинулись |
| подходящая (0.1) | уверенно приближаемся к 0 |
| великовата (0.9) | прыгаем туда-сюда (колебания), но всё же сходимся |
| слишком велика (1.1) | с каждым шагом всё дальше — **расходимся**; в реальном обучении потери становятся `inf` / `nan` |

> [!TIP]
> Если обучение пошло не так, **первым делом подозревайте скорость обучения**. Обычные стартовые значения: `1e-3`–`3e-4` для Adam/AdamW; `1e-4`–`6e-4` для предобучения LLM (чем больше модель, тем обычно меньше скорость); `1e-5`–`2e-4` для дообучения.

## 6.3 Расписание скорости обучения: разогрев + косинусное затухание

Скорость обучения не обязана быть постоянной. Почти все большие модели обучают с таким **расписанием** (schedule):

1. **Разогрев** (warmup): первые сотни или тысячи шагов скорость линейно растёт почти от 0 до максимума. В начале параметры случайны, а градиенты «хаотичны»; большие шаги сразу могут сломать обучение.
2. **Косинусное затухание** (cosine decay): потом скорость медленно снижается по косинусу до маленького значения. Меньшие шаги в конце позволяют точно «осесть» в низине.

```python
import math

def lr_at(step, max_lr=3e-4, warmup=100, total=1000, min_lr=3e-5):
    if step < warmup:                                   # линейный разогрев
        return max_lr * (step + 1) / warmup
    progress = (step - warmup) / (total - warmup)       # от 0 до 1
    return min_lr + (max_lr - min_lr) * 0.5 * (1 + math.cos(math.pi * progress))

for step in [0, 25, 50, 75] + list(range(100, 1001, 100)):
    lr = lr_at(step)
    print(f"step {step:4d}  lr {lr:.6f}  " + "█" * round(lr / 3e-4 * 40))
```

> [!NOTE]
> В некоторых новых рецептах применяют расписание **WSD** (Warmup-Stable-Decay): после разогрева скорость долго держится на максимуме и быстро снижается только в самом конце. Плюс в том, что обучение можно продлить в любой момент, не задавая заранее общее число шагов.

## 6.4 Оптимизаторы: SGD, Momentum, Adam и AdamW

Обычный градиентный спуск (SGD) мучается на функциях потерь в форме «длинной узкой долины»: он мечется поперёк крутого направления и ползёт вдоль пологого. Функция `x² + 100y²` ниже — как раз такая долина:

```python
import math

def loss_grad(x, y):                  # узкая долина: круто по y, полого по x
    return x * x + 100 * y * y, (2 * x, 200 * y)

def run(update, steps=1000):
    p, state = [-4.0, 1.0], {}
    for t in range(1, steps + 1):
        loss, g = loss_grad(*p)
        if loss < 1e-4:
            return t
        update(p, g, state, t)
    return None

def sgd(p, g, s, t, lr=0.009):        # чуть больше (от 0.01) — и по y начинается расхождение
    for i in range(2):
        p[i] -= lr * g[i]

def momentum(p, g, s, t, lr=0.005, beta=0.9):
    v = s.setdefault("v", [0.0, 0.0])
    for i in range(2):
        v[i] = beta * v[i] + g[i]                # «скорость»: накопленные прошлые градиенты; колебания гасятся
        p[i] -= lr * v[i]

def adam(p, g, s, t, lr=0.1, b1=0.9, b2=0.999, eps=1e-8):
    m = s.setdefault("m", [0.0, 0.0])
    v = s.setdefault("v", [0.0, 0.0])
    for i in range(2):
        m[i] = b1 * m[i] + (1 - b1) * g[i]       # первый момент: скользящее среднее градиента (направление)
        v[i] = b2 * v[i] + (1 - b2) * g[i] ** 2  # второй момент: скользящее среднее квадрата градиента (величина)
        m_hat = m[i] / (1 - b1 ** t)             # коррекция смещения (сначала m и v смещены к 0)
        v_hat = v[i] / (1 - b2 ** t)
        p[i] -= lr * m_hat / (math.sqrt(v_hat) + eps)   # у каждого параметра свой размер шага

for name, fn in [("SGD", sgd), ("Momentum", momentum), ("Adam", adam)]:
    t = run(fn)
    print(f"{name:9s}", f"дошёл до минимума за {t} шагов" if t else "не дошёл за 1000 шагов")
```

| Оптимизатор | Идея | Примечания |
|-------------|------|-----------|
| **SGD** | шаг против градиента | самый простой; очень чувствителен к скорости обучения |
| **Momentum** | добавляем «инерцию»: сохраняем прежнюю скорость | колебания гасятся, по пологим направлениям движение ускоряется |
| **Adam** | инерция + **размер шага подстраивается под величину градиента каждого параметра** | у параметров с большими градиентами шаг меньше и наоборот; нечувствителен к гиперпараметрам |
| **AdamW** | Adam + **отделённое затухание весов** | стандарт для обучения больших моделей; обычно `betas=(0.9, 0.95)`, `weight_decay=0.1` |

> [!NOTE]
> Оптимизаторы продолжают развиваться. Новые, например **Muon**, уже применялись при обучении некоторых больших моделей (скажем, Kimi K2) и, по заявлениям, требуют меньше вычислений, чем AdamW. Но AdamW остаётся самым распространённым и надёжным выбором. Учтите: Adam хранит для каждого параметра ещё два значения, `m` и `v`, поэтому **состояние оптимизатора занимает вдвое больше памяти, чем сами параметры** — одна из причин, почему обучению нужно гораздо больше памяти, чем инференсу.

## 6.5 Инициализация: важна стартовая точка

Начальные значения параметров нельзя выбирать как попало:

- **Все нули?** Нельзя. Все нейроны слоя будут выдавать одно и то же, получать одинаковые градиенты и навсегда останутся одинаковыми — как будто нейрон всего один. Чтобы нарушить симметрию, нужны **случайные** числа.
- **Важен и масштаб случайных чисел.** При прохождении слоя за слоем слишком большие значения всё растут (взрыв), а слишком маленькие всё уменьшаются (затухание).

```python
import math
import random
random.seed(0)

n, depth = 64, 10

def std(v):
    m = sum(v) / len(v)
    return math.sqrt(sum((a - m) ** 2 for a in v) / len(v))

def forward(scale):
    x = [random.gauss(0, 1) for _ in range(n)]
    stds = []
    for _ in range(depth):
        W = [[random.gauss(0, scale) for _ in range(n)] for _ in range(n)]
        x = [max(0.0, sum(w * a for w, a in zip(row, x))) for row in W]   # линейный слой + ReLU
        stds.append(std(x))
    return stds

print("инициализация     слой 1   слой 4   слой 7   слой 10 (стандартное отклонение выхода слоя)")
for name, scale in [("std=1", 1.0), ("std=0.01", 0.01), ("Kaiming √(2/n)", math.sqrt(2 / n))]:
    s = forward(scale)
    print(f"{name:15s}", "  ".join(f"{v:7.2g}" for v in (s[0], s[3], s[6], s[9])))
```

**Инициализация Кайминга (He)** задаёт весам каждого слоя стандартное отклонение `√(2/n)` (`n` — размерность входа), и сигнал от слоя к слою сохраняет примерно тот же размер. `nn.Linear` в PyTorch по умолчанию использует похожее масштабирование, так что обычно об этом можно не думать; модели вроде GPT обычно инициализируют нормальным распределением со средним 0 и отклонением 0.02, дополнительно уменьшая выходные слои остаточных ветвей в зависимости от глубины.

## 6.6 Нормализация: LayerNorm и RMSNorm

Даже при хорошей инициализации масштаб значений в ходе обучения «уплывает». Слои **нормализации** возвращают каждый вектор к «стандартному размеру»:

- **LayerNorm**: вычитаем среднее и делим на стандартное отклонение → среднее 0, дисперсия 1. Используется в исходном Transformer и GPT-2.
- **RMSNorm**: среднее не вычитаем, только делим на среднеквадратичное `√(mean(x²))`. Дешевле, работает не хуже, и **почти все современные LLM (Llama, Qwen, DeepSeek…) используют именно её**.

```python
import math

def layer_norm(x, eps=1e-5):
    mean = sum(x) / len(x)
    var = sum((a - mean) ** 2 for a in x) / len(x)
    return [(a - mean) / math.sqrt(var + eps) for a in x]

def rms_norm(x, eps=1e-5):
    rms = math.sqrt(sum(a * a for a in x) / len(x) + eps)
    return [a / rms for a in x]

x = [2.0, 4.0, 6.0, 8.0]
print("LayerNorm:", [round(v, 3) for v in layer_norm(x)])
print("RMSNorm:  ", [round(v, 3) for v in rms_norm(x)])
big = [v * 1000 for v in x]
print("RMSNorm после умножения на 1000:", [round(v, 3) for v in rms_norm(big)])   # не изменилось
```

Настоящие слои нормализации затем умножают результат на **обучаемый** вектор масштаба `γ` (LayerNorm ещё прибавляет сдвиг `β`), чтобы сеть сама решала, какой масштаб ей нужен. `eps` — крошечное число, защищающее от деления на ноль.

> [!NOTE]
> Вы могли слышать и о **BatchNorm**: он нормализует по примерам внутри батча и часто встречается в сетях для изображений (CNN). В языковых моделях предложения разной длины, а при инференсе часто обрабатывается одна последовательность, поэтому используют LayerNorm / RMSNorm, которые нормализуют **каждый вектор отдельно**.

## 6.7 Остаточные связи: магистраль для градиентов

Чем глубже сеть, тем больше локальных производных перемножается при обратном распространении. Если каждая меньше 1, через несколько десятков умножений получается почти 0 — **затухание градиентов**, и первые слои вообще не учатся.

**Остаточные связи** (residual connections, предложены в ResNet в 2015 году) решают это очень простой идеей: выход каждого слоя = **его вход + изменение, которое вычислил слой**, то есть `y = x + f(x)`. Производная равна `1 + f'(x)`, и эта «единица» гарантирует, что градиент проходит через каждый слой как минимум без потерь.

```python
import math

def grad_through(depth, residual, w=0.5):
    x, grad = 1.0, 1.0
    for _ in range(depth):
        f = math.tanh(w * x)
        local = w * (1 - f * f)                   # производная f(x) = tanh(w·x)
        if residual:
            x, grad = x + f, grad * (1 + local)   # y = x + f(x), производная = 1 + f'(x)
        else:
            x, grad = f, grad * local
    return grad

for depth in (5, 20, 50):
    print(f"{depth:2d} слоёв  обычная: {grad_through(depth, False):.2e}   с остаточной связью: {grad_through(depth, True):.2f}")
```

Каждый слой Transformer состоит ровно из двух остаточных блоков:

```formula
x = x + Attention(Norm(x))
x = x + MLP(Norm(x))
```

Такая схема «нормализуй, посчитай, прибавь обратно» называется **Pre-Norm**. Это стандарт для современных больших моделей, позволяющий стабильно обучать сети из сотни с лишним слоёв. Подробно — в части 3.

## 6.8 Регуляризация: боремся с переобучением

| Метод | Как | Интуиция |
|-------|-----|----------|
| **затухание весов** (weight decay) | на каждом шаге немного тянем параметры к 0: `w -= lr * λ * w` | веса не разрастаются, модель «глаже» |
| **dropout** | при обучении случайно обнуляем часть выходов нейронов | сеть не может полагаться на отдельный нейрон и учит более устойчивые признаки |
| **ранняя остановка** (early stopping) | останавливаемся, когда валидационные потери перестают падать, и берём лучшую контрольную точку | останавливаемся до того, как модель начнёт зубрить |
| **больше данных / аугментация** | собираем больше данных или преобразуем имеющиеся | самое фундаментальное средство |

Dropout реализуется просто. Сохранённые при обучении значения **делятся на `1 − p`**, чтобы среднее значение выхода не менялось; при оценке dropout выключается (это одна из задач `model.eval()`):

```python
import random
random.seed(0)

def dropout(x, p=0.5, training=True):
    if not training:
        return x
    return [0.0 if random.random() < p else a / (1 - p) for a in x]

x = [1.0] * 8
print("обучение:", dropout(x))
print("оценка:  ", dropout(x, training=False))
avg = sum(sum(dropout(x)) for _ in range(10000)) / 10000 / len(x)
print("среднее при обучении:", round(avg, 3))     # около 1, как и при оценке
```

> [!NOTE]
> При **предобучении** LLM dropout обычно не используют (данных столько, что переобучение редкость), а вот затухание весов AdamW применяют. При дообучении на маленьких наборах данных dropout и ранняя остановка очень полезны.

## 6.9 Обрезка градиентов

Иногда особенно «странный» батч даёт огромный градиент, который за один шаг отбрасывает параметры далеко, и потери скачут в `nan` («всплеск потерь»). **Обрезка градиентов** (gradient clipping): если общая длина всех градиентов (**глобальная норма**) превышает порог, пропорционально уменьшаем их, сохраняя направление.

```python
import math

def clip_by_norm(grads, max_norm):
    norm = math.sqrt(sum(g * g for g in grads))      # глобальная норма: длина всех градиентов как одного вектора
    if norm <= max_norm:
        return grads
    return [g * max_norm / norm for g in grads]       # направление то же, длина сжата до max_norm

print(clip_by_norm([0.3, -0.4], 1.0))     # длина 0.5: обрезать не нужно
print(clip_by_norm([30.0, -40.0], 1.0))   # длина 50: сжимаем до 1
```

Почти все большие модели обучают с `max_norm=1.0`. В PyTorch это одна строка — `torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)` — между `backward()` и `step()`.

## 6.10 Смешанная точность: fp32, fp16, bf16

Стандартный `float32` (fp32) занимает 4 байта на число. 16-битные (2-байтовые) форматы вдвое экономят память и гораздо быстрее на GPU:

| Формат | Байт | Диапазон | Точность | Примечания |
|--------|------|----------|----------|-----------|
| fp32 | 4 | около ±3.4×10³⁸ | около 7 значащих цифр | по умолчанию |
| fp16 | 2 | около ±65504 | около 3–4 цифр | узкий диапазон, легко переполняется, нужно «масштабирование потерь» |
| **bf16** | 2 | как у fp32 | около 2–3 цифр | широкий диапазон, трудно переполнить; **основной формат обучения LLM** |
| fp8 / fp4 | 1 / 0.5 | меньше | ниже | поддерживаются новейшими GPU; DeepSeek-V3 и другие обучались в fp8 |

Встроенный модуль `struct` позволяет увидеть потерю точности своими глазами:

```python
import struct

def to_fp16(x):
    return struct.unpack("e", struct.pack("e", x))[0]       # "e" — 16-битная половинная точность

def to_bf16(x):
    bits = struct.unpack("I", struct.pack("f", x))[0]       # биты 32-битного числа
    return struct.unpack("f", struct.pack("I", bits & 0xFFFF0000))[0]   # bf16 = только старшие 16 бит

for x in (0.1, 3.14159, 1000.7):
    print(f"{x:<8}  fp16 → {to_fp16(x):<12.7g} bf16 → {to_bf16(x):.7g}")

try:
    to_fp16(70000.0)
except OverflowError:
    print("70000 вне диапазона fp16 (максимум около 65504)")
print("Может ли bf16 представить 70000?", to_bf16(70000.0))   # да, только неточно
```

**Обучение со смешанной точностью**: «основная копия» параметров и состояние оптимизатора хранятся в fp32, а большая часть прямого и обратного прохода считается в bf16. В PyTorch (на GPU):

```python norun
with torch.autocast(device_type="cuda", dtype=torch.bfloat16):
    loss = loss_fn(model(xb), yb)
loss.backward()
```

> [!TIP]
> Простое правило оценки памяти: для **инференса** модели в bf16 нужно 2 байта на параметр, то есть 7 миллиардов (7B) параметров ≈ 14 ГБ; для **обучения** (AdamW + смешанная точность) — около 16 байт на параметр, то есть модель 7B ≈ 112 ГБ, не считая промежуточных активаций. Поэтому для дообучения популярны экономные методы вроде LoRA (часть 5).

## 6.11 Всё вместе: современный скрипт обучения

Вот все приёмы урока в PyTorch: остаточные блоки + RMSNorm + GELU + dropout + AdamW (затухание весов) + расписание с разогревом и косинусом + обрезка градиентов. Это почти скелет обучения мини-Transformer (не хватает только внимания):

```python requires=torch
import math
import torch
from torch import nn

torch.manual_seed(0)

class Block(nn.Module):                      # современный остаточный блок: Norm → MLP → Dropout, плюс вход
    def __init__(self, d, p_drop=0.1):
        super().__init__()
        self.norm = nn.RMSNorm(d)
        self.mlp = nn.Sequential(nn.Linear(d, 4 * d), nn.GELU(), nn.Linear(4 * d, d))
        self.drop = nn.Dropout(p_drop)

    def forward(self, x):
        return x + self.drop(self.mlp(self.norm(x)))      # остаточная связь

model = nn.Sequential(nn.Linear(8, 32), *[Block(32) for _ in range(4)], nn.Linear(32, 1))
X = torch.randn(512, 8)
y = (X[:, :1] * X[:, 1:2]).sin()                         # произвольная нелинейная цель

total_steps, warmup = 300, 30
optimizer = torch.optim.AdamW(model.parameters(), lr=3e-3, weight_decay=0.1)
def schedule(step):                                       # возвращает множитель скорости обучения
    if step < warmup:
        return (step + 1) / warmup
    return 0.5 * (1 + math.cos(math.pi * (step - warmup) / (total_steps - warmup)))
scheduler = torch.optim.lr_scheduler.LambdaLR(optimizer, schedule)

for step in range(total_steps):
    idx = torch.randint(0, len(X), (64,))                 # случайный мини-батч
    loss = nn.functional.mse_loss(model(X[idx]), y[idx])
    optimizer.zero_grad()
    loss.backward()
    norm = torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)   # обрезка градиентов
    optimizer.step()
    scheduler.step()                                      # обновляем скорость обучения
    if step % 100 == 0 or step == total_steps - 1:
        print(f"step {step:3d}  loss {loss.item():.4f}  lr {scheduler.get_last_lr()[0]:.5f}  grad_norm {norm:.2f}")

model.eval()                                              # режим оценки: dropout выключен
with torch.no_grad():
    print("итоговая MSE:", round(nn.functional.mse_loss(model(X), y).item(), 4))
```

## 6.13 Итоги

- Важно **обобщение**: следите за валидационной выборкой; обучающие потери падают, а валидационные растут — **переобучение**; обе высокие — **недообучение**.
- Важнее всего **скорость обучения**: слишком большая расходится, слишком маленькая медленная; большие модели используют **разогрев + косинусное затухание**.
- **AdamW** = инерция + адаптивные шаги + отделённое затухание весов, оптимизатор по умолчанию; его состояние занимает вдвое больше памяти, чем параметры.
- Хорошая **инициализация** (случайная, правильного масштаба), **нормализация** (RMSNorm/LayerNorm) и **остаточные связи** (`x + f(x)`) делают глубокие сети обучаемыми.
- Регуляризация: затухание весов, dropout, ранняя остановка, больше данных; **обрезка градиентов** (глобальная норма 1.0) предотвращает всплески потерь.
- Смешанная точность **bf16** вдвое экономит память и ускоряет вычисления при том же диапазоне, что у fp32.
