## 1.1 一句话：预测下一个词

你一定用过手机输入法的「联想」：打出「今天天气」，它会建议「很好」「不错」「怎么样」。它在做的事情是：**根据前面的文字，猜下一个最可能出现的词**。

大语言模型（**L**arge **L**anguage **M**odel，LLM）——ChatGPT、Claude、Gemini、DeepSeek、通义千问、Kimi、Llama 背后的东西——做的**本质上是同一件事**，只是做得好得多：

```text
输入：  "床前明月"
模型：  下一个字是「光」的概率 97%，「亮」2%，「照」0.5% ……
选出「光」，接到后面："床前明月光"
再预测下一个字："床前明月光，" → 「疑」……
不断重复，就「写」出了一整段文字。
```

这个过程叫**自回归生成**（autoregressive generation）：每次只预测一个，再把它接到输入后面，继续预测下一个。你和聊天机器人对话时看到文字一个一个蹦出来，就是这个原因。

> [!IMPORTANT]
> 记住这句话，后面的所有内容都是在回答「怎么把它做好」：**大语言模型是一个根据前文，计算「下一个 token 是什么」的概率分布的函数。**

## 1.2 动手：10 行代码写一个「语言模型」

最简单的方法是**数数**：在一堆文字里，统计每个词后面跟着什么词、出现了几次，预测时选出现次数最多的那个。

```python
text = "我 爱 学习 。 我 爱 编程 。 我 爱 学习 大模型 。 你 爱 学习 吗 ？"
words = text.split()

# 统计：每个词后面跟着什么词、各几次
follow = {}
for current, nxt in zip(words, words[1:]):
    follow.setdefault(current, {})
    follow[current][nxt] = follow[current].get(nxt, 0) + 1

print(follow["我"])     # {'爱': 3}
print(follow["爱"])     # {'学习': 3, '编程': 1}

# 生成：从「你」开始，每次选出现最多的下一个词
word = "你"
sentence = [word]
for _ in range(4):
    candidates = follow[word]
    word = max(candidates, key=candidates.get)
    sentence.append(word)
print(" ".join(sentence))
```

输出：

```text
{'爱': 3}
{'学习': 3, '编程': 1}
你 爱 学习 。 我
```

恭喜，你写出了一个（非常小的）语言模型！它只看**前一个词**来预测下一个词，叫做**二元语法模型**（bigram model）。第三部分的第 1 课会把它做得更完整：用概率代替次数、随机采样、计算它「猜得有多准」。

它的问题也很明显：

- 只看前 1 个词，**记不住上下文**：「我爱学习」之后它不知道前面说过什么；
- 没见过的词组合就**完全不会**；
- 不懂意思，只会背统计。

真正的大模型用**神经网络**代替这张统计表，可以同时考虑前面**几十万个词**，并且学到了词的含义、语法、事实知识乃至推理的模式。从统计表到神经网络，就是这门课第二、三部分要走的路。

## 1.3 「大」在哪里？

| 维度 | 我们的小模型 | 现代大模型（2026 年的典型规模） |
|------|--------------|------------------------------|
| **参数**（可调的数字） | 十几个计数 | 几十亿到上万亿个（7B、70B、600B+；B = billion，十亿） |
| **训练数据** | 一句话 | 十几万亿个 token 的网页、书籍、代码、论文 |
| **能看到的上文** | 1 个词 | 几万到上百万个 token（上下文窗口） |
| **训练成本** | 0.001 秒 | 数千张 GPU 训练数周到数月 |

**参数**（parameters，也叫权重 weights）是神经网络里的一个个数字。训练的过程，就是**不断调整这些数字**，让模型预测下一个词预测得越来越准。「70B 模型」意思是有 700 亿个参数；如果每个参数用 2 个字节保存，光是存下这些数字就需要约 140 GB。

令人惊讶的是：**仅仅是把「预测下一个词」这件事在海量数据上做到极致**，模型就「被迫」学会了很多东西——因为要准确预测下一个词，它必须理解语法、记住事实、跟上逻辑，甚至模拟写作者的意图。

## 1.4 Token：模型眼中的「词」

模型处理的最小单位不是字、也不是词，而是 **token**。一个 token 可能是一个完整的常用词、半个词，或者一个标点：

```text
英文 "unbelievable"  →  ["un", "believ", "able"]       3 个 token
中文 "大语言模型"     →  ["大", "语言", "模型"]          约 2～3 个 token（取决于分词器）
数字 "2026"          →  ["202", "6"] 或 ["2026"]        取决于分词器
```

把文字切成 token 的工具叫**分词器**（tokenizer），第三部分第 2 课会亲手实现一个。目前只需要知道：

- 一般来说，1 个 token 大约是 0.75 个英文单词，或 1～2 个汉字（不同模型差别很大）；
- 模型的价格、速度、能处理的长度，都是**按 token 计算**的；
- 模型一次能看到的最大 token 数叫**上下文窗口**（context window）。

## 1.5 一个大模型是怎样炼成的

```text
 ① 预训练 Pre-training           ② 指令微调 SFT             ③ 偏好对齐 RLHF / DPO       ④ 推理强化 RL
 海量文本上「预测下一个词」  →   用「问题→好回答」示范  →   人类/AI 比较哪个回答更好  →  在数学、代码等可验证的
 得到「基座模型」                教它按对话格式回答          让回答更有用、更安全          任务上奖励正确答案，学会
 （会续写，不会聊天）            （会聊天了）                                             「先思考再回答」
```

1. **预训练**：在十几万亿 token 的文本上训练「预测下一个词」。得到的**基座模型**（base model）知识丰富，但只会续写——你问它问题，它可能接着编出更多问题。（第四部分）
2. **监督微调**（SFT）：用大量「用户提问 → 理想回答」的示范数据继续训练，模型学会以助手的身份回答问题。（第五部分）
3. **偏好对齐**：让人（或 AI）比较两个回答哪个更好，用这些偏好继续训练（RLHF、DPO 等方法），让模型更有帮助、更诚实、更安全。（第五部分）
4. **推理强化学习**：近两年的重要进展。在数学题、编程题这类**答案能自动验证**的任务上做强化学习，模型学会在回答前写出很长的思考过程，推理能力大幅提升。OpenAI o 系列、DeepSeek-R1 等「推理模型」都用了这类方法。（第五部分）

之后还有**部署**：把训练好的模型高效地运行起来，服务成千上万的用户（第六部分），以及基于模型**开发应用**（第七部分）。

## 1.6 训练与推理

两个经常出现的词：

- **训练**（training）：调整参数的过程。很贵，只做一次（或少数几次）。
- **推理**（inference）：用训练好的模型生成回答。每次用户提问都要做一次。

> [!NOTE]
> 中文里「推理」一词有两个意思：一是这里的 inference（运行模型），二是 reasoning（逻辑推理，如「推理模型」）。看上下文区分；本课程在可能混淆时会注明英文。

## 1.7 大模型擅长什么、不擅长什么

✅ 擅长：写作和改写、翻译、总结、回答常识问题、写代码和解释代码、头脑风暴、从文字中提取信息、多轮对话……

⚠️ 需要注意：

- **幻觉**（hallucination）：模型会**一本正经地编造**不存在的事实、论文、网址或函数。原因是它的目标是「写出看起来合理的下一个词」，而不是「只说真话」。重要信息一定要核实。
- **知识截止**：模型只知道训练数据截止时间之前的事。要了解最新信息，需要给它联网搜索或提供资料（第七部分的 RAG）。
- **精确计算**：大数相乘、数数字母这类任务容易出错（和 token 的切分方式有关）。让它调用计算器或写代码来算会可靠得多（第七部分的工具调用）。
- **对提问方式敏感**：同一个问题换个说法，答案可能不同（第七部分的提示词工程）。

## 1.9 小结

- 大语言模型做的事：**根据前文，计算下一个 token 的概率**；不断重复就生成了文字（自回归）。
- 最简单的语言模型可以靠「数数」实现；大模型用神经网络，能看很长的上文，并学到了意义和知识。
- 参数是模型里可调的数字，训练就是调整参数；token 是模型处理文字的单位；上下文窗口是一次能看的最大 token 数。
- 炼成路线：预训练 → 指令微调 → 偏好对齐 → 推理强化学习 → 部署与应用。
- 大模型会幻觉、有知识截止、不擅长精确计算——重要信息要核实。

### 练习 1：核心任务

大语言模型在生成文字时，最核心的一步是什么？

- 在数据库里搜索现成的答案
- 根据前面的文字，计算下一个 token 的概率
- 把问题翻译成英文再回答
- 随机组合常用的句子

<details>
<summary>答案与解析</summary>

LLM 每次只做一件事：给出下一个 token 的概率分布，选出一个，接到后面，再重复。它并不是在数据库里查答案。
</details>

<!-- exercise: next-word -->
### 练习 2：最常见的下一个词

起始代码里已经有一段文字 `text`。程序读入一个词，输出在 `text` 中**紧跟在它后面、出现次数最多**的词。如果次数相同，输出**在文中先出现**的那个。

```text
样例输入：the
样例输出：cat
```

（`the` 后面跟着 cat 2 次、mat 1 次、fish 1 次。）

<details>
<summary>提示 1</summary>

参考 1.2 节：用 `zip(words, words[1:])` 遍历相邻的两个词，用字典统计次数。
</details>

<details>
<summary>提示 2</summary>

`max(counts, key=counts.get)` 会返回次数最多的键；次数相同时，它返回字典里**先加入**的那个，正好符合「先出现」的要求。
</details>

<!-- exercise: hallucination -->
### 练习 3：幻觉

你让一个大模型推荐 3 篇关于某个冷门话题的论文，它给出了标题、作者和年份，看起来很专业。最合理的做法是？

- 直接引用，大模型不会出错
- 逐一搜索核实这些论文是否真的存在
- 要求它把字数写多一点
- 换一种字体显示

<details>
<summary>答案与解析</summary>

大模型可能编造看起来真实的论文（幻觉）。凡是事实、引用、数据，都要去可靠来源核实。
</details>

<!-- exercise: stages -->
### 练习 4：哪个阶段？

「在海量网页、书籍、代码上训练模型预测下一个词，得到一个知识丰富但只会续写的模型」，这是哪个阶段？

- 预训练
- 指令微调
- 偏好对齐
- 部署

<details>
<summary>答案与解析</summary>

预训练（pre-training）。它得到的是基座模型；之后的指令微调和对齐才让它变成好用的助手。
</details>
