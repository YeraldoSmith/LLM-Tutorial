## 1.1 一句話：預測下一個詞

你一定用過手機輸入法的「聯想」：打出「今天天氣」，它會建議「很好」「不錯」「怎麼樣」。它在做的事情是：**根據前面的文字，猜下一個最可能出現的詞**。

大語言模型（**L**arge **L**anguage **M**odel，LLM）——ChatGPT、Claude、Gemini、DeepSeek、通義千問、Kimi、Llama 背後的東西——做的**本質上是同一件事**，只是做得好得多：

```text
輸入：  "床前明月"
模型：  下一個字是「光」的機率 97%，「亮」2%，「照」0.5% ……
選出「光」，接到後面："床前明月光"
再預測下一個字："床前明月光，" → 「疑」……
不斷重複，就「寫」出了一整段文字。
```

這個過程叫**自迴歸生成**（autoregressive generation）：每次只預測一個，再把它接到輸入後面，繼續預測下一個。你和聊天機器人對話時看到文字一個一個蹦出來，就是這個原因。

> [!IMPORTANT]
> 記住這句話，後面的所有內容都是在回答「怎麼把它做好」：**大語言模型是一個根據前文，計算「下一個 token 是什麼」的機率分佈的函式。**

## 1.2 動手：10 行程式碼寫一個「語言模型」

最簡單的方法是**數數**：在一堆文字裡，統計每個詞後面跟著什麼詞、出現了幾次，預測時選出現次數最多的那個。

```python
text = "我 愛 學習 。 我 愛 程式設計 。 我 愛 學習 大模型 。 你 愛 學習 嗎 ？"
words = text.split()

# 統計：每個詞後面跟著什麼詞、各幾次
follow = {}
for current, nxt in zip(words, words[1:]):
    follow.setdefault(current, {})
    follow[current][nxt] = follow[current].get(nxt, 0) + 1

print(follow["我"])     # {'愛': 3}
print(follow["愛"])     # {'學習': 3, '程式設計': 1}

# 生成：從「你」開始，每次選出現最多的下一個詞
word = "你"
sentence = [word]
for _ in range(4):
    candidates = follow[word]
    word = max(candidates, key=candidates.get)
    sentence.append(word)
print(" ".join(sentence))
```

輸出：

```text
{'愛': 3}
{'學習': 3, '程式設計': 1}
你 愛 學習 。 我
```

恭喜，你寫出了一個（非常小的）語言模型！它只看**前一個詞**來預測下一個詞，叫做**二元語法模型**（bigram model）。第三部分的第 1 課會把它做得更完整：用機率代替次數、隨機取樣、計算它「猜得有多準」。

它的問題也很明顯：

- 只看前 1 個詞，**記不住上下文**：「我愛學習」之後它不知道前面說過什麼；
- 沒見過的片語合就**完全不會**；
- 不懂意思，只會背統計。

真正的大模型用**神經網路**代替這張統計表，可以同時考慮前面**幾十萬個詞**，並且學到了詞的含義、語法、事實知識乃至推理的模式。從統計表到神經網路，就是這門課第二、三部分要走的路。

## 1.3 「大」在哪裡？

| 維度 | 我們的小模型 | 現代大模型（2026 年的典型規模） |
|------|--------------|------------------------------|
| **引數**（可調的數字） | 十幾個計數 | 幾十億到上萬億個（7B、70B、600B+；B = billion，十億） |
| **訓練資料** | 一句話 | 十幾萬億個 token 的網頁、書籍、程式碼、論文 |
| **能看到的上文** | 1 個詞 | 幾萬到上百萬個 token（上下文視窗） |
| **訓練成本** | 0.001 秒 | 數千張 GPU 訓練數週到數月 |

**引數**（parameters，也叫權重 weights）是神經網路裡的一個個數字。訓練的過程，就是**不斷調整這些數字**，讓模型預測下一個詞預測得越來越準。「70B 模型」意思是有 700 億個引數；如果每個引數用 2 個位元組儲存，光是存下這些數字就需要約 140 GB。

令人驚訝的是：**僅僅是把「預測下一個詞」這件事在海量資料上做到極致**，模型就「被迫」學會了很多東西——因為要準確預測下一個詞，它必須理解語法、記住事實、跟上邏輯，甚至模擬寫作者的意圖。

## 1.4 Token：模型眼中的「詞」

模型處理的最小單位不是字、也不是詞，而是 **token**。一個 token 可能是一個完整的常用詞、半個詞，或者一個標點：

```text
英文 "unbelievable"  →  ["un", "believ", "able"]       3 個 token
中文 "大語言模型"     →  ["大", "語言", "模型"]          約 2～3 個 token（取決於分詞器）
數字 "2026"          →  ["202", "6"] 或 ["2026"]        取決於分詞器
```

把文字切成 token 的工具叫**分詞器**（tokenizer），第三部分第 2 課會親手實現一個。目前只需要知道：

- 一般來說，1 個 token 大約是 0.75 個英文單詞，或 1～2 個漢字（不同模型差別很大）；
- 模型的價格、速度、能處理的長度，都是**按 token 計算**的；
- 模型一次能看到的最大 token 數叫**上下文視窗**（context window）。

## 1.5 一個大模型是怎樣煉成的

```text
 ① 預訓練 Pre-training           ② 指令微調 SFT             ③ 偏好對齊 RLHF / DPO       ④ 推理強化 RL
 海量文字上「預測下一個詞」  →   用「問題→好回答」示範  →   人類/AI 比較哪個回答更好  →  在數學、程式碼等可驗證的
 得到「基座模型」                教它按對話格式回答          讓回答更有用、更安全          任務上獎勵正確答案，學會
 （會續寫，不會聊天）            （會聊天了）                                             「先思考再回答」
```

1. **預訓練**：在十幾萬億 token 的文字上訓練「預測下一個詞」。得到的**基座模型**（base model）知識豐富，但只會續寫——你問它問題，它可能接著編出更多問題。（第四部分）
2. **監督微調**（SFT）：用大量「使用者提問 → 理想回答」的示範資料繼續訓練，模型學會以助手的身份回答問題。（第五部分）
3. **偏好對齊**：讓人（或 AI）比較兩個回答哪個更好，用這些偏好繼續訓練（RLHF、DPO 等方法），讓模型更有幫助、更誠實、更安全。（第五部分）
4. **推理強化學習**：近兩年的重要進展。在數學題、程式設計題這類**答案能自動驗證**的任務上做強化學習，模型學會在回答前寫出很長的思考過程，推理能力大幅提升。OpenAI o 系列、DeepSeek-R1 等「推理模型」都用了這類方法。（第五部分）

之後還有**部署**：把訓練好的模型高效地執行起來，服務成千上萬的使用者（第六部分），以及基於模型**開發應用**（第七部分）。

## 1.6 訓練與推理

兩個經常出現的詞：

- **訓練**（training）：調整引數的過程。很貴，只做一次（或少數幾次）。
- **推理**（inference）：用訓練好的模型生成回答。每次使用者提問都要做一次。

> [!NOTE]
> 中文裡「推理」一詞有兩個意思：一是這裡的 inference（執行模型），二是 reasoning（邏輯推理，如「推理模型」）。看上下文區分；本課程在可能混淆時會註明英文。

## 1.7 大模型擅長什麼、不擅長什麼

✅ 擅長：寫作和改寫、翻譯、總結、回答常識問題、寫程式碼和解釋程式碼、頭腦風暴、從文字中提取資訊、多輪對話……

⚠️ 需要注意：

- **幻覺**（hallucination）：模型會**一本正經地編造**不存在的事實、論文、網址或函式。原因是它的目標是「寫出看起來合理的下一個詞」，而不是「只說真話」。重要資訊一定要核實。
- **知識截止**：模型只知道訓練資料截止時間之前的事。要了解最新資訊，需要給它聯網搜尋或提供資料（第七部分的 RAG）。
- **精確計算**：大數相乘、數數字母這類任務容易出錯（和 token 的切分方式有關）。讓它呼叫計算器或寫程式碼來算會可靠得多（第七部分的工具呼叫）。
- **對提問方式敏感**：同一個問題換個說法，答案可能不同（第七部分的提示詞工程）。

## 1.9 小結

- 大語言模型做的事：**根據前文，計算下一個 token 的機率**；不斷重複就生成了文字（自迴歸）。
- 最簡單的語言模型可以靠「數數」實現；大模型用神經網路，能看很長的上文，並學到了意義和知識。
- 引數是模型裡可調的數字，訓練就是調整引數；token 是模型處理文字的單位；上下文視窗是一次能看的最大 token 數。
- 煉成路線：預訓練 → 指令微調 → 偏好對齊 → 推理強化學習 → 部署與應用。
- 大模型會幻覺、有知識截止、不擅長精確計算——重要資訊要核實。

## 1.10 練習

<!-- exercise: core-idea -->
### 練習 1：核心任務

大語言模型在生成文字時，最核心的一步是什麼？

- 在資料庫裡搜尋現成的答案
- 根據前面的文字，計算下一個 token 的機率
- 把問題翻譯成英文再回答
- 隨機組合常用的句子

<details>
<summary>答案與解析</summary>

LLM 每次只做一件事：給出下一個 token 的機率分佈，選出一個，接到後面，再重複。它並不是在資料庫裡查答案。
</details>

<!-- exercise: next-word -->
### 練習 2：最常見的下一個詞

起始程式碼裡已經有一段文字 `text`。程式讀入一個詞，輸出在 `text` 中**緊跟在它後面、出現次數最多**的詞。如果次數相同，輸出**在文中先出現**的那個。

```text
樣例輸入：the
樣例輸出：cat
```

（`the` 後面跟著 cat 2 次、mat 1 次、fish 1 次。）

<details>
<summary>提示 1</summary>

參考 1.2 節：用 `zip(words, words[1:])` 遍歷相鄰的兩個詞，用字典統計次數。
</details>

<details>
<summary>提示 2</summary>

`max(counts, key=counts.get)` 會返回次數最多的鍵；次數相同時，它返回字典裡**先加入**的那個，正好符合「先出現」的要求。
</details>

<!-- exercise: hallucination -->
### 練習 3：幻覺

你讓一個大模型推薦 3 篇關於某個冷門話題的論文，它給出了標題、作者和年份，看起來很專業。最合理的做法是？

- 直接引用，大模型不會出錯
- 逐一搜尋核實這些論文是否真的存在
- 要求它把字數寫多一點
- 換一種字型顯示

<details>
<summary>答案與解析</summary>

大模型可能編造看起來真實的論文（幻覺）。凡是事實、引用、資料，都要去可靠來源核實。
</details>

<!-- exercise: stages -->
### 練習 4：哪個階段？

「在海量網頁、書籍、程式碼上訓練模型預測下一個詞，得到一個知識豐富但只會續寫的模型」，這是哪個階段？

- 預訓練
- 指令微調
- 偏好對齊
- 部署

<details>
<summary>答案與解析</summary>

預訓練（pre-training）。它得到的是基座模型；之後的指令微調和對齊才讓它變成好用的助手。
</details>
