# 6. Вероятность и информация: как оценивают модели

>

В уроке 1 мы сказали: языковая модель выдаёт **распределение вероятностей следующего токена**. Этот урок проясняет каждое слово этой фразы и показывает, как оценивать предсказания модели.

## 6.1 Распределения вероятностей

**Вероятность** — число от 0 до 1, показывающее, насколько возможно событие. Перечислите вероятности всех исходов — и получите **распределение вероятностей**; их **сумма равна 1**.

```text
кубик:     1      2      3      4      5      6
p:        1/6    1/6    1/6    1/6    1/6    1/6     (равномерное распределение)

следующее слово для «Погода сегодня очень ___»:
         хорошая жаркая холодная плохая странная
p:       0.55    0.25   0.12     0.05   0.03         (в сумме 1)
```

### Выбор по вероятности

Имея распределение, можно **случайно вытянуть исход** — вероятные выпадают чаще. Именно так языковая модель выбирает слова при генерации:

```python
import random
random.seed(0)

words = ["хорошая", "жаркая", "холодная", "плохая", "странная"]
probs = [0.55, 0.25, 0.12, 0.05, 0.03]
samples = random.choices(words, weights=probs, k=1000)
for w in words:
    print(w, samples.count(w) / 1000)       # частоты в выборке приближаются к вероятностям
```

Всегда брать самое вероятное слово («хорошая») — это **жадное декодирование** (greedy decoding); выбор по вероятностям делает текст разнообразнее. О стратегиях сэмплирования подробно — в уроке 7 части 3.

## 6.2 Softmax: из оценок в вероятности

Последний слой нейросети выдаёт произвольные числа — **логиты** (logits): они бывают отрицательными, и их сумма не равна 1. Превратить их в вероятности помогает **softmax**:

```formula
softmax(zᵢ) = e^zᵢ / Σⱼ e^zⱼ
```

Два шага: ① возвести e в степень каждого числа, `e^z` (все становятся положительными, а различия растягиваются); ② разделить на сумму (чтобы в сумме была 1).

```python
import math

def softmax(logits):
    exps = [math.exp(z) for z in logits]
    total = sum(exps)
    return [e / total for e in exps]

logits = [2.0, 1.0, 0.1]
probs = softmax(logits)
print([round(p, 4) for p in probs])     # [0.659, 0.2424, 0.0986]
print(sum(probs))                        # 1.0 (с точностью до крошечной погрешности)
```

Наибольшая оценка получает наибольшую вероятность, но остальным тоже кое-что достаётся — это «мягче», чем просто выбрать максимум, отсюда *soft*max.

### Численно устойчивая версия

`math.exp(1000)` переполняется (слишком большое число). Настоящие логиты бывают большими, поэтому на практике **сначала вычитают максимум** — результат тот же (числитель и знаменатель умножаются на `e^(−max)`), но переполнения нет:

```python
import math

def softmax(logits):
    m = max(logits)
    exps = [math.exp(z - m) for z in logits]
    total = sum(exps)
    return [e / total for e in exps]

print([round(p, 4) for p in softmax([1000.0, 999.0, 998.1])])   # без ошибок
```

### Температура: насколько быть уверенной

Разделите логиты на **температуру** `T` перед softmax:

```python
import math

def softmax(logits):
    m = max(logits)
    exps = [math.exp(z - m) for z in logits]
    s = sum(exps)
    return [e / s for e in exps]

logits = [2.0, 1.0, 0.1]
for T in [0.5, 1.0, 2.0]:
    print(f"T={T}:", [round(p, 3) for p in softmax([z / T for z in logits])])
```

- `T < 1`: распределение «острее» — почти всегда первый вариант; вывод консервативнее и стабильнее;
- `T > 1`: распределение «площе» — случайнее, творческее, но и болтливее.

Параметр `temperature` в API чат-ботов — именно это.

## 6.3 Почему логарифм повсюду?

**Логарифм** — обратная операция к экспоненте: `e^x = y` ⇔ `x = ln y` (в курсе `log` — натуральный логарифм). В вероятностях он повсюду по двум причинам:

**① Превращает произведения в суммы.** Вероятность фразы — **произведение** вероятностей её слов. 100 слов по 0.1 дают 10⁻¹⁰⁰ — слишком мало для точного представления (исчезновение порядка, underflow). Логарифм превращает это в **сумму**: `log(a × b) = log a + log b` — численно гораздо устойчивее.

```python
import math
probs = [0.1] * 100
product = 1.0
for p in probs:
    product *= p
print(product)                              # 1e-100; ещё чуть меньше — и станет 0.0
print(sum(math.log(p) for p in probs))      # -230.26: с логарифмами всё в порядке
```

**② Измеряет удивление.** `−log p` — **количество информации**, или **удивлённость** (surprisal), события:

| вероятность p | −log p | интуиция |
|---------------|--------|----------|
| 1.0 | 0 | ожидаемо, никакого удивления |
| 0.5 | 0.69 | подброшенная монета |
| 0.1 | 2.30 | немного неожиданно |
| 0.01 | 4.61 | очень неожиданно |
| 0.0001 | 9.21 | ошеломительно |

## 6.4 Перекрёстная энтропия: оценка предсказания

При обучении мы знаем **правильный следующий токен**. Чем большую вероятность модель ему дала, тем лучше предсказание. **Функция потерь перекрёстной энтропии** (cross-entropy loss) — это просто **удивлённость правильным ответом**:

```formula
loss = −log p(правильный токен)
```

```python
import math

def cross_entropy(probs, target):
    return -math.log(probs[target])

probs = [0.7, 0.2, 0.1]          # предсказание модели для трёх кандидатов
print(round(cross_entropy(probs, 0), 4))    # правильный — №0: 0.3567 (хорошее предсказание)
print(round(cross_entropy(probs, 2), 4))    # правильный — №2: 2.3026 (плохое предсказание)
```

- вероятность 1 у правильного ответа → потери 0 (идеально);
- вероятность около 0 → потери стремятся к бесконечности (сильная ошибка).

Чтобы обучать языковую модель, перекрёстную энтропию **усредняют** по **всем позициям** текста — это потери на пакете данных. Градиентный спуск (урок 5) всё время подстраивает параметры, чтобы уменьшить это среднее, **то есть дать правильному следующему слову большую вероятность**.

> [!IMPORTANT]
> Вот и вся цель предобучения LLM: **минимизировать среднюю перекрёстную энтропию следующего токена**. Миллиарды параметров, тысячи GPU, месяцы обучения — всё ради оптимизации одного числа.

Полезный ориентир: при словаре из `V` токенов модель, ничему не научившаяся и считающая все токены равновероятными, даёт каждому вероятность `1/V`, а её потери равны `log V`. В словаре GPT-2 около 50 000 токенов, `log 50257 ≈ 10.8` — примерно такие потери в самом начале обучения.

## 6.5 Перплексия: между сколькими вариантами колеблется модель

Перекрёстная энтропия не очень наглядна. Возведите e в степень средней перекрёстной энтропии — получится **перплексия** (perplexity):

```formula
perplexity = e^(средняя перекрёстная энтропия)
```

Интуиция: **между сколькими вариантами в среднем колеблется модель**. Перплексия 1 — всегда уверена (и права); 50 — будто угадывает среди 50 слов.

```python
import math

def perplexity(target_probs):
    """target_probs: вероятность, данная правильному токену в каждой позиции"""
    avg_ce = sum(-math.log(p) for p in target_probs) / len(target_probs)
    return math.exp(avg_ce)

print(round(perplexity([0.25, 0.25, 0.25, 0.25]), 2))    # 4.0: как угадывание из 4
print(round(perplexity([0.9, 0.8, 0.95, 0.7]), 2))       # около 1.2: очень уверенно
```

## 6.6 Энтропия (полезно знать)

Неопределённость самого распределения — его **энтропия**: `H = −Σ pᵢ log pᵢ`, «средняя удивлённость». У равномерного распределения энтропия наибольшая, у распределения с одним достоверным исходом — нулевая. *Перекрёстной* энтропия называется потому, что измеряет среднюю удивлённость **реальными данными** с помощью **распределения модели**.

## 6.7 Итоги

- **Распределение вероятностей** перечисляет вероятности всех исходов, сумма 1; `random.choices` выбирает по нему.
- **Softmax** `e^z / Σ e^z` превращает любые логиты в вероятности; сначала вычитайте максимум, чтобы избежать переполнения.
- **Температура**: деление логитов на T; малая T — увереннее, большая — случайнее.
- **log** превращает произведения в суммы и спасает от исчезновения порядка; `−log p` — удивлённость.
- **Перекрёстная энтропия** = `−log p(правильный)`; обучение LM минимизирует её среднее по всем позициям.
- **Перплексия** = `e^(средняя перекрёстная энтропия)` — между сколькими вариантами колеблется модель; угадывание из V даёт V.
