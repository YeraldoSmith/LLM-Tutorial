# 7. Декодирование: как модель выбирает следующее слово

> 🎯 **Цели урока**: понять, что модель выдаёт лишь «вероятность следующего токена», а **как выбирать** — отдельный шаг (декодирование); увидеть, почему жадное декодирование однообразно и повторяется; освоить сэмплирование с **температурой**, **top-k**, **top-p**, **min-p** и **штрафы за повторы**; узнать о лучевом поиске, условиях остановки и **ограниченном декодировании** (структурированный вывод); понять, как задавать эти параметры при работе с API LLM.
>
> ⏱ **Время**: 60 минут　|　📋 **Что нужно знать**: уроки 1 и 6 этой части

Обученная языковая модель на каждом шаге выдаёт лишь **распределение вероятностей**: 63% — что следующий токен «хорошая», 14% — что «жаркая»… Чтобы на самом деле сгенерировать текст, нужно решить, **какой выбрать**. Этот шаг называется **декодированием** (decoding) или **сэмплированием** (sampling). Одна и та же модель при разном декодировании даёт ответы совершенно разного стиля, качества и разнообразия. Параметры вроде `temperature` и `top_p` в API LLM управляют именно этим шагом.

## 7.1 Жадное декодирование: всегда самое вероятное

Простейший способ — на каждом шаге брать токен с **наибольшей вероятностью** (так делал GPT для сложения из прошлого урока). Это детерминировано и воспроизводимо и хорошо подходит для задач с «единственным правильным ответом» (арифметика, классификация, извлечение информации). Но для написания текстов проблемы очевидны:

- **скучно**: всегда выбирается самая частая формулировка, никакого разнообразия;
- **повторы**: попав в цикл, модель из него не выходит.

Возьмём маленькую «словесную» модель, заданную вручную. После `cat` самое вероятное слово — `the`, а после `the` — `cat`…

```python
# «словесная» модель, заданная вручную: логиты слов, которые могут идти после каждого слова
LM = {
    "<s>": {"the": 2.0, "a": 1.0},
    "the": {"cat": 2.0, "dog": 1.5, "mat": 0.5},
    "a":   {"cat": 1.0, "dog": 1.0},
    "cat": {"the": 1.6, "sat": 1.4, ".": 0.5},
    "dog": {"the": 1.6, "ran": 1.2, ".": 0.5},
    "sat": {"on": 2.0, ".": 0.5},
    "ran": {"away": 2.0, ".": 0.5},
    "on":  {"the": 2.0, "a": 1.0},
    "away": {".": 2.0},
    "mat": {".": 2.0, "the": 0.5},
}

def greedy(penalty=1.0, max_len=12):
    out, cur = [], "<s>"
    while len(out) < max_len:
        scores = dict(LM[cur])
        for w in set(out):                        # штраф за повторы: уже встречавшиеся слова получают скидку
            if w in scores:
                scores[w] = scores[w] / penalty if scores[w] > 0 else scores[w] * penalty
        cur = max(scores, key=scores.get)
        out.append(cur)
        if cur == ".":
            break
    return " ".join(out)

print("жадно:                ", greedy())
print("штраф за повторы 1.5: ", greedy(penalty=1.5))
```

Жадное декодирование застревает в `the cat the cat …` до предела длины. **Штраф за повторы** (repetition penalty) уменьшает оценки уже встречавшихся слов и разрывает цикл. (Слишком сильный штраф тоже плох: модель вынуждена избегать слов, которые и должны повторяться, вроде предлогов.)

## 7.2 Температура: насколько «смело» выбирать

Для разнообразия будем **тянуть случайно** согласно вероятностям (сэмплирование). **Температура** (temperature, T) делит логиты на T перед softmax:

```formula
P(токен i) = softmax(zᵢ / T)
```

```python
import math

def softmax(z, T=1.0):
    z = [v / T for v in z]
    m = max(z)
    e = [math.exp(v - m) for v in z]
    s = sum(e)
    return [v / s for v in e]

words = ["хорошая", "жаркая", "холодная", "прекрасная", "ужасная", "фиолетовая"]
logits = [3.0, 1.5, 1.2, 1.0, 0.2, -2.0]          # оценки модели для «Сегодня погода очень ___»

for T in (0.2, 0.7, 1.0, 1.5):
    probs = softmax(logits, T)
    print(f"T={T:<4}", "  ".join(f"{w}:{p:5.1%}" for w, p in zip(words, probs)))
```

- **T < 1**: распределение становится «острее», вероятное — ещё вероятнее: осторожнее и стабильнее. При T → 0 получается жадное декодирование.
- **T = 1**: исходное распределение модели.
- **T > 1**: распределение «площе», маловероятные варианты (даже «фиолетовая») получают больше шансов — креативнее, но и чаще бессмыслица.

Почувствуем это на биграммной модели имён из урока 1:

```python
import math
import random

NAMES = """emma olivia ava isabella sophia mia charlotte amelia harper evelyn abigail emily
elizabeth sofia avery ella madison scarlett victoria aria grace chloe camila penelope riley
layla lillian nora zoey mila aubrey hannah lily addison eleanor natalie luna savannah leah
stella hazel ellie audrey violet claire bella aurora lucy anna samantha caroline sarah maya
liam noah william james oliver benjamin elijah lucas mason logan alexander ethan jacob
michael daniel henry jackson sebastian aiden matthew samuel david joseph carter owen wyatt
john jack luke dylan levi isaac gabriel julian mateo anthony lincoln joshua andrew caleb
ryan nathan thomas leo isaiah charles hudson hunter connor eli ezra aaron adrian nolan""".split()

chars = list(".abcdefghijklmnopqrstuvwxyz")
counts = {a: {b: 0.1 for b in chars} for a in chars}      # биграммная модель из урока 1 (со сглаживанием)
for name in NAMES:
    seq = ["."] + list(name) + ["."]
    for a, b in zip(seq, seq[1:]):
        counts[a][b] += 1
logits = {a: [math.log(counts[a][b]) for b in chars] for a in chars}   # превращаем вероятности обратно в «логиты»

def generate(T=1.0, top_k=None, greedy=False, max_len=15):
    out, cur = "", "."
    while len(out) < max_len:
        z = logits[cur]
        if greedy:
            cur = chars[max(range(len(z)), key=lambda i: z[i])]
        else:
            z = [v / T for v in z]                         # температура
            if top_k:                                      # top-k: тянем только из k самых вероятных
                kth = sorted(z, reverse=True)[top_k - 1]
                z = [v if v >= kth else float("-inf") for v in z]
            m = max(z)
            w = [math.exp(v - m) for v in z]
            cur = random.choices(chars, weights=w)[0]
        if cur == ".":
            break
        out += cur
    return out

random.seed(0)
print("жадно             ", [generate(greedy=True) for _ in range(5)])
for T in (0.5, 1.0, 1.5):
    print(f"температура {T:<4}  ", [generate(T=T) for _ in range(5)])
print("темп. 1 + top-5   ", [generate(T=1.0, top_k=5) for _ in range(5)])
```

Жадный способ каждый раз выдаёт одно и то же имя `a` (самая частая первая буква — `a`, а после `a` чаще всего идёт конец); при низкой температуре имена короткие и осторожные, при высокой превращаются в длинную бессмыслицу; top-k заметно уменьшает бессмыслицу.

## 7.3 Отрезаем «длинный хвост»: top-k, top-p, min-p

Даже хорошая модель даёт десяткам тысяч токенов маленькие, но ненулевые вероятности. При сэмплировании странные слова из этого «длинного хвоста» в сумме имеют заметный шанс выпасть — а если выпадет одно, всё дальнейшее может пойти вкривь. Поэтому перед сэмплированием обычно **оставляют лишь часть кандидатов**:

- **top-k**: только k самых вероятных токенов;
- **top-p** (nucleus sampling, «ядерное» сэмплирование): складываем вероятности, начиная с самого вероятного, и оставляем наименьший набор, **сумма которого достигает p**. Когда модель уверена, остаются один-два токена; когда сомневается — много. Гибче, чем фиксированное k;
- **min-p** (более новый способ): оставляем только токены с вероятностью **не меньше «максимальная вероятность × min_p»**.

Оставшихся кандидатов перенормируют (чтобы сумма была 1) и затем сэмплируют:

```python
import math

def softmax(z):
    m = max(z)
    e = [math.exp(v - m) for v in z]
    return [v / sum(e) for v in e]

def top_k(probs, k):
    keep = sorted(range(len(probs)), key=lambda i: -probs[i])[:k]
    total = sum(probs[i] for i in keep)
    return [probs[i] / total if i in keep else 0.0 for i in range(len(probs))]

def top_p(probs, p):
    order = sorted(range(len(probs)), key=lambda i: -probs[i])
    keep, cum = [], 0.0
    for i in order:                      # складываем с самого вероятного, пока сумма не достигнет p
        keep.append(i)
        cum += probs[i]
        if cum >= p:
            break
    total = sum(probs[i] for i in keep)
    return [probs[i] / total if i in keep else 0.0 for i in range(len(probs))]

def min_p(probs, ratio):
    limit = ratio * max(probs)           # оставляем токены с вероятностью ≥ максимальная × ratio
    total = sum(q for q in probs if q >= limit)
    return [q / total if q >= limit else 0.0 for q in probs]

words = ["хорошая", "жаркая", "холодная", "прекрасная", "ужасная", "фиолетовая"]
probs = softmax([3.0, 1.5, 1.2, 1.0, 0.2, -2.0])
show = lambda ps: "  ".join(f"{w}:{q:5.1%}" for w, q in zip(words, ps) if q > 0)
print("исходно  ", show(probs))
print("top-k=3  ", show(top_k(probs, 3)))
print("top-p=0.9", show(top_p(probs, 0.9)))
print("min-p=0.1", show(min_p(probs, 0.1)))
```

На практике **температуру обычно сочетают с top-p (или top-k, или min-p)**: сначала температурой меняем распределение, затем отрезаем хвост и только потом сэмплируем.

## 7.4 Штрафы за повторы: repetition, frequency и presence

В разделе 7.1 мы видели **штраф за повторы**. В API, например OpenAI, есть ещё два похожих параметра:

| Параметр | Как работает | Эффект |
|----------|--------------|--------|
| `frequency_penalty` | из логита токена вычитается «число появлений × штраф» | чем чаще токен встречался, тем меньше его хочется; меньше многословных повторов |
| `presence_penalty` | если токен хоть раз встречался, вычитается фиксированная величина | поощряет новые темы |
| `repetition_penalty` (Hugging Face, vLLM и др.) | у встречавшихся токенов положительные логиты делятся на штраф, отрицательные умножаются | разрывает циклы |

Обычно эти параметры оставляют по умолчанию (0 или 1.0) и немного увеличивают, только если видны явные повторы.

## 7.5 Лучевой поиск

Жадный способ смотрит только на лучший выбор прямо сейчас, но «лучшее на каждом шаге» — не то же самое, что «лучшее предложение целиком». **Лучевой поиск** (beam search) на каждом шаге хранит **b** последовательностей-кандидатов с наибольшей общей вероятностью (b — ширина луча) и в конце выбирает самую вероятную в целом:

```text
ширина луча b = 2
шаг 1: the (0.7)         a (0.3)
шаг 2: the cat (0.42)    the dog (0.21)     ← из всех продолжений оставляем лучшие 2
шаг 3: the cat sat (…)   the dog ran (…)
…
```

Лучевой поиск широко применяется в задачах с довольно определённым ответом — **машинный перевод, распознавание речи**. В свободном письме и диалоге он даёт пресный, повторяющийся текст, поэтому чат-боты почти всегда используют **сэмплирование**.

## 7.6 Когда остановиться?

Генерация продолжается, пока не выполнится **условие остановки**:

- сгенерирован **токен конца** (например, `<|endoftext|>` или `<|im_end|>` — специальные токены из урока 2): модель сама «решила», что закончила;
- достигнута **максимальная длина** (`max_tokens` / `max_output_tokens` в API);
- появилась заданная вами **стоп-последовательность** (параметр `stop`), например остановиться на `"\n\n"`.

> [!WARNING]
> Если `max_tokens` слишком мал, ответ обрежется на полуслове. Рассуждающие модели (часть 5) перед ответом генерируют длинные «размышления», и они тоже считаются в бюджет токенов — дайте им достаточно места.

## 7.7 Ограниченное декодирование: гарантируем формат

Многим приложениям нужен вывод в **строгом формате**: корректный JSON, только «да / нет», число. **Ограниченное декодирование** (constrained decoding) перед каждым шагом сэмплирования задаёт **логитам токенов, нарушающих формат, значение −∞**, и модель просто не может выдать некорректный результат:

```python
import math

vocab = ["1", "2", "3", "семь", "abc", ".", "<end>"]
logits = [1.0, 0.5, 0.2, 2.5, 1.8, 0.3, 0.1]       # модели больше всего хочется сказать «семь», а нам нужны цифры

allowed = {"1", "2", "3", "<end>"}                   # правило формата: только цифры и конец
masked = [z if tok in allowed else float("-inf") for tok, z in zip(vocab, logits)]
m = max(masked)
e = [math.exp(z - m) for z in masked]
probs = [v / sum(e) for v in e]
for tok, p in zip(vocab, probs):
    print(f"{tok:6s}{p:6.1%}")
```

Настоящие системы по JSON Schema или грамматике вычисляют, какие токены разрешены на каждом шаге. Функции «структурированного вывода» в API OpenAI, Anthropic и других и грамматические ограничения в движках инференса вроде vLLM и llama.cpp работают на этом принципе. Мы снова воспользуемся этим при вызове инструментов в части 7.

## 7.8 Практические советы

| Задача | Рекомендация |
|--------|--------------|
| код, математика, извлечение данных, классификация | низкая температура (0–0.3) или просто жадно |
| обычные вопросы и диалог | температура около 0.7, top-p 0.9–0.95 |
| рассказы и мозговой штурм | температура 0.8–1.2 |
| рассуждающие модели | **следуйте официальным рекомендациям**: например, для DeepSeek-R1 рекомендуют температуру 0.5–0.7 (лучше 0.6); в API некоторых рассуждающих моделей температуру вообще нельзя менять |

> [!NOTE]
> **Температура 0 не всегда даёт полностью воспроизводимый результат**: порядок операций с плавающей точкой на GPU и объединение запросов в батчи на сервере дают крошечные различия, а стоит одному токену отличиться — всё дальнейшее может измениться. Если нужна воспроизводимость, зафиксируйте зерно (`seed`, если API его поддерживает) и запишите версию модели.

## 7.9 Итоги

- Модель даёт лишь **распределение вероятностей** следующего токена; **декодирование** решает, какой выбрать, поэтому ответы одной модели могут сильно различаться по качеству.
- **Жадное**: детерминировано, подходит для задач с одним ответом, но скучно и повторяется. **Сэмплирование**: случайный выбор по вероятностям — разнообразно, но может нести чушь.
- **Температура** T делит логиты; T < 1 — осторожнее (T → 0 — жадное), T > 1 — смелее.
- **top-k / top-p / min-p** сэмплируют только среди вероятных кандидатов, отрезая «длинный хвост»; обычно в сочетании с температурой.
- **Штрафы за повторы, частоту и присутствие** уменьшают повторы; **лучевой поиск** подходит для перевода и подобных задач; **условия остановки** — токен конца, максимальная длина и стоп-последовательности.
- **Ограниченное декодирование** запрещает токены, нарушающие формат, и гарантирует корректный вывод (структурированный вывод, JSON).

Деление логитов на крошечное T многократно увеличивает разрыв между максимумом и остальными, и softmax отдаёт почти всю вероятность самому большому — это и есть жадный способ. Только очень высокая температура приближает распределение к равномерному.
