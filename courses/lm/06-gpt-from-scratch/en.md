# 6. Train a GPT yourself

> The code structure follows Andrej Karpathy's [nanoGPT](https://github.com/karpathy/nanoGPT) and [minGPT](https://github.com/karpathy/minGPT) (MIT licence; minGPT also has an addition example). After this lesson, read nanoGPT's `model.py` — you'll understand nearly every line.

## 6.1 The task: teach GPT to add

Why addition rather than novels or web pages straight away?

- **No data to download**: the problems are generated by code, so anyone, in any language, can run it directly;
- **We can test whether it "really learned" or "memorised"**: two-digit addition has 100 × 100 = 10,000 problems; we **hold out 1,000** that the model never sees and test it on them after training;
- **It is language modelling**: each problem is written as a string of characters, such as `37+48=580`, and the model just "predicts the next character" — exactly like GPT predicting the next token.

You may have noticed: 37 + 48 = 85, yet we wrote `580`. That's a small trick: **pad the answer to 3 digits and write it backwards** (`085` → `580`). We add starting from the ones digit and carry towards the higher digits, but the model generates from left to right, one character at a time. Written backwards, the model produces the ones digit first, then the tens and hundreds — the same order as column addition by hand — which makes learning much easier.

## 6.2 Training data: shift by one, every position predicts

Training examples for a language model are built very simply: **the input is a piece of text and the target is the same text shifted one position to the left**.

```text
full sequence:  3   7   +   4   8   =   5   8   0
input x:        3   7   +   4   8   =   5   8
target y:       7   +   4   8   =   5   8   0
                ↑ seeing "3" predict "7"; seeing "37" predict "+"; … seeing "37+48=58" predict "0"
```

Because of the causal mask, position t can only see the first t characters, so **one forward pass trains the prediction at every position at once** — a sequence of length T provides T training signals. This is one reason Transformers train so efficiently (an RNN has to go step by step).

In this task the problem itself (two random numbers) can't be predicted; we only want the model to learn **to produce the answer from the problem**. So we set the targets of the problem part to `-1` and tell the loss function `ignore_index=-1`, which leaves those positions out of the loss. (Fine-tuning chat models works the same way: the loss is computed only on the "assistant's answer" — part 5.)

## 6.3 The complete code

Here is all the code: data, model, training and evaluation. You have seen every part of the model in earlier lessons: token + position embeddings (lesson 3), multi-head causal self-attention (lesson 4), Blocks with residuals (lesson 5), weight tying (lesson 3), AdamW (part 2 lesson 6).

```python requires=torch timeout=300
import random
import time
import torch
from torch import nn
import torch.nn.functional as F

# ---------------- 1. Data: two-digit addition, e.g. "37+48=" followed by the answer 85 (padded to 3 digits and reversed: "580")
random.seed(0)
torch.manual_seed(0)
pairs = [(a, b) for a in range(100) for b in range(100)]
random.shuffle(pairs)
test_pairs, train_pairs = pairs[:1000], pairs[1000:]       # 1000 problems held out for testing, never seen in training

def to_text(a, b):
    return f"{a:02d}+{b:02d}={str(a + b).zfill(3)[::-1]}"    # pad the result to 3 digits and reverse it: "085" → "580"

chars = list("0123456789+=")                               # the vocabulary has only 12 characters
stoi = {c: i for i, c in enumerate(chars)}
def encode(s):
    return [stoi[c] for c in s]

block_size = 9                                             # "37+48=580" is exactly 9 characters
def get_batch(batch_size=128):
    batch = random.sample(train_pairs, batch_size)
    data = torch.tensor([encode(to_text(a, b)) for a, b in batch])
    x, y = data[:, :-1], data[:, 1:].clone()               # y is x shifted by one: every position predicts the next character
    y[:, :5] = -1                                          # no loss on the problem; learn only the answer after "="
    return x, y

# ---------------- 2. The model: a mini GPT
class CausalSelfAttention(nn.Module):
    def __init__(self, d, n_heads):
        super().__init__()
        self.h = n_heads
        self.qkv = nn.Linear(d, 3 * d)
        self.proj = nn.Linear(d, d)
    def forward(self, x):
        B, T, C = x.shape
        q, k, v = self.qkv(x).split(C, dim=2)
        q, k, v = (t.view(B, T, self.h, C // self.h).transpose(1, 2) for t in (q, k, v))
        y = F.scaled_dot_product_attention(q, k, v, is_causal=True)
        return self.proj(y.transpose(1, 2).reshape(B, T, C))

class Block(nn.Module):
    def __init__(self, d, n_heads):
        super().__init__()
        self.ln1, self.ln2 = nn.LayerNorm(d), nn.LayerNorm(d)
        self.attn = CausalSelfAttention(d, n_heads)
        self.mlp = nn.Sequential(nn.Linear(d, 4 * d), nn.GELU(), nn.Linear(4 * d, d))
    def forward(self, x):
        x = x + self.attn(self.ln1(x))
        return x + self.mlp(self.ln2(x))

class GPT(nn.Module):
    def __init__(self, vocab, block_size, d=64, n_layer=2, n_heads=4):
        super().__init__()
        self.tok = nn.Embedding(vocab, d)                  # token embedding
        self.pos = nn.Embedding(block_size, d)             # position embedding
        self.blocks = nn.Sequential(*[Block(d, n_heads) for _ in range(n_layer)])
        self.ln = nn.LayerNorm(d)
        self.head = nn.Linear(d, vocab, bias=False)
        self.head.weight = self.tok.weight                 # weight tying: the output layer shares the embedding matrix
    def forward(self, idx, targets=None):
        T = idx.shape[1]
        x = self.tok(idx) + self.pos(torch.arange(T))
        logits = self.head(self.ln(self.blocks(x)))        # (B, T, vocab)
        if targets is None:
            return logits
        loss = F.cross_entropy(logits.reshape(-1, logits.shape[-1]), targets.reshape(-1), ignore_index=-1)
        return logits, loss

    @torch.no_grad()
    def generate(self, idx, n_new):                        # greedy generation: always take the most likely token
        for _ in range(n_new):
            logits = self(idx[:, -block_size:])
            nxt = logits[:, -1].argmax(dim=-1, keepdim=True)
            idx = torch.cat([idx, nxt], dim=1)
        return idx

model = GPT(len(chars), block_size)
print(f"parameters: {sum(p.numel() for p in model.parameters()):,}")

def accuracy(pairs):
    model.eval()
    prompts = torch.tensor([encode(f"{a:02d}+{b:02d}=") for a, b in pairs])
    out = model.generate(prompts, 3)[:, 6:]                # generate the 3-character (reversed) answer
    model.train()
    right = 0
    for (a, b), row in zip(pairs, out.tolist()):
        answer = int("".join(chars[i] for i in row)[::-1])
        right += answer == a + b
    return right / len(pairs)

# ---------------- 3. Training
optimizer = torch.optim.AdamW(model.parameters(), lr=5e-3, weight_decay=0.1)
start = time.time()
for step in range(1, 1001):
    x, y = get_batch()
    _, loss = model(x, y)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    if step % 200 == 0:
        print(f"step {step:4d}  loss {loss.item():.3f}  test accuracy {accuracy(test_pairs):.1%}  ({time.time() - start:.0f}s)")

print("a few problems the model has never seen:")
for a, b in test_pairs[:6]:
    out = model.generate(torch.tensor([encode(f"{a:02d}+{b:02d}=")]), 3)[0, 6:].tolist()
    reply = int("".join(chars[i] for i in out)[::-1])
    print(f"  {a:2d} + {b:2d} = {reply:3d}   {'✓' if reply == a + b else '✗ (correct answer ' + str(a + b) + ')'}")
```

On an ordinary laptop CPU this takes about 10–30 seconds.

## 6.4 Reading the results

You'll see output like this (the exact numbers vary slightly between computers):

```text
parameters: 101,440
step  200  loss 1.515  test accuracy 2.7%
step  400  loss 0.287  test accuracy 66.4%
step  600  loss 0.072  test accuracy 98.2%
step  800  loss 0.097  test accuracy 93.4%
step 1000  loss 0.002  test accuracy 100.0%
```

- **At first it knows nothing**: accuracy is a few percent, about as good as guessing.
- **Then it suddenly "gets it"**: within a few hundred steps accuracy jumps from single digits to over 90%. Neural networks often learn rules in sudden jumps like this.
- **The test problems are all right too**: the model has **never seen** these 1,000 problems, so it didn't memorise "37+48 is 85" — it learned **the rules of addition and carrying**.
- The occasional dip in between (93% at step 800, say) is normal training noise.

A model with only 100,000 parameters learned addition in under a minute just by "predicting the next character". Scale the same method up a million times and you get today's large language models.

> [!TIP]
> Try it yourself: change `n_layer` to 1 or `d` to 32, or drop the "write it backwards" trick (remove the `[::-1]`, and the reversal in `accuracy` too), and see how accuracy and learning speed change. This is the kind of **ablation study** researchers run every day.

## 6.5 Training on your own text

The same model with different data can learn text in any language. Below is a training script for a **character-level** language model: prepare a text file `input.txt` (any language — a novel, a poetry collection…) and it will learn the style of the writing and then "continue" it. Compared with addition, the main changes are: the vocabulary comes from the text itself, training examples are random slices of the text, and generation **samples** by probability rather than always taking the maximum (sampling is next lesson's topic).

```python norun
# first prepare input.txt (ideally at least a few hundred thousand characters; more text works better),
# and copy the Block and GPT classes from section 6.3 here
import torch

text = open("input.txt", encoding="utf-8").read()
chars = sorted(set(text))                            # every character in the text forms the vocabulary
stoi = {c: i for i, c in enumerate(chars)}
data = torch.tensor([stoi[c] for c in text])
n = int(0.9 * len(data))
train_data, val_data = data[:n], data[n:]            # the last 10% is a validation set to watch for overfitting

block_size, batch_size = 128, 32
def get_batch(split):
    d = train_data if split == "train" else val_data
    ix = torch.randint(len(d) - block_size - 1, (batch_size,))
    x = torch.stack([d[i:i + block_size] for i in ix])
    y = torch.stack([d[i + 1:i + block_size + 1] for i in ix])       # shifted by one again; this time every position counts
    return x, y

device = "cuda" if torch.cuda.is_available() else "mps" if torch.backends.mps.is_available() else "cpu"
model = GPT(len(chars), block_size, d=256, n_layer=6, n_heads=8).to(device)
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3)
for step in range(5000):
    x, y = get_batch("train")
    _, loss = model(x.to(device), y.to(device))
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    if step % 500 == 0:
        print(step, loss.item())

# generation: start from a prompt and sample the next character by probability
idx = torch.tensor([[stoi[c] for c in "Once"]], device=device)    # the prompt's characters must appear in input.txt
for _ in range(200):
    logits = model(idx[:, -block_size:])[:, -1] / 0.8   # 0.8 is the "temperature": lower is more conservative (next lesson)
    nxt = torch.multinomial(torch.softmax(logits, dim=-1), 1)
    idx = torch.cat([idx, nxt], dim=1)
print("".join(chars[i] for i in idx[0].tolist()))
```

> [!NOTE]
> Character-level models are the best place to start: no tokenizer needed, and they are especially intuitive for languages like Chinese (one character = one token). Languages with large character sets need more data and more training steps. A free cloud GPU such as Google Colab makes this much faster (part 1 lesson 2). The classic English practice dataset is Karpathy's [tinyshakespeare](https://raw.githubusercontent.com/karpathy/char-rnn/master/data/tinyshakespeare/input.txt) (about 1 MB of Shakespeare's plays).

## 6.6 From mini GPT to a real large model

Our model and real large models have **no fundamental difference in structure**. The differences are scale and engineering:

| | This lesson's addition GPT | GPT-2 small (2019) | GPT-3 (2020) | Today's frontier models |
|---|---|---|---|---|
| parameters | 100 thousand | 124 million | 175 billion | hundreds of billions to trillions (often MoE) |
| layers × dimension | 2 × 64 | 12 × 768 | 96 × 12288 | tens to a hundred-plus layers × thousands |
| vocabulary | 12 characters | 50k (BPE) | 50k (BPE) | 100k–250k |
| context | 9 | 1024 | 2048 | 128k to millions |
| training data | 9,000 addition problems | about 10 billion tokens | about 300 billion tokens | tens of trillions of tokens |
| training hardware | a laptop CPU, tens of seconds | dozens of GPUs | thousands of GPUs | tens of thousands to 100k GPUs, for months |

Getting from here to there takes **better data** (large-scale cleaning, deduplication, mixing), **more compute and distributed training** (splitting models and data across thousands of GPUs), **scaling laws** (working out in advance how much data a given model size deserves) and the training tricks of the previous part. That's part 4.

And a pre-trained model can only "continue text"; it doesn't yet "follow instructions and answer properly". Turning it into a useful, safe assistant also requires **fine-tuning and alignment** (part 5).

## 6.7 Summary

- A complete GPT = token embedding + position embedding → several Blocks (attention + MLP + residuals + normalization) → normalization → output layer; about 100 lines of PyTorch.
- Training data: **target = input shifted by one**; the causal mask lets one forward pass train every position in the sequence; positions we don't want to learn are excluded with `ignore_index`.
- Only a held-out **test set** can tell whether the model learned the rule or memorised answers; "data representation" tricks such as writing the answer backwards hugely affect how hard learning is.
- The same code trained on any text gives a character-level language model; generation samples by probability.
- A mini GPT and a real large model have the same structure; the differences are data, scale, compute and engineering — plus the fine-tuning and alignment that come afterwards.
