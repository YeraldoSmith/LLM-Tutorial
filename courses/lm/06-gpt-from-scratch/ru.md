## 6.1 Задача: научить GPT складывать

Почему сложение, а не сразу романы или веб-страницы?

- **Ничего не нужно скачивать**: задачи генерирует код, так что запустить его может кто угодно, на каком угодно языке;
- **Можно проверить, «научилась» модель или «зазубрила»**: двузначных сложений всего 100 × 100 = 10 000; мы **отложим 1000** задач, которых модель не увидит, и проверим её на них после обучения;
- **Это и есть языковое моделирование**: каждая задача записывается строкой символов, например `37+48=580`, и модель просто «предсказывает следующий символ» — ровно как GPT предсказывает следующий токен.

Вы могли заметить: 37 + 48 = 85, а мы написали `580`. Это небольшой приём: **дополняем ответ до 3 цифр и пишем его задом наперёд** (`085` → `580`). Мы складываем, начиная с единиц и перенося в старшие разряды, а модель генерирует слева направо по одному символу. Если писать ответ задом наперёд, модель сначала выдаёт единицы, затем десятки и сотни — в том же порядке, что и при сложении столбиком, — и учиться гораздо проще.

## 6.2 Обучающие данные: сдвиг на один, предсказывает каждая позиция

Обучающие примеры для языковой модели строятся очень просто: **вход — кусок текста, цель — тот же текст, сдвинутый на одну позицию влево**.

```text
полная строка:  3   7   +   4   8   =   5   8   0
вход x:         3   7   +   4   8   =   5   8
цель y:         7   +   4   8   =   5   8   0
                ↑ видим «3» — предсказываем «7»; видим «37» — «+»; … видим «37+48=58» — «0»
```

Благодаря причинной маске позиция t видит только первые t символов, поэтому **один прямой проход обучает предсказание сразу на всех позициях** — последовательность длины T даёт T обучающих сигналов. Это одна из причин, почему трансформеры учатся так эффективно (RNN приходится идти шаг за шагом).

В этой задаче саму задачу (два случайных числа) предсказать нельзя; мы хотим лишь, чтобы модель научилась **выдавать ответ по задаче**. Поэтому цели в части с задачей заменяем на `-1` и говорим функции потерь `ignore_index=-1` — эти позиции не учитываются в потерях. (Дообучение чат-моделей устроено так же: потери считаются только на «ответе ассистента» — часть 5.)

## 6.3 Полный код

Вот весь код: данные, модель, обучение и оценка. Каждую часть модели вы уже видели: эмбеддинги токенов и позиций (урок 3), многоголовое причинное самовнимание (урок 4), блоки с остаточными связями (урок 5), связывание весов (урок 3), AdamW (урок 6 части 2).

```python requires=torch timeout=300
import random
import time
import torch
from torch import nn
import torch.nn.functional as F

# ---------------- 1. Данные: сложение двузначных чисел, например "37+48=" и ответ 85 (до 3 цифр и задом наперёд: "580")
random.seed(0)
torch.manual_seed(0)
pairs = [(a, b) for a in range(100) for b in range(100)]
random.shuffle(pairs)
test_pairs, train_pairs = pairs[:1000], pairs[1000:]       # 1000 задач отложены для проверки, при обучении их не видно

def to_text(a, b):
    return f"{a:02d}+{b:02d}={str(a + b).zfill(3)[::-1]}"    # дополняем результат до 3 цифр и переворачиваем: "085" → "580"

chars = list("0123456789+=")                               # в словаре всего 12 символов
stoi = {c: i for i, c in enumerate(chars)}
def encode(s):
    return [stoi[c] for c in s]

block_size = 9                                             # "37+48=580" — ровно 9 символов
def get_batch(batch_size=128):
    batch = random.sample(train_pairs, batch_size)
    data = torch.tensor([encode(to_text(a, b)) for a, b in batch])
    x, y = data[:, :-1], data[:, 1:].clone()               # y — это x со сдвигом на один: каждая позиция предсказывает следующий символ
    y[:, :5] = -1                                          # на задаче потерь нет; учим только ответ после "="
    return x, y

# ---------------- 2. Модель: мини-GPT
class CausalSelfAttention(nn.Module):
    def __init__(self, d, n_heads):
        super().__init__()
        self.h = n_heads
        self.qkv = nn.Linear(d, 3 * d)
        self.proj = nn.Linear(d, d)
    def forward(self, x):
        B, T, C = x.shape
        q, k, v = self.qkv(x).split(C, dim=2)
        q, k, v = (t.view(B, T, self.h, C // self.h).transpose(1, 2) for t in (q, k, v))
        y = F.scaled_dot_product_attention(q, k, v, is_causal=True)
        return self.proj(y.transpose(1, 2).reshape(B, T, C))

class Block(nn.Module):
    def __init__(self, d, n_heads):
        super().__init__()
        self.ln1, self.ln2 = nn.LayerNorm(d), nn.LayerNorm(d)
        self.attn = CausalSelfAttention(d, n_heads)
        self.mlp = nn.Sequential(nn.Linear(d, 4 * d), nn.GELU(), nn.Linear(4 * d, d))
    def forward(self, x):
        x = x + self.attn(self.ln1(x))
        return x + self.mlp(self.ln2(x))

class GPT(nn.Module):
    def __init__(self, vocab, block_size, d=64, n_layer=2, n_heads=4):
        super().__init__()
        self.tok = nn.Embedding(vocab, d)                  # эмбеддинг токенов
        self.pos = nn.Embedding(block_size, d)             # позиционный эмбеддинг
        self.blocks = nn.Sequential(*[Block(d, n_heads) for _ in range(n_layer)])
        self.ln = nn.LayerNorm(d)
        self.head = nn.Linear(d, vocab, bias=False)
        self.head.weight = self.tok.weight                 # связывание весов: выходной слой делит матрицу с эмбеддингом
    def forward(self, idx, targets=None):
        T = idx.shape[1]
        x = self.tok(idx) + self.pos(torch.arange(T))
        logits = self.head(self.ln(self.blocks(x)))        # (B, T, vocab)
        if targets is None:
            return logits
        loss = F.cross_entropy(logits.reshape(-1, logits.shape[-1]), targets.reshape(-1), ignore_index=-1)
        return logits, loss

    @torch.no_grad()
    def generate(self, idx, n_new):                        # жадная генерация: всегда берём самый вероятный токен
        for _ in range(n_new):
            logits = self(idx[:, -block_size:])
            nxt = logits[:, -1].argmax(dim=-1, keepdim=True)
            idx = torch.cat([idx, nxt], dim=1)
        return idx

model = GPT(len(chars), block_size)
print(f"параметров: {sum(p.numel() for p in model.parameters()):,}")

def accuracy(pairs):
    model.eval()
    prompts = torch.tensor([encode(f"{a:02d}+{b:02d}=") for a, b in pairs])
    out = model.generate(prompts, 3)[:, 6:]                # генерируем 3-символьный (перевёрнутый) ответ
    model.train()
    right = 0
    for (a, b), row in zip(pairs, out.tolist()):
        answer = int("".join(chars[i] for i in row)[::-1])
        right += answer == a + b
    return right / len(pairs)

# ---------------- 3. Обучение
optimizer = torch.optim.AdamW(model.parameters(), lr=5e-3, weight_decay=0.1)
start = time.time()
for step in range(1, 1001):
    x, y = get_batch()
    _, loss = model(x, y)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    if step % 200 == 0:
        print(f"step {step:4d}  loss {loss.item():.3f}  точность на тесте {accuracy(test_pairs):.1%}  ({time.time() - start:.0f}s)")

print("несколько задач, которых модель никогда не видела:")
for a, b in test_pairs[:6]:
    out = model.generate(torch.tensor([encode(f"{a:02d}+{b:02d}=")]), 3)[0, 6:].tolist()
    reply = int("".join(chars[i] for i in out)[::-1])
    print(f"  {a:2d} + {b:2d} = {reply:3d}   {'✓' if reply == a + b else '✗ (правильный ответ ' + str(a + b) + ')'}")
```

На процессоре обычного ноутбука это занимает примерно 10–30 секунд.

Вы увидите примерно такой вывод (точные числа немного зависят от компьютера):

- **Сначала модель ничего не умеет**: точность — несколько процентов, почти как угадывание.
- **Потом она вдруг «понимает»**: за несколько сотен шагов точность подскакивает с единиц процентов до 90% с лишним. Нейросети часто выучивают правила такими скачками.
- **Тестовые задачи тоже решены верно**: эти 1000 задач модель **никогда не видела**, значит, она не зазубрила «37+48 — это 85», а выучила **правила сложения и переноса**.
- Случайные провалы посередине (скажем, 93% на шаге 800) — нормальный шум обучения.

Модель всего из 100 000 параметров меньше чем за минуту научилась складывать, просто «предсказывая следующий символ». Увеличьте тот же метод в миллион раз — и получатся современные большие языковые модели.

## 6.5 Обучаем на собственном тексте

Та же модель с другими данными выучит текст на любом языке. Ниже — скрипт обучения **символьной** языковой модели: подготовьте текстовый файл `input.txt` (на любом языке — роман, сборник стихов…), и модель выучит стиль текста, а затем будет его «продолжать». По сравнению со сложением главные отличия: словарь берётся из самого текста, обучающие примеры — случайные отрывки текста, а при генерации символы **сэмплируются** по вероятностям, а не всегда берётся максимальный (сэмплированию посвящён следующий урок).

```python norun
# сначала подготовьте input.txt (желательно хотя бы несколько сотен тысяч символов; чем больше, тем лучше)
# и скопируйте сюда классы Block и GPT из раздела 6.3
import torch

text = open("input.txt", encoding="utf-8").read()
chars = sorted(set(text))                            # все символы текста образуют словарь
stoi = {c: i for i, c in enumerate(chars)}
data = torch.tensor([stoi[c] for c in text])
n = int(0.9 * len(data))
train_data, val_data = data[:n], data[n:]            # последние 10% — валидационная выборка, следим за переобучением

block_size, batch_size = 128, 32
def get_batch(split):
    d = train_data if split == "train" else val_data
    ix = torch.randint(len(d) - block_size - 1, (batch_size,))
    x = torch.stack([d[i:i + block_size] for i in ix])
    y = torch.stack([d[i + 1:i + block_size + 1] for i in ix])       # снова сдвиг на один; теперь считается каждая позиция
    return x, y

device = "cuda" if torch.cuda.is_available() else "mps" if torch.backends.mps.is_available() else "cpu"
model = GPT(len(chars), block_size, d=256, n_layer=6, n_heads=8).to(device)
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3)
for step in range(5000):
    x, y = get_batch("train")
    _, loss = model(x.to(device), y.to(device))
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    if step % 500 == 0:
        print(step, loss.item())

# генерация: начинаем с затравки и сэмплируем следующий символ по вероятностям
idx = torch.tensor([[stoi[c] for c in "Жил"]], device=device)    # символы затравки должны встречаться в input.txt
for _ in range(200):
    logits = model(idx[:, -block_size:])[:, -1] / 0.8   # 0.8 — «температура»: чем ниже, тем осторожнее (следующий урок)
    nxt = torch.multinomial(torch.softmax(logits, dim=-1), 1)
    idx = torch.cat([idx, nxt], dim=1)
print("".join(chars[i] for i in idx[0].tolist()))
```

> [!NOTE]
> Символьные модели — лучший старт: не нужен токенизатор, и всё очень наглядно. Для русского языка словарь символов небольшой (около сотни с пунктуацией), так что символьная модель на хорошем романе быстро начинает писать «по-русски». Бесплатный облачный GPU вроде Google Colab сильно ускорит обучение (урок 2 части 1). Классический английский набор для практики — [tinyshakespeare](https://raw.githubusercontent.com/karpathy/char-rnn/master/data/tinyshakespeare/input.txt) от Карпатого (около 1 МБ пьес Шекспира).

## 6.6 От мини-GPT к настоящей большой модели

Наша модель и настоящие большие модели **принципиально не различаются по устройству**. Различия — в масштабе и инженерии:

| | GPT для сложения из урока | GPT-2 small (2019) | GPT-3 (2020) | Современные передовые модели |
|---|---|---|---|---|
| параметры | 100 тысяч | 124 млн | 175 млрд | от сотен миллиардов до триллионов (часто MoE) |
| слои × размерность | 2 × 64 | 12 × 768 | 96 × 12288 | от десятков до сотни с лишним слоёв × тысячи |
| словарь | 12 символов | 50 тыс. (BPE) | 50 тыс. (BPE) | 100–250 тыс. |
| контекст | 9 | 1024 | 2048 | от 128 тыс. до миллионов |
| обучающие данные | 9000 задач на сложение | около 10 млрд токенов | около 300 млрд токенов | десятки триллионов токенов |
| оборудование для обучения | процессор ноутбука, десятки секунд | десятки GPU | тысячи GPU | от десятков до сотни тысяч GPU, месяцы |

Чтобы дойти отсюда туда, нужны **лучшие данные** (масштабная чистка, дедупликация, смешивание), **больше вычислений и распределённое обучение** (модель и данные делятся между тысячами GPU), **законы масштабирования** (заранее рассчитать, сколько данных нужно модели данного размера) и приёмы обучения из предыдущей части. Это часть 4.

К тому же предобученная модель умеет только «продолжать текст», но ещё не «следует инструкциям и отвечает как следует». Чтобы превратить её в полезного и безопасного ассистента, нужны **дообучение и выравнивание** (часть 5).

## 6.7 Итоги

- Полный GPT = эмбеддинг токенов + позиционный эмбеддинг → несколько блоков (внимание + MLP + остаточные связи + нормализация) → нормализация → выходной слой; около 100 строк PyTorch.
- Обучающие данные: **цель = вход со сдвигом на один**; причинная маска позволяет одним прямым проходом обучать каждую позицию последовательности; ненужные позиции исключаются через `ignore_index`.
- Только отложенная **тестовая выборка** показывает, выучила ли модель правило или зазубрила ответы; приёмы «представления данных» вроде ответа задом наперёд сильно влияют на сложность обучения.
- Тот же код, обученный на любом тексте, даёт символьную языковую модель; генерация сэмплирует по вероятностям.
- У мини-GPT и настоящей большой модели одна структура; различаются данные, масштаб, вычисления и инженерия — плюс последующие дообучение и выравнивание.

### Задание 5: Зачем откладывать 1000 задач?

- чтобы обучение шло быстрее
- чтобы проверить, что модель выучила правила сложения, а не просто запомнила увиденные задачи
- потому что модель слишком мала, чтобы вместить все 10 000 задач
- чтобы потери стали ниже

<details>
<summary>Ответ и разбор</summary>

Проверка только на задачах из обучения не отличит «научилась» от «запомнила». Если модель верно решает задачи, которых никогда не видела, значит, она выучила обобщающееся правило — это и есть **обобщение**.
</details>
