## 1.1 Что такое языковая модель?

**Языковая модель** (language model) — это модель, которая присваивает тексту вероятность. Самая распространённая форма: по предыдущему тексту выдать **вероятность каждого возможного следующего токена**.

```text
вход:   «Сегодня погода очень»
выход:  хорошая 38%   жаркая 15%   холодная 11%   плохая 7%   … (вероятности всех токенов в сумме дают 1)
```

Подсказки клавиатуры в телефоне и автодополнение в поисковой строке — это маленькие языковые модели. Большие языковые модели (LLM) просто **намного больше** (от миллиардов до триллионов параметров), **видят намного дальше** (сотни тысяч токенов контекста) и обучены на огромных объёмах текста.

**Токен** — базовая единица текста для модели: символ, слово или часть слова. Как делится текст, разберём в следующем уроке. Чтобы не усложнять, в этом уроке **каждый отдельный символ — это токен**.

## 1.2 Оцениваем предложение: цепное правило вероятностей

Вероятность предложения раскладывается в произведение вероятностей «предсказания следующего токена» на каждом шаге:

```formula
P(w₁ w₂ … wₙ) = P(w₁) × P(w₂ | w₁) × P(w₃ | w₁ w₂) × … × P(wₙ | w₁ … wₙ₋₁)
```

`P(w₂ | w₁)` читается как «вероятность w₂ при условии w₁» (условная вероятность). Значит, **кто умеет предсказывать следующий токен, тот может оценить любой текст и генерировать текст по одному токену** — именно так и работает GPT.

```python
import math

# допустим, модель на каждом шаге фразы «я люблю тебя» дала такие вероятности
steps = [("я", 0.05), ("люблю", 0.10), ("тебя", 0.60)]
p = 1.0
for token, prob in steps:
    p *= prob
    print(f"P({token} | контекст) = {prob}")
print("вероятность фразы:", round(p, 6))
print("отрицательное логарифмическое правдоподобие (NLL):", round(-math.log(p), 3))   # меньше вероятность → больше NLL
```

Вероятность длинного предложения почти равна 0 (перемножается много чисел меньше 1), поэтому на практике всегда используют **логарифмы**: произведение вероятностей превращается в сумму логарифмов, а **отрицательное логарифмическое правдоподобие** (negative log-likelihood, NLL) служит функцией потерь — это та самая перекрёстная энтропия из части 2.

## 1.3 Простейшая языковая модель: смотрим только на предыдущий символ

Полная условная вероятность `P(wₙ | w₁ … wₙ₋₁)` слишком сложна. Простейшее приближение — **смотреть только на предыдущий токен**:

```formula
P(wₙ | w₁ … wₙ₋₁) ≈ P(wₙ | wₙ₋₁)
```

Это **биграммная** модель (bigram). Если смотреть на 2 предыдущих токена — триграммная, а в общем случае — **n-граммная модель**. N-граммы — классическая статистическая языковая модель; Клод Шеннон ещё в 1948 году генерировал с их помощью текст, «похожий на английский».

Обучим **символьную биграммную модель**, которая изучит, как выглядят английские имена, и сгенерирует новые. Данные — около сотни распространённых имён. К каждому имени добавим спереди и сзади особый символ `.`, обозначающий «начало» и «конец»: `emma` превращается в `.emma.`, где 5 пар соседних символов: `.e`, `em`, `mm`, `ma`, `a.`.

«Обучение» здесь — это просто **подсчёт**: считаем, как часто за каждым символом следует каждый другой, и делим на сумму, чтобы получить вероятности.

```python
import math
import random

NAMES = """emma olivia ava isabella sophia mia charlotte amelia harper evelyn abigail emily
elizabeth sofia avery ella madison scarlett victoria aria grace chloe camila penelope riley
layla lillian nora zoey mila aubrey hannah lily addison eleanor natalie luna savannah leah
stella hazel ellie audrey violet claire bella aurora lucy anna samantha caroline sarah maya
liam noah william james oliver benjamin elijah lucas mason logan alexander ethan jacob
michael daniel henry jackson sebastian aiden matthew samuel david joseph carter owen wyatt
john jack luke dylan levi isaac gabriel julian mateo anthony lincoln joshua andrew caleb
ryan nathan thomas leo isaiah charles hudson hunter connor eli ezra aaron adrian nolan""".split()

chars = list(".abcdefghijklmnopqrstuvwxyz")    # "." обозначает начало и конец имени
print(len(NAMES), "имён,", len(chars), "символов:", "".join(chars))

# 1. Считаем, как часто за каждым символом идёт каждый символ
counts = {a: {b: 0 for b in chars} for a in chars}
for name in NAMES:
    seq = ["."] + list(name) + ["."]
    for a, b in zip(seq, seq[1:]):
        counts[a][b] += 1

# 2. Превращаем в вероятности: P(b | a) = count(a, b) / count(a, любой); к каждому счёту прибавляем 0.1 (сглаживание)
probs = {}
for a in chars:
    total = sum(counts[a][b] + 0.1 for b in chars)
    probs[a] = {b: (counts[a][b] + 0.1) / total for b in chars}

top = sorted(probs["."].items(), key=lambda kv: -kv[1])[:5]
print("самые частые первые буквы:", [(b, round(p, 3)) for b, p in top])

# 3. Сэмплирование: начиная с ".", тянем символы по одному согласно вероятностям, пока снова не выпадет "."
random.seed(7)
def sample():
    out, cur = "", "."
    while True:
        cur = random.choices(chars, weights=[probs[cur][b] for b in chars])[0]
        if cur == ".":
            return out
        out += cur
print("сгенерированные имена:", [sample() for _ in range(10)])

# 4. Оценка: среднее отрицательное логарифмическое правдоподобие (NLL) и перплексия
def avg_nll(words):
    nll, n = 0.0, 0
    for w in words:
        seq = ["."] + list(w) + ["."]
        for a, b in zip(seq, seq[1:]):
            nll += -math.log(probs[a][b])
            n += 1
    return nll / n

loss = avg_nll(NAMES)
print(f"обучающая выборка: средний NLL = {loss:.3f}, перплексия = {math.exp(loss):.2f}")
print(f"случайное угадывание (равномерно): средний NLL = {math.log(len(chars)):.3f}, перплексия = {len(chars)}")
print(f"новое имя 'sophie': {avg_nll(['sophie']):.3f}   бессмыслица 'zqxj': {avg_nll(['zqxj']):.3f}")
```

Разберём, что делает эта программа.

### Сэмплирование (генерация)

Такой способ генерации называется **авторегрессионным** (autoregressive): начинаем с символа начала, **случайно вытягиваем** символ согласно вероятностям модели, приписываем его, вытягиваем следующий при условии этого… пока не выпадет символ конца. `random.choices(кандидаты, weights=вероятности)` — это и есть «тянуть жребий по вероятностям». GPT генерирует ответы точно так же, токен за токеном.

Одни сгенерированные имена выглядят правдоподобно, другие странно — потому что модель **помнит только предыдущий символ** и не знает, какой длины уже имя и какие слоги в нём были. Чтобы стало лучше, нужен более длинный контекст.

### Оценка: перплексия

Как понять, хороша ли языковая модель? Посмотреть, какую вероятность она даёт **настоящему тексту**: средний NLL (чем ниже, тем лучше) или его экспоненту — **перплексию** (perplexity):

```formula
перплексия = e^(средний NLL)
```

Интуитивно перплексия — это **между сколькими вариантами модель в среднем «колеблется» на каждом шаге**. У чистого угадывания (все 27 символов равновероятны) перплексия ровно 27; наша биграммная модель получает около 9 — значит, она действительно чему-то научилась. Бессмыслица `zqxj` получает NLL гораздо выше, чем похожее на имя `sophie`.

> [!NOTE]
> Перплексия — классическая метрика языковых моделей; её до сих пор используют для сравнения предобученных моделей (она зависит от токенизации, поэтому сравнивать можно только модели с одинаковой токенизацией).

### Сглаживание: зачем прибавлять 0.1?

Если какая-то пара символов ни разу не встретилась в обучающих данных (например, `qx`), её счёт 0, вероятность 0, а `−log(0)` — **бесконечность**: одно такое появление ломает всю оценку. Если прибавить к каждому счёту небольшое число (это **сглаживание**, smoothing), даже «невиданные» сочетания получат немного вероятности.

## 1.4 То же самое нейросетью

Подсчёт прост, но не масштабируется: чтобы смотреть на 10 предыдущих символов, понадобилось бы 27¹⁰ ≈ 2×10¹⁴ сочетаний, почти ни одно из которых не встречалось, — сосчитать невозможно. Подход **нейросети** — не считать, а **выучить функцию**, которая принимает контекст и выдаёт вероятности следующего символа.

Сначала переделаем биграммную модель на нейросеть и посмотрим, выучит ли она то же, что подсчёт:

- вход: текущий символ (номер 0–26) в виде **one-hot вектора** (1 на позиции i, остальные 0);
- модель: матрица весов `W` размером 27×27; one-hot вектор, умноженный на `W`, — это ровно i-я строка `W`, она служит **логитами**;
- выход: softmax от логитов — вероятности следующего символа;
- потери: перекрёстная энтропия (средний NLL выше); обучаем градиентным спуском.

```python
import math
import random

NAMES = """emma olivia ava isabella sophia mia charlotte amelia harper evelyn abigail emily
elizabeth sofia avery ella madison scarlett victoria aria grace chloe camila penelope riley
layla lillian nora zoey mila aubrey hannah lily addison eleanor natalie luna savannah leah
stella hazel ellie audrey violet claire bella aurora lucy anna samantha caroline sarah maya
liam noah william james oliver benjamin elijah lucas mason logan alexander ethan jacob
michael daniel henry jackson sebastian aiden matthew samuel david joseph carter owen wyatt
john jack luke dylan levi isaac gabriel julian mateo anthony lincoln joshua andrew caleb
ryan nathan thomas leo isaiah charles hudson hunter connor eli ezra aaron adrian nolan""".split()

chars = list(".abcdefghijklmnopqrstuvwxyz")
idx = {c: i for i, c in enumerate(chars)}          # символ → номер
V = len(chars)

pairs = []                                          # обучающие данные: (текущий символ, следующий символ)
for name in NAMES:
    seq = ["."] + list(name) + ["."]
    pairs += [(idx[a], idx[b]) for a, b in zip(seq, seq[1:])]
print("обучающих примеров:", len(pairs))

# Модель: матрица весов V×V. One-hot(a), умноженный на W, выбирает строку a — это и есть логиты
random.seed(0)
W = [[random.gauss(0, 0.1) for _ in range(V)] for _ in range(V)]

def softmax(z):
    m = max(z)
    e = [math.exp(v - m) for v in z]
    s = sum(e)
    return [v / s for v in e]

lr = 20.0
for epoch in range(1, 201):
    grad = [[0.0] * V for _ in range(V)]
    loss = 0.0
    for a, b in pairs:
        p = softmax(W[a])                          # прямой проход: распределение следующего символа
        loss += -math.log(p[b])                    # перекрёстная энтропия
        for j in range(V):                         # обратный проход: градиент softmax + перекрёстной энтропии = p − one_hot(b)
            grad[a][j] += p[j] - (1.0 if j == b else 0.0)
    for i in range(V):                             # градиентный спуск (по усреднённому градиенту)
        for j in range(V):
            W[i][j] -= lr * grad[i][j] / len(pairs)
    if epoch in (1, 10, 50, 100, 200):
        print(f"эпоха {epoch:3d}  средний NLL {loss / len(pairs):.3f}")

p = softmax(W[idx["a"]])
best = sorted(range(V), key=lambda j: -p[j])[:3]
print("выученные P(следующий | 'a'):", [(chars[j], round(p[j], 3)) for j in best])
```

Потери падают примерно с 3.3 (угадывание) до примерно 2.14 — практически как у подсчёта, и выученная таблица вероятностей совпадает с подсчитанной. **Оба способа выучивают одно и то же.** Различия:

| | Подсчёт (n-граммы) | Нейросеть |
|---|---|---|
| «обучение» | считаем частоты | градиентный спуск |
| длинный контекст | число сочетаний растёт экспоненциально, данных не хватает | число параметров остаётся разумным; контекст может быть сколь угодно длинным |
| обобщение | невиданные сочетания — только через сглаживание | похожие контексты дают похожие предсказания |

> [!TIP]
> Интересное соответствие: L2-регуляризация (затухание весов) в нейросетевой версии действует так же, как сглаживание в версии с подсчётом, — обе не дают распределениям стать слишком «крайними».

## 1.5 От n-грамм к GPT: краткая история

| Год | Веха | Ключевая идея |
|-----|------|---------------|
| 1948 | эксперименты Шеннона с n-граммами | предсказывать следующую букву / слово по статистическим частотам |
| 1980–2000-е | статистические n-граммные модели | основа распознавания речи и машинного перевода |
| 2003 | нейросетевая вероятностная языковая модель Бенжио | **векторы слов** + нейросеть вместо подсчёта (векторы слов — в уроке 3) |
| 2010-е | RNN / LSTM | рекуррентные структуры, «помнящие» длинный контекст |
| 2017 | **Transformer** («Attention Is All You Need») | **внимание** видит весь контекст сразу и обучается параллельно |
| 2018– | семейства GPT и BERT | предобучение огромных трансформеров на огромных объёмах текста |
| 2022– | эпоха LLM после ChatGPT | инструктивное дообучение, выравнивание, рассуждающие модели… |

В следующих уроках мы пройдём этот путь шаг за шагом: **токенизация** (урок 2) → **эмбеддинги** (урок 3) → **внимание** (урок 4) → **трансформер** (урок 5) → обучаем **маленький GPT** сами (урок 6) → **стратегии декодирования** (урок 7).

## 1.6 Итоги

- Языковая модель предсказывает **распределение вероятностей следующего токена**; цепное правило позволяет оценить весь текст, а **авторегрессионное сэмплирование** — генерировать текст.
- На практике используют **отрицательное логарифмическое правдоподобие** (NLL, то есть перекрёстную энтропию); **перплексия** = e^(средний NLL) — примерно «между сколькими вариантами модель колеблется на каждом шаге»; чем ниже, тем лучше.
- **N-граммные** модели смотрят только на n−1 предыдущих токенов и обучаются подсчётом; невиданным сочетаниям нужно **сглаживание**; длинный контекст сосчитать невозможно.
- Нейросеть с one-hot входом, линейным слоем и softmax градиентным спуском выучивает ровно ту же биграммную модель — а нейросети масштабируются на гораздо более длинный контекст.

### Задание 3: Почему имена получаются странными?

Имена, сгенерированные биграммной моделью, часто слишком длинные или нечитаемые. Главная причина:

- в обучающих данных есть опечатки
- модель смотрит только на предыдущий символ и ничего не знает о более раннем (например, какой длины уже имя)
- неудачно выбрано зерно генератора случайных чисел
- в наборе символов нет заглавных букв

<details>
<summary>Ответ и разбор</summary>

Биграммная модель предсказывает следующий символ только по предыдущему и полностью «забывает» всё, что было раньше, поэтому не может сделать целое похожим на имя. Ключ к улучшению — более длинный контекст; именно это сделают нейросети и трансформеры.
</details>

### Задание 4: Что будет без сглаживания?

Если не делать сглаживание, а в тестовом тексте встретится пара символов, которой не было в обучающей выборке, средний NLL на тесте будет:

- 0
- бесконечным
- не изменится
- отрицательным

<details>
<summary>Ответ и разбор</summary>

У невиданного сочетания вероятность 0, `−log(0) = ∞`, значит, и среднее бесконечно (как и перплексия). Поэтому и нужно сглаживание.
</details>

### Задание 5: Перплексия угадывания

Модель, которая «ничему не научилась», даёт одинаковую вероятность всем 50 000 токенам словаря. Какая у неё перплексия?

- 1
- около 10.8 (то есть ln 50000)
- 50000
- 25000

<details>
<summary>Ответ и разбор</summary>

Вероятность каждого токена 1/50000, NLL = ln 50000, перплексия = e^(ln 50000) = 50000. Перплексия равномерного распределения равна числу вариантов — отсюда и «между сколькими вариантами колеблется».
</details>
