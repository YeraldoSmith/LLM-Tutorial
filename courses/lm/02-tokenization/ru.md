# 2. Токенизация: как текст превращается в токены

> 🎯 **Цели урока**: понять, зачем моделям «токенизация» и чем хороши и плохи деление на символы, слова и подслова; разобраться в Unicode и **байтах UTF-8**; самостоятельно реализовать токенизатор **BPE (кодирование пар байтов)**, который используют модели GPT: обучение, кодирование, декодирование; увидеть, как обучающие данные токенизатора влияют на пользователей, говорящих по-русски, по-китайски и на других языках; познакомиться со специальными токенами и шаблонами диалога; понять, почему LLM «не умеют считать буквы» и откуда другие странности.
>
> ⏱ **Время**: 80 минут　|　📋 **Что нужно знать**: урок 1 этой части

В прошлом уроке каждый символ был токеном. Настоящие большие модели так не делают: они с помощью **токенизатора** (tokenizer) режут текст на кусочки-**подслова** (subword) и заменяют каждый кусочек номером. Токенизатор кажется просто «предобработкой», но он сильно влияет на способности модели, её скорость и стоимость — особенно для тех, кто не говорит по-английски.

> Реализация BPE в этом уроке следует проекту Андрея Карпатого [minbpe](https://github.com/karpathy/minbpe) (лицензия MIT) и его видео [Let's build the GPT Tokenizer](https://www.youtube.com/watch?v=zduSFxRajkE).

## 2.1 Зачем токенизировать? Три способа резать

Нейросети понимают только числа, поэтому текст сначала режут на кусочки и дают каждому номер. Как резать — это компромисс:

| Способ | Размер словаря | Длина последовательности | Проблемы |
|--------|----------------|--------------------------|----------|
| **по символам** | маленький (десятки для английского; с китайскими иероглифами — десятки тысяч) | очень длинная | последовательности слишком длинные и дорогие; отдельный символ почти ничего не значит |
| **по словам** | огромный (сотни тысяч и больше) | короткая | новые слова, опечатки, имена не представить («слова вне словаря»); для китайского сначала нужна сегментация на слова; у русского слишком много словоформ |
| **по подсловам** (BPE и др.) | умеренный (30 000–250 000) | умеренная | частые слова — один токен, редкие делятся на несколько частей; лучшее из обоих миров |

Почти все современные LLM используют токенизацию **по подсловам**. Например, `unbelievable` может стать `un` + `believ` + `able`, а слово, которого модель никогда не видела, всегда можно собрать из имеющихся кусочков.

## 2.2 От символов к байтам: Unicode и UTF-8

У каждого символа в компьютере есть **номер Unicode** (кодовая точка): `A` — 65, `Ж` — 1046, `你` — 20320. Для хранения и передачи чаще всего используют кодировку **UTF-8**, которая превращает кодовую точку в 1–4 **байта** (числа от 0 до 255): английская буква занимает 1 байт, кириллическая — 2, китайский иероглиф — 3, эмодзи — 4.

```python
for ch in ["A", "é", "Ж", "你", "😀"]:
    b = ch.encode("utf-8")
    print(f"{ch!r}: кодовая точка {ord(ch):6d}  байты UTF-8 {list(b)} ({len(b)})")

text = "Hi 你好 Привет"
print(len(text), "символов,", len(text.encode("utf-8")), "байт")
print(bytes([228, 189, 160]).decode("utf-8"))     # байты обратно в текст
```

Начиная с GPT-2, большинство токенизаторов начинает с **байтов**: любой текст (на любом языке, с эмодзи, даже мусор) записывается последовательностью байтов, поэтому **символов, которые нельзя представить, не бывает**. Первые 256 токенов словаря — это 256 значений байта; все следующие токены **слиты** из них.

## 2.3 BPE: кодирование пар байтов

Обучение **BPE** (Byte Pair Encoding) удивительно простое:

1. превращаем обучающий текст в последовательность байтов (каждый байт — токен с номером 0–255);
2. считаем, сколько раз встречается каждая **пара соседних токенов**;
3. сливаем **самую частую пару** в новый токен (номер 256, 257…) и записываем это «правило слияния»;
4. повторяем шаги 2–3, пока словарь не достигнет нужного размера.

Чтобы **закодировать** новый текст, применяем выученные правила **в том порядке, в котором они выучены**; чтобы **декодировать** — склеиваем байты всех токенов и декодируем их как UTF-8.

```python
EN = """A language model reads text as a sequence of tokens and learns to predict the next token.
The model never sees letters or words directly: it only sees numbers. Before training, we must
decide how to cut the text into pieces. If the pieces are single characters, the sequences become
very long. If the pieces are whole words, the vocabulary becomes huge and new words cannot be
represented. Byte pair encoding finds a middle way: it starts from bytes and repeatedly merges the
most frequent pair of neighbouring tokens into a new token. Frequent words become single tokens,
while rare words are split into smaller pieces. The same tokenizer is used for training the model
and for every request the model receives later, so the tokenizer is part of the model."""

def get_stats(ids):                       # считаем, сколько раз встречается каждая пара соседей
    counts = {}
    for pair in zip(ids, ids[1:]):
        counts[pair] = counts.get(pair, 0) + 1
    return counts

def merge(ids, pair, new_id):             # заменяем каждое вхождение pair в ids на new_id
    out, i = [], 0
    while i < len(ids):
        if i < len(ids) - 1 and (ids[i], ids[i + 1]) == pair:
            out.append(new_id)
            i += 2
        else:
            out.append(ids[i])
            i += 1
    return out

def train(text, vocab_size):
    ids = list(text.encode("utf-8"))      # начинаем с байтов: 0–255
    merges = {}                           # (a, b) → номер нового токена
    vocab = {i: bytes([i]) for i in range(256)}
    for new_id in range(256, vocab_size):
        stats = get_stats(ids)
        if not stats:
            break
        pair = max(stats, key=stats.get)  # самая частая пара
        ids = merge(ids, pair, new_id)
        merges[pair] = new_id
        vocab[new_id] = vocab[pair[0]] + vocab[pair[1]]
    return merges, vocab

def encode(text, merges):
    ids = list(text.encode("utf-8"))
    while len(ids) >= 2:
        stats = get_stats(ids)
        pair = min(stats, key=lambda p: merges.get(p, float("inf")))   # сначала самое раннее правило
        if pair not in merges:
            break
        ids = merge(ids, pair, merges[pair])
    return ids

def decode(ids, vocab):
    return b"".join(vocab[i] for i in ids).decode("utf-8", errors="replace")

merges, vocab = train(EN, 256 + 100)      # выучим 100 правил слияния
print("первые 10 выученных токенов:", [vocab[i].decode("utf-8", "replace") for i in range(256, 266)])
sentence = "the model predicts the next token"
ids = encode(sentence, merges)
print("закодировано:", ids)
print("кусочки:     ", [vocab[i].decode("utf-8", "replace") for i in ids])
print(f"{len(sentence)} символов → {len(ids)} токенов; декодируется обратно: {decode(ids, vocab) == sentence}")
```

Первыми сливаются очень частые фрагменты: `e ` (конечная e с пробелом), ` t`, `he `; вскоре появляются целые слова — ` the `, `model `, ` token`. Частые слова становятся 1 токеном, менее частые (как `predicts`) делятся на части.

> [!NOTE]
> В настоящих токенизаторах перед BPE есть шаг **предварительной токенизации**: регулярное выражение сначала делит текст на слова, числа, знаки препинания и пробелы, и BPE сливает только внутри каждого куска. Так `dog.`, `dog!` и `dog?` не превращаются в три разных токена.

## 2.4 Кому выгоден токенизатор? «Налог на токены» для неанглоязычных

Токенизатор учится на своих **обучающих данных**. Если это в основном английский текст, английский сжимается хорошо, а другие языки остаются россыпью байтов. Ниже обучим один токенизатор только на английском, а другой — на английском + китайском + русском, и сравним, сколько токенов нужно предложениям с одинаковым смыслом:

```python
EN = """A language model reads text as a sequence of tokens and learns to predict the next token.
The model never sees letters or words directly: it only sees numbers. Before training, we must
decide how to cut the text into pieces. If the pieces are single characters, the sequences become
very long. If the pieces are whole words, the vocabulary becomes huge and new words cannot be
represented. Byte pair encoding finds a middle way: it starts from bytes and repeatedly merges the
most frequent pair of neighbouring tokens into a new token. Frequent words become single tokens,
while rare words are split into smaller pieces. The same tokenizer is used for training the model
and for every request the model receives later, so the tokenizer is part of the model."""
ZH = """语言模型把文本看成一串词元，学习预测下一个词元。模型看不到汉字本身，只能看到数字。
训练之前，我们必须决定怎样把文本切成小块。如果每个汉字都是一块，序列就会很长；
如果每个词都是一块，词表就会非常大，新词也无法表示。字节对编码从字节出发，
不断把最常见的相邻两块合并成新的一块，于是常见的词变成一个词元，少见的词被拆成更小的部分。
同一个分词器既用于训练模型，也用于模型以后收到的每一个请求，所以分词器也是模型的一部分。"""
RU = """Языковая модель читает текст как последовательность токенов и учится предсказывать
следующий токен. Модель не видит букв и слов, она видит только числа. Перед обучением нужно
решить, как разрезать текст на кусочки. Если кусочки — отдельные символы, последовательности
становятся очень длинными. Если кусочки — целые слова, словарь становится огромным, а новые
слова нельзя представить. Кодирование пар байтов находит середину: оно начинает с байтов и
снова и снова объединяет самую частую пару соседних токенов в новый токен."""

def get_stats(ids):
    counts = {}
    for pair in zip(ids, ids[1:]):
        counts[pair] = counts.get(pair, 0) + 1
    return counts

def merge(ids, pair, new_id):
    out, i = [], 0
    while i < len(ids):
        if i < len(ids) - 1 and (ids[i], ids[i + 1]) == pair:
            out.append(new_id)
            i += 2
        else:
            out.append(ids[i])
            i += 1
    return out

def train(text, vocab_size):
    ids, merges = list(text.encode("utf-8")), {}
    vocab = {i: bytes([i]) for i in range(256)}
    for new_id in range(256, vocab_size):
        stats = get_stats(ids)
        pair = max(stats, key=stats.get)
        ids = merge(ids, pair, new_id)
        merges[pair] = new_id
        vocab[new_id] = vocab[pair[0]] + vocab[pair[1]]
    return merges, vocab

def encode(text, merges):
    ids = list(text.encode("utf-8"))
    while len(ids) >= 2:
        stats = get_stats(ids)
        pair = min(stats, key=lambda p: merges.get(p, float("inf")))
        if pair not in merges:
            break
        ids = merge(ids, pair, merges[pair])
    return ids

for name, data in [("обучен только на английском", EN), ("обучен на английском + китайском + русском", EN + ZH + RU)]:
    merges, vocab = train(data, 256 + 300)
    print(name)
    for s in ["the model predicts the next token", "模型预测下一个词元", "модель предсказывает токен"]:
        ids = encode(s, merges)
        pieces = [vocab[i].decode("utf-8", "replace") for i in ids]
        print(f"   {len(s):2d} символов → {len(ids):2d} токенов  ", pieces[:6])
```

При обучении только на английском китайское предложение из 9 иероглифов превращается в 27 токенов (по 3 байта на иероглиф, ничего не слито), а русское — почти в один токен на байт; если добавить китайский и русский в обучающие данные, тем же предложениям нужно вдвое меньше токенов и даже меньше. `�` означает, что токен — это лишь **часть байтов** символа и сам по себе не отображается.

На практике это важно, потому что:

- **оплата за токены**: API берут деньги за число токенов, поэтому тот же смысл на «прожорливом» языке стоит дороже;
- **контекст короче**: модель читает за раз ограниченное число токенов, и чем больше токенов, тем меньше текста помещается;
- **генерация медленнее**: модель выдаёт по одному токену, больше токенов — дольше.

Ранний токенизатор GPT-2 был очень неэффективен для русского и китайского. Современные токенизаторы (`o200k_base` у GPT-4o, Llama 3, Qwen, DeepSeek и другие) обучены на большом количестве многоязычных данных, у них больше словари, и с русским и китайским они работают гораздо эффективнее.

| Модель / токенизатор | Размер словаря |
|----------------------|----------------|
| GPT-2 | 50 257 |
| GPT-4 (`cl100k_base`) | около 100 000 |
| GPT-4o (`o200k_base`) | около 200 000 |
| Llama 3 | около 128 000 |
| семейство Qwen | около 150 000 |
| DeepSeek-V3 | около 129 000 |

## 2.5 Настоящие токенизаторы

В реальных проектах BPE сами не пишут, а берут готовую библиотеку, например `tiktoken` от OpenAI или `transformers` от Hugging Face (она загружает токенизатор любой открытой модели):

```python norun
# pip install tiktoken
import tiktoken
enc = tiktoken.get_encoding("o200k_base")          # токенизатор GPT-4o
ids = enc.encode("Большие языковые модели — это интересно!")
print(len(ids), ids)
print([enc.decode([i]) for i in ids])               # посмотрим, что за каждый токен

# pip install transformers
from transformers import AutoTokenizer
tok = AutoTokenizer.from_pretrained("Qwen/Qwen3-0.6B")   # при первом запуске скачивается с Hugging Face
print(tok.tokenize("Большие языковые модели — это интересно!"))
```

> [!TIP]
> Наглядно посмотреть, как режется текст, можно в онлайн-инструментах, например на странице [Tokenizer](https://platform.openai.com/tokenizer) от OpenAI или в [The Tokenizer Playground](https://huggingface.co/spaces/Xenova/the-tokenizer-playground) на Hugging Face.

## 2.6 Специальные токены и шаблоны диалога

Кроме обычных кусочков текста, в словаре есть **специальные токены**, которые не соответствуют никакому тексту, а служат «метками»:

- `<|endoftext|>`: конец документа (разделяет документы при предобучении);
- **метки ролей** в чат-моделях: «дальше — системная подсказка / пользователь / ассистент».

Переписка, которую вы видите в чате, перед подачей в модель склеивается в один длинный текст со специальными токенами. Такой формат называется **шаблоном диалога** (chat template). Формат, который используют Qwen и другие, выглядит примерно так:

```text
<|im_start|>system
Ты полезный ассистент.<|im_end|>
<|im_start|>user
Сколько будет 1 + 1?<|im_end|>
<|im_start|>assistant
1 + 1 = 2.<|im_end|>
```

Модель выучила: после `<|im_start|>assistant` нужно генерировать ответ и остановиться на `<|im_end|>`. У разных моделей разные шаблоны, и неправильный шаблон ухудшает работу модели — `tokenizer.apply_chat_template(...)` из Hugging Face сам подставляет правильный. Мы снова воспользуемся им при дообучении в части 5.

## 2.7 Странности из-за токенизации

Многие загадочные особенности LLM объясняются токенизацией:

| Поведение | Причина |
|-----------|---------|
| не может сосчитать буквы `r` в `strawberry` | модель видит токены вроде `str` + `aw` + `berry`, а не отдельные буквы |
| плохо пишет слова задом наперёд и работает с буквами | то же: буквы спрятаны внутри токенов |
| ошибается в арифметике с большими числами | числа режутся на неровные куски (например, `12345` → `123` + `45`), разряды не совпадают |
| лишний пробел в конце портит ответ | `" token"` (с пробелом впереди) и `"token"` — разные токены, а одинокий пробел в обучении встречается редко |
| русский, китайский и редкие языки «дороже» | их мало в обучающих данных токенизатора, сжатие хуже (раздел 2.4) |

> [!NOTE]
> Новые рассуждающие модели «продумывают» задачу (например, сначала выписывают слово по буквам, а потом считают), поэтому эти проблемы стали гораздо мягче, но корень всё тот же — токенизация. Есть и исследования, которые пытаются вообще убрать токенизатор и моделировать байты напрямую.

## 2.8 Итоги

- Модели понимают только числа: **токенизатор** режет текст на токены и нумерует их. Токенизация по подсловам уравновешивает размер словаря и длину последовательности.
- Текст → кодовые точки Unicode → **байты UTF-8** (1 байт на английскую букву, 2 на кириллическую, 3 на иероглиф); начиная с байтов, можно представить любой текст.
- **BPE**: начинаем с байтов и снова и снова сливаем самую частую пару соседей; кодирование применяет слияния в выученном порядке, декодирование склеивает байты обратно.
- От обучающих данных токенизатора зависит, насколько хорошо сжимается каждый язык: больше токенов — дороже, меньше текста в контексте, медленнее генерация. Современные многоязычные токенизаторы намного лучше.
- **Специальные токены** и **шаблоны диалога** превращают многоходовую переписку в один текст; странности вроде подсчёта букв и арифметических ошибок часто происходят из токенизации.

<details>
<summary>Ответ и разбор</summary>

`72, 105, 32` — это `H`, `i` и пробел; 3 байта `228, 189, 160` вместе — кодировка UTF-8 китайского иероглифа 你. Поэтому выводится `Hi 你`, а затем `6` (6 байтов, но всего 4 символа).
</details>

### Задание 4: Считаем буквы

Ранние LLM часто ошибались в вопросе «сколько букв r в слове strawberry». Главная причина:

- модель не учила английский
- модель видит токены (куски из нескольких букв), а не отдельные буквы
- модели не хватает вычислительных способностей
- этого слова нет в обучающих данных

<details>
<summary>Ответ и разбор</summary>

Слово режется на куски вроде `str`, `aw` и `berry`, и для модели каждый кусок — просто номер; буквы внутри куска напрямую не видны.
</details>

<!-- exercise: vocab-size -->
### Задание 5: Чем больше словарь, тем лучше?

Словарь токенизатора увеличили с 30 000 до 200 000. Какое утверждение **верно**?

- тот же текст превратится в большее число токенов
- тот же текст превратится в меньшее число токенов, но у слоя эмбеддингов и выходного слоя станет больше параметров
- на модель это никак не влияет
- модель перестанет справляться с незнакомыми словами

<details>
<summary>Ответ и разбор</summary>

В большом словаре больше слитых кусков, поэтому последовательности короче (быстрее, больше текста в контексте). Цена: каждому токену нужна своя строка эмбеддингов, а выходной слой должен оценить каждый токен, так что параметров и вычислений больше. Байтовый BPE представляет любой текст при любом размере словаря.
</details>
