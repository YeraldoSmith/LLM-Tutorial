## 4.1 Зачем нужно внимание?

Нейросетевая языковая модель из прошлого урока смотрела **ровно на 3 предыдущих** символа и склеивала их. Здесь две проблемы:

1. **Фиксированное окно**: чтобы смотреть на 1000 предыдущих токенов, вход должен стать в 1000 раз длиннее, а параметров станет взрывно много;
2. **Всё одинаково**: каждая позиция обрабатывается фиксированным образом, хотя полезная информация может быть где угодно.

Возьмём фразу: «Аня вернула книгу Маше, потому что **ей** завтра сдавать экзамен». Чтобы понять, о ком «ей», модель должна **оглянуться назад** и найти нужное слово (Маша), которое может быть далеко. Нам нужно, чтобы **каждый токен мог по мере надобности «выбрать» нужную информацию из всех предыдущих токенов и собрать её в себе.** Это и есть **внимание** (attention).

## 4.2 Шаг первый: усредняем предыдущую информацию

Самый простой способ «собрать предыдущий текст»: выход на позиции t = **среднее** векторов на позициях до t (включая её саму).

```python
# 4 токена, каждый — двумерный вектор (представим, что это эмбеддинги)
X = [[1.0, 0.0], [0.0, 2.0], [3.0, 1.0], [1.0, 1.0]]

# выход на позиции t = среднее первых t+1 векторов (включая себя)
out = []
for t in range(len(X)):
    seen = X[:t + 1]
    out.append([sum(v[i] for v in seen) / len(seen) for i in range(2)])
for t, v in enumerate(out):
    print(f"позиция {t}: усреднили {t + 1} токен(а) →", [round(a, 3) for a in v])
```

Обратите внимание: каждая позиция **видит только себя и более ранние**, но не более поздние: языковая модель предсказывает следующий токен, и если бы она могла «подсмотреть» ответ, то ничему бы не научилась. Это **причинное** (causal) ограничение.

У усреднения очевидный недостаток: все предыдущие токены получают **одинаковый вес**. Мы хотим, чтобы у нужных токенов вес был большим, у ненужных — маленьким, и чтобы веса **зависели от содержания**.

## 4.3 Шаг второй: взвешиваем по важности — Query, Key, Value

Представьте внимание как **нечёткий поиск по словарю** (или поисковую систему):

- **Query (запрос)**: «что я ищу?» — вопрос, который задаёт текущий токен;
- **Key (ключ)**: «что у меня есть?» — ярлык, который вывешивает каждый токен;
- **Value (значение)**: «что я дам, если выберешь меня» — содержимое каждого токена.

**Скалярное произведение** запроса с каждым ключом даёт оценки совпадения, **softmax** превращает их в веса с суммой 1, а затем берём **взвешенное среднее** значений:

```python
import math

def softmax(z):
    m = max(z)
    e = [math.exp(v - m) for v in z]
    s = sum(e)
    return [v / s for v in e]

def dot(a, b):
    return sum(x * y for x, y in zip(a, b))

# «мини-поисковик»: у каждой записи есть key (ярлык) и value (содержимое)
keys   = [[1.0, 0.0], [0.0, 1.0], [0.7, 0.7]]
values = [[10.0, 0.0], [0.0, 10.0], [5.0, 5.0]]
query  = [1.0, 0.2]                          # что я ищу

scores = [dot(query, k) for k in keys]       # насколько совпадает с каждым ключом
weights = softmax(scores)                    # веса с суммой 1
output = [sum(w * v[i] for w, v in zip(weights, values)) for i in range(2)]
print("оценки совпадения:", [round(s, 3) for s in scores])
print("веса внимания:    ", [round(w, 3) for w in weights])
print("выход (взвешенное среднее значений):", [round(o, 3) for o in output])
```

Обычный словарь требует «точного совпадения» и возвращает одну запись; внимание возвращает «**смесь всех записей, взвешенную по степени совпадения**», причём весь процесс дифференцируем, так что его можно обучать градиентным спуском.

В **самовнимании** (self-attention) запросы, ключи и значения **берутся из той же последовательности токенов**: эмбеддинг каждого токена `x` умножается на три обучаемые матрицы, и получаются его q, k и v:

```formula
q = x·W_Q　　k = x·W_K　　v = x·W_V
```

В ходе обучения модель сама учится, какие «вопросы» задавать, какие «ярлыки» вывешивать и какое «содержимое» отдавать, если её выбрали.

## 4.4 Масштабированное скалярное внимание

Сложим q, k, v всех токенов в матрицы Q, K, V (по строке на токен) — и внимание для всех позиций считается сразу матрицами:

```formula
Attention(Q, K, V) = softmax( Q·Kᵀ / √d ) · V
```

- `Q·Kᵀ` — матрица n×n: строка i, столбец j = скалярное произведение запроса токена i и ключа токена j;
- деление на `√d` (d — размерность q и k) — это **масштабирование**, объяснение ниже;
- softmax применяется к **каждой строке**, поэтому веса каждого токена в сумме дают 1;
- умножение на V: выход каждого токена = взвешенное среднее всех значений.

### Зачем делить на √d?

Скалярное произведение двух случайных d-мерных векторов растёт примерно как `√d`. При большой размерности оценки сильно различаются, и softmax становится очень «острым»: почти весь вес уходит одному токену, остальные получают градиенты около 0, и учиться трудно. Деление на `√d` возвращает оценки в разумный диапазон:

```python
import math
import random

def softmax(z):
    m = max(z)
    e = [math.exp(v - m) for v in z]
    s = sum(e)
    return [v / s for v in e]

random.seed(0)
for d in (4, 64, 1024):
    q = [random.gauss(0, 1) for _ in range(d)]
    keys = [[random.gauss(0, 1) for _ in range(d)] for _ in range(5)]
    raw = [sum(a * b for a, b in zip(q, k)) for k in keys]
    scaled = [s / math.sqrt(d) for s in raw]
    print(f"d={d:4d}  наибольший вес без масштаба {max(softmax(raw)):.3f}   после деления на √d {max(softmax(scaled)):.3f}")
```

### Причинная маска

В языковой модели токен i может смотреть только на токены с позициями ≤ i. Приём: **до** softmax записать в оценки «будущих» позиций **−∞**. Поскольку e^(−∞) = 0, после softmax у этих позиций вес 0. Поэтому матрица весов **нижнетреугольная**.

## 4.5 Полное причинное самовнимание на чистом Python

```python
import math
import random

def softmax(z):
    m = max(z)
    e = [math.exp(v - m) for v in z]
    s = sum(e)
    return [v / s for v in e]

def matmul(A, B):                       # (n×k) @ (k×m)
    return [[sum(a * b for a, b in zip(row, col)) for col in zip(*B)] for row in A]

random.seed(0)
tokens = ["я", "люблю", "большие", "модели"]
n, d = len(tokens), 4
X = [[random.gauss(0, 1) for _ in range(d)] for _ in range(n)]          # эмбеддинги 4 токенов (n×d)
Wq = [[random.gauss(0, 0.3) for _ in range(d)] for _ in range(d)]       # три обучаемые матрицы (d×d)
Wk = [[random.gauss(0, 0.3) for _ in range(d)] for _ in range(d)]
Wv = [[random.gauss(0, 0.3) for _ in range(d)] for _ in range(d)]

Q, K, V = matmul(X, Wq), matmul(X, Wk), matmul(X, Wv)                   # query, key и value каждого токена
scores = matmul(Q, [list(c) for c in zip(*K)])                          # Q @ Kᵀ: оценки совпадения n×n
scale = 1 / math.sqrt(d)
weights = []
for i in range(n):
    row = [scores[i][j] * scale if j <= i else float("-inf") for j in range(n)]   # причинная маска: будущее не видно
    weights.append(softmax(row))
out = matmul(weights, V)                                                # взвешенное среднее значений

print("веса внимания (строка i = на кого смотрит токен i):")
print("          " + "".join(f"{t:>9}" for t in tokens))
for t, row in zip(tokens, weights):
    print(f"{t:>8}  " + "".join(f"{w:9.3f}" for w in row))
print("форма выхода:", len(out), "×", len(out[0]))
```

Матрица весов нижнетреугольная, каждая строка в сумме даёт 1. Эти веса получены из случайных матриц и пока ничего не значат; **после обучения** модель выучивает полезные закономерности: местоимения «смотрят» на существительные, к которым относятся, глаголы — на свои подлежащие.

> [!TIP]
> Форма выхода внимания такая же, как у входа (n токенов по d измерений), поэтому слои можно ставить друг за другом. После слоя внимания вектор каждого токена **вбирает информацию из контекста**: одно и то же слово «ключ» получит разные векторы во фразах «ключ от двери» и «бьёт ключ».

## 4.6 Многоголовое внимание

Токену может быть нужно сразу несколько видов информации: кто его подлежащее, какое было предыдущее слово, о чём вообще предложение… Один набор Q, K, V даёт только **одно** распределение весов. **Многоголовое внимание** (multi-head attention) выполняет внимание h раз параллельно:

1. разбиваем d измерений на h частей; каждая «голова» независимо выполняет внимание со своими Q, K, V (по d/h измерений);
2. **склеиваем** выходы h голов обратно в d измерений;
3. умножаем на выходную матрицу `W_O`, смешивая информацию голов.

Вычислений примерно столько же, сколько у одной головы, но модель может одновременно следить за разными отношениями. В обученных моделях действительно находят специализированные головы: одни смотрят только на предыдущий токен, другие «копируют» закономерности, встретившиеся раньше в тексте (**индукционные головы**, induction heads)…

Вот многоголовое причинное самовнимание на PyTorch, устроенное почти так же, как код GPT-2:

```python requires=torch
import math
import torch
from torch import nn
import torch.nn.functional as F

class CausalSelfAttention(nn.Module):
    def __init__(self, d_model, n_heads):
        super().__init__()
        assert d_model % n_heads == 0
        self.h, self.dh = n_heads, d_model // n_heads          # число голов, размерность головы
        self.qkv = nn.Linear(d_model, 3 * d_model)             # Q, K и V за один раз
        self.proj = nn.Linear(d_model, d_model)                # выходная проекция W_O

    def forward(self, x):
        B, T, C = x.shape                                      # батч, длина последовательности, размерность
        q, k, v = self.qkv(x).split(C, dim=2)
        # (B, T, C) → (B, h, T, dh): режем C на h голов, каждая выполняет внимание отдельно
        q = q.view(B, T, self.h, self.dh).transpose(1, 2)
        k = k.view(B, T, self.h, self.dh).transpose(1, 2)
        v = v.view(B, T, self.h, self.dh).transpose(1, 2)
        att = q @ k.transpose(-2, -1) / math.sqrt(self.dh)    # (B, h, T, T)
        mask = torch.tril(torch.ones(T, T, dtype=torch.bool))  # нижний треугольник: только себя и раньше
        att = att.masked_fill(~mask, float("-inf"))
        att = F.softmax(att, dim=-1)
        y = att @ v                                            # (B, h, T, dh)
        y = y.transpose(1, 2).reshape(B, T, C)                 # склеиваем головы обратно
        return self.proj(y), att

torch.manual_seed(0)
attn = CausalSelfAttention(d_model=32, n_heads=4)
x = torch.randn(2, 5, 32)                                      # 2 последовательности по 5 токенов, по 32 измерения
y, att = attn(x)
print("выход:", tuple(y.shape), " веса внимания:", tuple(att.shape))
print("веса внимания 1-й последовательности, 1-й головы:")
print(att[0, 0].detach().round(decimals=2))
print("параметров:", sum(p.numel() for p in attn.parameters()))   # 4 × 32 × 32 + 4 × 32

# встроенная эффективная реализация PyTorch (сама выбирает FlashAttention и т. п.) даёт тот же результат
q, k, v = attn.qkv(x).split(32, dim=2)
q, k, v = (t.view(2, 5, 4, 8).transpose(1, 2) for t in (q, k, v))
fast = F.scaled_dot_product_attention(q, k, v, is_causal=True).transpose(1, 2).reshape(2, 5, 32)
print("совпадает с F.scaled_dot_product_attention:", torch.allclose(attn.proj(fast), y, atol=1e-6))
```

Параметры многоголового внимания — четыре матрицы d×d `W_Q`, `W_K`, `W_V`, `W_O`: всего **4d²** (плюс 4d смещений). В каждом слое внимания GPT-2 small (d = 768) около 2,36 млн параметров.

## 4.7 Цена внимания: O(n²)

Матрица оценок внимания имеет размер **n×n**: удвойте длину последовательности — и вычисления с памятью вырастут **вчетверо**. В контексте из миллиона токенов 10¹² оценок — вот почему «длинный контекст» дорог. Исследователи придумали много обходных путей:

| Техника | Идея | Кто использует |
|---------|------|----------------|
| **FlashAttention** | не хранить всю матрицу n×n, считать её блоками в быстрой памяти GPU — тот же результат, гораздо быстрее и экономнее | почти все современные фреймворки обучения и инференса |
| **KV-кэш** | при генерации хранить уже посчитанные K и V, чтобы для нового токена считать только одну новую строку | инференс всех LLM (подробно в части 6) |
| **GQA / MQA** | несколько голов запросов **делят** один набор голов K, V; KV-кэш в разы меньше | Llama 3, Qwen и др. |
| **MLA** (multi-head latent attention) | сжимать K и V в низкоразмерный «латентный вектор» перед кэшированием | DeepSeek-V2/V3 |
| **скользящее окно / разреженное внимание** | каждый токен смотрит только на ближнее окно или на выбранное подмножество токенов | Mistral, Gemma, разреженное внимание DeepSeek и др. |
| **линейное внимание / модели пространства состояний** | заменить softmax-внимание структурами, стоимость которых растёт линейно с длиной | Mamba и некоторые гибридные архитектуры |

## 4.8 Информация о позиции: ротационные эмбеддинги RoPE

Как мы говорили в прошлом уроке, внимание само не знает порядка: перемешайте токены — и распределение весов каждого токена не изменится. GPT-2 **прибавляет** ко входу позиционные эмбеддинги. Почти все современные модели (Llama, Qwen, DeepSeek, Mistral…) используют вместо этого **RoPE** (Rotary Position Embedding, предложено Су Цзяньлинем и соавторами в 2021 году):

- измерения векторов q и k группируются парами, каждая пара — точка на плоскости;
- для токена на позиции m каждая пара **поворачивается** на угол `m × θ` (разные пары вращаются с разной скоростью θ);
- после поворота обоих векторов их скалярное произведение зависит только от **разности углов**, то есть от **относительной позиции m − n**.

```python
import math

def rotate(v, angle):                      # поворот двумерного вектора против часовой стрелки на angle радиан
    x, y = v
    return [x * math.cos(angle) - y * math.sin(angle), x * math.sin(angle) + y * math.cos(angle)]

theta = 0.5                                 # каждая следующая позиция поворачивается ещё на 0.5 радиана
q, k = [1.0, 0.5], [0.3, 1.0]
for m, n in [(5, 3), (10, 8), (102, 100), (3, 5), (7, 7)]:
    qm, kn = rotate(q, m * theta), rotate(k, n * theta)   # q на позиции m, k на позиции n
    score = qm[0] * kn[0] + qm[1] * kn[1]
    print(f"q на позиции {m:3d}, k на позиции {n:3d}, расстояние {m - n:2d}: q·k = {score:.4f}")
```

Если расстояние одинаковое (здесь 2), оценка внимания одинакова, будь токены на 5-й или на 102-й позиции. Это именно то, что нужно: в языке важны **относительные отношения** вроде «предыдущее слово» или «три слова назад». В настоящем RoPE пара i вращается со скоростью `θᵢ = base^(−2i/d)` (base обычно 10000; в Llama 3 — 500000), поэтому одни пары вращаются быстро (различают близкие позиции), а другие очень медленно (различают далёкие). Настройка base и похожих параметров (например, метод YaRN) позволяет моделям работать и с контекстом длиннее, чем при обучении.

## 4.9 Итоги

- Внимание позволяет каждому токену собрать **взвешенную сводку** (более ранних) токенов в зависимости от содержания; веса определяются совпадением запросов с ключами.
- Самовнимание: `q = xW_Q, k = xW_K, v = xW_V`; `Attention = softmax(QKᵀ/√d)·V`; деление на `√d` не даёт softmax стать слишком острым.
- **Причинная маска**: до softmax будущие позиции получают −∞; матрица весов нижнетреугольная.
- **Многоголовое внимание**: h голов параллельно следят за разными отношениями, их выходы склеиваются и умножаются на `W_O`; около 4d² параметров.
- Стоимость растёт как **O(n²)** по длине последовательности; FlashAttention, KV-кэш, GQA/MLA и разреженное внимание нужны, чтобы её уменьшить.
- **RoPE** поворачивает q и k в зависимости от позиции, и оценки внимания зависят только от относительной позиции — стандарт современных LLM.

### Задание 1: Веса внимания

В первой строке — вектор запроса, во второй — целое `n`, в следующих `n` строках — `n` векторов ключей (той же длины, что и запрос). Выведите веса масштабированного скалярного внимания `softmax(q·kⱼ / √d)` (d — длина вектора) с 4 знаками после точки через пробел.

```text
Пример ввода:
1 0
2
1 0
0 1
Пример вывода: 0.6698 0.3302
```

<details>
<summary>Подсказка</summary>

Оценки `s = [sum(a * b for a, b in zip(q, k)) / math.sqrt(len(q)) for k in keys]`, затем softmax (не забудьте сначала вычесть максимум, чтобы избежать переполнения).
</details>

<!-- exercise: causal-mask -->
### Задание 2: Причинная маска

Прочитайте целое `n` и выведите причинную маску `n×n`: в строке i и столбце j стоит `1`, если токен i видит токен j (j ≤ i), иначе `0`. Числа в строке разделяйте пробелами.

```text
Пример ввода: 3
Пример вывода:
1 0 0
1 1 0
1 1 1
```

<details>
<summary>Подсказка</summary>

Два вложенных цикла с `1 if j <= i else 0` или `" ".join("1" if j <= i else "0" for j in range(n))`.
</details>

<!-- exercise: attn-output -->
### Задание 3: Выход внимания

В первой строке — вектор запроса, во второй — целое `n`, затем `n` строк с векторами ключей и `n` строк с векторами значений. Вычислите выход масштабированного скалярного внимания (взвешенное среднее значений) с 4 знаками после точки через пробел.

```text
Пример ввода:
1 0
2
1 0
0 1
10 0
0 10
Пример вывода: 6.6976 3.3024
```

<details>
<summary>Подсказка</summary>

Сначала посчитайте веса `w`, как в задании 1; i-я компонента выхода — `sum(wj * v[i] for wj, v in zip(w, values))`.
</details>

### Задание 4: Параметры многоголового внимания

Прочитайте строку из двух целых `d bias`: размерность модели и наличие смещений (1 — есть, 0 — нет). Выведите общее число параметров одного слоя многоголового внимания (четыре матрицы d×d `W_Q`, `W_K`, `W_V`, `W_O` и, при наличии смещений, по d смещений на матрицу). Обратите внимание: число параметров не зависит от числа голов.

```text
Пример ввода: 768 1
Пример вывода: 2362368
```

<details>
<summary>Подсказка</summary>

`4 * d * d + (4 * d if bias else 0)`
</details>

<!-- exercise: why-scale -->
### Задание 5: Зачем делить на √d?

- чтобы вычисления были быстрее
- чем больше размерность, тем больше скалярные произведения; softmax становится очень «острым», а градиенты уходят в 0, и деление на √d возвращает оценки в хороший диапазон
- чтобы веса давали в сумме 1
- чтобы реализовать причинную маску

<details>
<summary>Ответ и разбор</summary>

Стандартное отклонение скалярного произведения случайных d-мерных векторов около √d. Без масштабирования softmax при большой размерности становится почти one-hot, и большинство позиций не получают градиента. «Сумма 1» обеспечивается самим softmax.
</details>

<!-- exercise: quadratic -->
### Задание 6: Удваиваем контекст

При прочих равных длина последовательности выросла с 4000 до 8000 токенов. Во сколько раз больше элементов станет в матрице оценок внимания?

- в 1 раз (не изменится)
- в 2 раза
- в 4 раза
- в 8 раз

<details>
<summary>Ответ и разбор</summary>

Матрица оценок n×n: 8000² / 4000² = 4. Вот что значит «стоимость внимания растёт квадратично с длиной» — и поэтому длинный контекст дорог.
</details>
