## 5.1 Общая картина

```text
входной текст  «Сегодня погода»
   │  токенизатор
   ▼
номера токенов  [3452, 8812, 1043]                    (T токенов)
   │  эмбеддинг токена + информация о позиции
   ▼
векторы  (T × d)  ──────────────────────┐
   │                                     │  остаточный поток (residual stream)
   │   ┌──────────── Блок 1 ───────────┐ │  каждый блок читает его
   │   │ x = x + Attention(Norm(x))    │ │  и «прибавляет» свой результат
   │   │ x = x + MLP(Norm(x))          │ │
   │   └───────────────────────────────┘ │
   │          … повторяется N раз …       │
   │   ┌──────────── Блок N ───────────┐ │
   │   └───────────────────────────────┘ │
   ▼                                     │
финальная Norm  ◄────────────────────────┘
   │  выходной слой (d → размер словаря)
   ▼
логиты  (T × V)  →  softmax  →  вероятность «следующего токена» на каждой позиции
```

Ключевые моменты:

- Всё время каждому токену соответствует d-мерный вектор; форма остаётся `T × d`, пока в самом конце не станет логитами `T × V`.
- Выход на позиции t предсказывает токен **t+1**. При генерации используется только предсказание последней позиции; **при обучении предсказывает каждая позиция**, и один прямой проход даёт T обучающих сигналов (подробнее в следующем уроке).
- «Глубина» модели — число блоков N: у GPT-2 small 12 слоёв, у Llama 3 70B — 80.

## 5.2 Блок: сначала общаемся, потом думаем

В каждом блоке два подслоя, и каждый устроен как «**нормализуем → считаем → прибавляем к остаточному потоку**»:

```formula
x = x + Attention(Norm(x))     ← токены общаются: собирают информацию из контекста
x = x + MLP(Norm(x))           ← каждый токен думает сам: обрабатывает собранное
```

1. **Внимание** — единственное место, где токены на разных позициях **обмениваются информацией** (прошлый урок).
2. **MLP** (он же FFN, сеть прямого распространения) применяет одно и то же вычисление к **каждому токену независимо**: `d → 4d → d` с активацией вроде GELU посередине. Исследования показывают, что большая часть «знаний» модели (вроде «Париж — столица Франции») хранится в весах MLP.
3. **Остаточные связи**: каждый подслой вычисляет только «изменение», которое прибавляется к x, а не заменяет его. Представьте x как **остаточный поток**, проходящий через все слои: каждый слой из него читает и в него пишет. Градиенты беспрепятственно доходят до первых слоёв (урок 6 части 2), поэтому обучаются даже сети из сотни с лишним слоёв.
4. **Pre-Norm**: нормализация применяется ко **входу** каждого подслоя (а не после сложения, как в исходном трансформере). Так обучение стабильнее; со времён GPT-2 это стандарт.

## 5.3 Блок на PyTorch

```python requires=torch
import torch
from torch import nn
import torch.nn.functional as F

class CausalSelfAttention(nn.Module):           # многоголовое причинное самовнимание из прошлого урока (быстрое ядро PyTorch)
    def __init__(self, d, n_heads):
        super().__init__()
        self.h = n_heads
        self.qkv = nn.Linear(d, 3 * d)
        self.proj = nn.Linear(d, d)
    def forward(self, x):
        B, T, C = x.shape
        q, k, v = self.qkv(x).split(C, dim=2)
        q, k, v = (t.view(B, T, self.h, C // self.h).transpose(1, 2) for t in (q, k, v))
        y = F.scaled_dot_product_attention(q, k, v, is_causal=True)
        return self.proj(y.transpose(1, 2).reshape(B, T, C))

class MLP(nn.Module):                           # d → 4d → d
    def __init__(self, d):
        super().__init__()
        self.fc = nn.Linear(d, 4 * d)
        self.proj = nn.Linear(4 * d, d)
    def forward(self, x):
        return self.proj(F.gelu(self.fc(x)))

class Block(nn.Module):
    def __init__(self, d, n_heads):
        super().__init__()
        self.ln1 = nn.LayerNorm(d)
        self.attn = CausalSelfAttention(d, n_heads)
        self.ln2 = nn.LayerNorm(d)
        self.mlp = MLP(d)
    def forward(self, x):
        x = x + self.attn(self.ln1(x))          # ① токены обмениваются информацией
        x = x + self.mlp(self.ln2(x))           # ② каждый токен «думает» сам
        return x

torch.manual_seed(0)
block = Block(d=64, n_heads=4)
x = torch.randn(2, 10, 64)                      # 2 последовательности по 10 токенов, по 64 измерения
print("вход", tuple(x.shape), "→ выход", tuple(block(x).shape))   # форма та же — блоки можно складывать стопкой
print("параметров в одном блоке:", sum(p.numel() for p in block.parameters()), "= 12d² + 13d =", 12 * 64**2 + 13 * 64)
```

Форма выхода в точности совпадает с формой входа, поэтому блоков можно поставить сколько угодно.

## 5.4 Откуда берутся 124 миллиона параметров GPT-2?

Параметры одного блока (d — размерность модели):

| Часть | Параметры |
|-------|-----------|
| внимание: проекция QKV `d × 3d` + смещение `3d` | 3d² + 3d |
| внимание: выходная проекция `d × d` + смещение `d` | d² + d |
| MLP: `d × 4d` + `4d`, `4d × d` + `d` | 8d² + 5d |
| две LayerNorm (у каждой γ и β) | 4d |
| **итого** | **12d² + 13d** |

Добавьте эмбеддинг токенов (`V × d`), позиционный эмбеддинг (`длина контекста × d`) и финальную LayerNorm (`2d`); выходной слой **делит** матрицу с эмбеддингом токенов (связывание весов) и параметров не добавляет:

```python
def gpt2_params(n_layer, d, vocab=50257, ctx=1024):
    emb = vocab * d + ctx * d                       # эмбеддинг токенов + позиционный эмбеддинг
    attn = (d * 3 * d + 3 * d) + (d * d + d)        # проекция QKV + выходная проекция (со смещениями)
    mlp = (d * 4 * d + 4 * d) + (4 * d * d + d)     # d → 4d → d (со смещениями)
    norms = 2 * (2 * d)                             # две LayerNorm, у каждой γ и β
    per_layer = attn + mlp + norms
    final = 2 * d                                   # финальная LayerNorm; выходной слой делит эмбеддинг токенов
    return per_layer, emb + n_layer * per_layer + final

for name, n_layer, d in [("GPT-2 small", 12, 768), ("GPT-2 medium", 24, 1024),
                         ("GPT-2 large", 36, 1280), ("GPT-2 XL", 48, 1600)]:
    per_layer, total = gpt2_params(n_layer, d)
    print(f"{name:13s} {n_layer:2d} слоёв  d={d:4d}  на слой {per_layer / 1e6:5.1f}M  всего {total / 1e6:7.1f}M")
```

Получаются ровно те 124M, 355M, 774M и 1,5B, которые опубликовала OpenAI. Видно, что **параметры в основном дают `12d²`**: удвойте размерность — и в каждом слое станет примерно вчетверо больше параметров.

## 5.5 Три вида трансформеров

Исходный трансформер (2017) создавался для машинного перевода и состоял из **кодировщика** и **декодировщика**. Потом он разделился на три семейства:

| Семейство | Примеры | Внимание | Цель обучения | В чём силён |
|-----------|---------|----------|---------------|-------------|
| **только кодировщик** | BERT (2018) | **двунаправленное**: каждый токен видит всё предложение | заполнение пропусков: прячем слова, модель угадывает | понимание: классификация, поиск, эмбеддинги предложений |
| **кодировщик-декодировщик** | исходный трансформер, T5 | двунаправленный кодировщик и причинный декодировщик, читающий кодировщик через «перекрёстное внимание» | превратить входную последовательность в выходную | перевод, реферирование |
| **только декодировщик** | GPT, Llama, Qwen, DeepSeek, Claude… | **причинное**: видит только предыдущий текст | предсказать следующий токен | генерация; в большом масштабе — почти всё |

Почти все современные LLM — **только декодировщик**: это самая простая и легко масштабируемая конструкция, а цель «предсказать следующий токен» можно обучать на **любом тексте** из интернета без ручной разметки.

## 5.6 Современные улучшения: трансформер в стиле Llama

После GPT-2 общая структура почти не изменилась, но многие детали улучшились. Набор решений Llama (Meta, 2023) стал фактическим стандартом и широко используется в Qwen, Mistral, DeepSeek и других:

| Компонент | GPT-2 (2019) | Стиль Llama (2023 — сегодня) | Почему |
|-----------|--------------|-------------------------------|--------|
| нормализация | LayerNorm | **RMSNorm** | дешевле, работает не хуже |
| информация о позиции | обучаемые позиционные эмбеддинги, прибавляемые ко входу | **RoPE** (поворот q и k внутри внимания) | относительные позиции; проще расширять контекст |
| MLP | GELU, `d → 4d → d` | **SwiGLU** — MLP с «вентилем» | лучше при том же числе параметров |
| головы K, V | столько же, сколько голов запросов | **GQA**: несколько голов запросов делят один набор K, V | KV-кэш в разы меньше, инференс быстрее |
| смещения | во всех линейных слоях | обычно **без смещений** | почти не влияет, проще |
| выходной слой | общий с эмбеддингом | в больших моделях обычно **отдельный** | чуть лучше, когда параметров много |

**SwiGLU** — это MLP с «вентилем»: одна ветвь вычисляет «вентиль» (через SiLU), который умножается на результат другой ветви, затем всё проецируется обратно в d измерений. Матриц три, поэтому скрытую размерность обычно берут около `8d/3`, чтобы параметров было столько же, сколько у обычного MLP:

```python requires=torch
import torch
from torch import nn
import torch.nn.functional as F

class SwiGLU(nn.Module):                        # MLP из Llama, Qwen, DeepSeek и других
    def __init__(self, d, hidden):
        super().__init__()
        self.gate = nn.Linear(d, hidden, bias=False)
        self.up = nn.Linear(d, hidden, bias=False)
        self.down = nn.Linear(hidden, d, bias=False)
    def forward(self, x):
        return self.down(F.silu(self.gate(x)) * self.up(x))   # «вентиль» поэлементно умножается на «содержимое»

mlp = SwiGLU(d=64, hidden=172)                  # 172 ≈ 8 × 64 / 3
print(tuple(mlp(torch.randn(2, 10, 64)).shape), "параметров:", sum(p.numel() for p in mlp.parameters()))
```

Тем же способом можно посчитать параметры Llama 3. Llama 3 8B: 32 слоя, d = 4096, 32 головы запросов, 8 голов KV, скрытая размерность SwiGLU 14336, словарь 128256:

```python
def llama_params(n_layer, d, n_heads, n_kv_heads, ffn_hidden, vocab):
    head_dim = d // n_heads
    attn = d * d + 2 * d * (n_kv_heads * head_dim) + d * d      # W_Q, W_K и W_V (меньше благодаря GQA), W_O
    mlp = 3 * d * ffn_hidden                                    # три матрицы SwiGLU
    norms = 2 * d                                               # две RMSNorm (только γ)
    per_layer = attn + mlp + norms
    return n_layer * per_layer + 2 * vocab * d + d              # отдельные входной эмбеддинг и выходной слой; финальная RMSNorm

print(f"Llama 3 8B:  {llama_params(32, 4096, 32, 8, 14336, 128256) / 1e9:.2f}B")
print(f"Llama 3 70B: {llama_params(80, 8192, 64, 8, 28672, 128256) / 1e9:.2f}B")
```

Совпадает с опубликованными Meta 8,03B и 70,6B. В моделях в стиле Llama **большая часть параметров — в MLP** (в модели 8B около 176 млн параметров MLP на слой против примерно 42 млн у внимания).

## 5.7 Смесь экспертов (MoE): параметров много, используется лишь часть

Чем больше модель, тем она умнее, но и тем дороже вычисления на каждый токен. **Смесь экспертов** (Mixture of Experts, MoE) заменяет один большой MLP на **много маленьких MLP (экспертов)** и добавляет **маршрутизатор** (router). Каждый токен отправляется лишь к нескольким экспертам с наибольшими оценками:

```python
import math

def softmax(z):
    m = max(z)
    e = [math.exp(v - m) for v in z]
    return [v / sum(e) for v in e]

# 4 «эксперта» (в настоящей модели каждый — это MLP; здесь их заменяют простые функции)
experts = [lambda x: [2 * v for v in x],         # эксперт 0
           lambda x: [v + 1 for v in x],         # эксперт 1
           lambda x: [-v for v in x],            # эксперт 2
           lambda x: [v * v for v in x]]         # эксперт 3
router = [[0.5, -1.0], [1.0, 0.2], [-0.3, 0.8], [0.1, 0.1]]     # маршрутизатор: строка весов на эксперта

def moe(x, top_k=2):
    scores = [sum(w * v for w, v in zip(row, x)) for row in router]
    chosen = sorted(range(len(experts)), key=lambda i: -scores[i])[:top_k]   # выбираем только k лучших
    gates = softmax([scores[i] for i in chosen])                            # веса выбранных экспертов
    outs = [experts[i](x) for i in chosen]                                  # считают только выбранные эксперты
    y = [sum(g * o[j] for g, o in zip(gates, outs)) for j in range(len(x))]
    return chosen, [round(g, 3) for g in gates], [round(v, 3) for v in y]

for x in ([1.0, 0.0], [0.0, 1.0], [-1.0, 1.0]):
    print("вход", x, "→ выбранные эксперты, веса, выход:", moe(x))
```

Разные входы попадают к разным экспертам. Тогда **общее число параметров** модели может быть огромным (больше знаний), а параметров, **реально участвующих в вычислении для каждого токена** (активных параметров), — лишь малая доля:

| Модель | Всего параметров | Активных на токен |
|--------|------------------|-------------------|
| Mixtral 8x7B | около 47 млрд | около 13 млрд (2 эксперта из 8) |
| DeepSeek-V3 / R1 | 671 млрд | около 37 млрд |
| Qwen3-235B-A22B | 235 млрд | около 22 млрд |

MoE стала основным выбором для передовых моделей. Трудности: эксперты должны делить работу равномерно (чтобы все токены не скапливались у одного эксперта), а параметры всех экспертов всё равно должны помещаться в память.

## 5.8 Итоги

- Трансформер в стиле GPT: эмбеддинги токенов (+ позиции) → N блоков → финальная нормализация → выходной слой → логиты следующего токена на каждой позиции.
- Блок = `x + Attention(Norm(x))`, затем `x + MLP(Norm(x))`: внимание позволяет токенам **общаться**, MLP — каждому токену **считать** самостоятельно; остаточный поток проходит через все слои, Pre-Norm делает обучение стабильным.
- Около **12d²** параметров на слой; GPT-2 small = 12 слоёв × d=768 ≈ 124 млн параметров.
- Три семейства: только кодировщик (BERT, двунаправленный, понимание), кодировщик-декодировщик (T5, перевод), **только декодировщик** (GPT, Llama, Qwen…, современные LLM).
- Современные улучшения: RMSNorm, RoPE, SwiGLU, GQA, отказ от смещений; **MoE** направляет каждый токен к немногим экспертам, так что параметров много, а вычислений мало.

В трансформере каждый подслой записан как `x = x + f(x)`, а не `x = f(x)`. Главная польза:

- меньше параметров
- градиенты проходят прямо к ранним слоям по «пути сложения», поэтому обучаются очень глубокие сети; каждому слою нужно выучить только «изменение»

<summary>Ответ и разбор</summary>

Все они — только декодировщик: причинное внимание + предсказание следующего токена. Эта конструкция самая простая, легче всего масштабируется и обучается на любом тексте.
</details>

<!-- exercise: moe-why -->
### Задание 5: Зачем MoE?

У DeepSeek-V3 всего 671 млрд параметров, но каждый токен активирует лишь около 37 млрд. Главная польза MoE:

- файл модели меньше
- общее число параметров (ёмкость знаний) огромно, а вычислений на каждый токен — как у гораздо меньшей модели
- маршрутизатор не нужно обучать
- не нужен GPU

<details>
<summary>Ответ и разбор</summary>

Каждый токен проходит лишь через нескольких экспертов, поэтому объём вычислений определяется активными параметрами, а знания хранятся во всех экспертах. Цена: параметры всех экспертов всё равно должны находиться в памяти.
</details>
